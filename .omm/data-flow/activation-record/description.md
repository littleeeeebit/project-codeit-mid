Triggered by the CLI `activate-run` or by the 실험 비교 activate action (`activate_experiment`). The function `activate_run` validates the run (current `EVAL_VERSION`, index and matrix verification, pinned revisions and prefixes), then in one transaction writes `app_settings.active_run` (mode, limits, embedding, reranker, eval_version) and `active_index`, and appends the previous configuration to `activations`. Nothing activates on its own, and maintenance never activates anything.
