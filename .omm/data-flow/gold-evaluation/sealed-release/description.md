`freeze-release` (`sealed.freeze_release`, `sealed_evaluator` only) refuses unless the selected run is the activated, servable one, dev and test are validated, frozen and unchanged, a development answer run compared that run, and the owner states who decided and why. It writes `releases/<freeze_id>/freeze.json` and an audit event. The sealed set then runs once (`sealed.begin`); any later run is a labeled post-test regression. `release-report` decides `ready` only when every hard check passes and every quality target is met on sealed gold; otherwise `limited` or `blocked`. `backup` (pg_dump custom format plus the mutable trees) and `restore-check` (restore into an empty isolated database with paid admission off and the fake provider, then compare tables, ledger and artifacts) are the rollback path.
