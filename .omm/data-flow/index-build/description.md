`cli build-keyword` → `retrieval.build_keyword_index(settings, Analyzer(), include_unreviewed, profile, activate)`. It selects parsed sources by review policy and freezes each document's title and institution tokens (`metadata_term_snapshot`). The version is the hash of the config: chunker fingerprint, profile, analyzer fingerprint, IDF policy, review scope, extraction IDs and metadata-terms hash. An existing ready version is reused. Otherwise `chunking.build_profile` builds structural chunks (`structural-5`: target 700, hard limit 800 tokens with o200k_base, table rows with carried title lines, linked split pieces, requirement-code inventory) or a fixed baseline. Kiwi tokens are computed, files are written to a temporary directory and renamed into `.runtime/indexes/<version>/`, and `indexes`, `chunks` and `requirements` rows are inserted in one transaction. `KeywordIndex.load` re-verifies the manifest and every file hash on load.
