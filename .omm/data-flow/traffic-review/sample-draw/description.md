`group_of` keys each request by (mode, outcome, validation or processing_failure/passed/not_validated, document titles or 전체 문서). `draw` orders groups so validation failures come first, then non-answers, then larger groups. It takes one random representative per group while picks remain, then gives extra picks D'Hondt-style to groups with the most unpicked requests per pick. The seed comes from the run ID. Each pick records a Korean reason (`reason`). The app's map shows every request and lets the person add more by hand as `sample` annotation records.
