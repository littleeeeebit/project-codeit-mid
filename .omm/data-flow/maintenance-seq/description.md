`maintenance.run`, triggered by CLI `maintain --actor` or by the 검증 → 유지보수 → 유지보수 실행 (Verify → Maintenance → Run maintenance) button through POST /api/verify/maintenance/start, runs, in order: `backup` (postgres_backup.backup, pg_dump custom format), `restore_check` (pg_restore into a scratch `rfp_mrestore_*` database, which is then dropped), `ingest` (manifest plus changed originals only), `fidelity` (HWP extractions without a verdict), `keyword` (rebuild the served profile without activating), `embedding` (new chunks with the activated model; paid models stop at their estimate), `regression` (`compare.regression`: K1 and the serving configuration on the served and the rebuilt index) and `report`. Each step reuses what is unchanged. Reports are written to `.runtime/maintenance/reports/<run>.json|.md`. The web run uses the serving process's gateway and transport; the CLI run builds its own Resources and therefore refuses while the UI runs.
