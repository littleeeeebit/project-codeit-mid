`requests` rows hold the input snapshot (`request_json`), the configuration snapshot hash, `trace_json` (config, retrieval with every candidate and packed unit, rewrite record, token estimate, billing attempts, raw output on validation failure) and `result_json` (the `AnswerResult` with its evidence map). The evidence pane (`open_evidence`), history (`list_requests`), export (`export_request` with `redact`) and the conversation context of the next turn (`_conversation`) all read these rows. `verifier_runs` holds frozen traces the same way.
