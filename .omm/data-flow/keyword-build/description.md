build_keyword_index selects parsed sources by review policy. It freezes title and institution terms (metadata_term_snapshot), chunks each active extraction with chunking.build_profile (structural-5 by default, with fixed-window profiles for comparison), tokenizes payloads with Kiwi, writes a temp directory and renames it to indexes/<version>. The version is the hash of the config (chunker, analyzer fingerprint, IDF policy, review scope, extraction list, metadata-term hash). In one transaction it then inserts indexes, chunks and requirements rows and optionally sets active_index. A version already ready on disk is reused.
