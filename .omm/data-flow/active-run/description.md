`activate_decision` (from `cli activate-run`, or `POST /api/verify/experiments/activate` → `service.activate_experiment`) validates the run (`decision_errors`: index and matrix verify, current policy, pinned revisions and prefixes). In one transaction it writes `app_settings.active_run` (`serving_config` plus finalist and timestamp) and `active_index`, and appends `activations` with the previous configuration for rollback. Every reader goes through `service.active_serving`, and the next `Resources.index()`, `dense()` or `reranker()` call reloads to match.
