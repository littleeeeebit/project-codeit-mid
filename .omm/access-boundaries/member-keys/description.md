`PUT /api/settings/api-key` → `service.set_api_key` checks the key against the chosen model (`generation.check_api_key` returns the billing project) and calls `Resources.set_api_key`, which creates a new key session and client. The key is never written to a file, row, log or trace. `OPENAI_API_KEY` from the environment or `.env` serves only callers without a session key; on the shared host there is none.
