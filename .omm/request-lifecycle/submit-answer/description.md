`submit_answer` first runs `_validate_request`, which checks mode, question length (1..`question_max_characters` for paid modes), duplicate refs, scope cardinality per mode (corpus: none; compare: exactly two; others: one or two), id lengths, and `_frozen_run_for`. Next, `_conversation` walks `previous_request_id` back up to 6 turns. Every earlier turn must belong to the same member, be terminal, and have an identical scope; otherwise the request is refused before anything is persisted. The function collects each turn's standalone question and display text (`_answer_text`, 6000 characters for the latest turn, 1200 for older ones) and up to 8 cited `EvidenceUnit`s of the previous answer. Finally `_create` inserts the `requests` row (input hash, config hash, scope, request snapshot, status) in one immediate transaction. An existing `(member_id, idempotency_key)` with the same input hash returns the prior request id; with a different hash it raises.
