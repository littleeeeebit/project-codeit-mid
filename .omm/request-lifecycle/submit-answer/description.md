`_validate_request` checks mode and length, and `_conversation` validates the follow-up chain. Free modes run `_create(status='running')` and execute inline. Paid modes take `res.runner()`, then `_create(status='queued', before_insert=admit)`. `admit` → `RequestRunner.try_admit` runs inside the insert transaction, so a full queue or an active update fence refuses before any row or cost exists ('(유료 호출 없음)'). If `runner.submit` fails, the slot is released and `_fail_unscheduled` marks the row failed.
