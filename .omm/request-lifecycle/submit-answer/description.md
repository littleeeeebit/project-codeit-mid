service.submit_answer calls _validate_request, then _create. _create runs in one tx(immediate) on the application mutex. A prior row with the same member and key returns its request_id if the input hash matches, and raises '같은 요청 키가 다른 입력에 재사용되었습니다' if it does not. Otherwise it inserts requests(status queued, request_json snapshot including capabilities, trace_json {config}). For paid modes, before_insert=admit takes a RequestRunner slot or raises '요청이 많아…' with no row and no cost. If executor submission fails, the slot is released and _fail_unscheduled marks the row failed.
