_validate_request checks the mode, question length, duplicate refs, scope rules per mode, identifier lengths and any frozen verifier run. _conversation then walks previous_request_id up to CONVERSATION_TURNS = 6 turns. It requires every turn to be the same member's, finished and on the same scope, otherwise it refuses before queueing. _create inserts the request under (member_id, idempotency_key) with input_hash, a config snapshot and request_json. The same key with the same input returns the prior request; a different input is refused. For paid modes, admission to the runner happens inside that insert transaction, and runner.submit failure marks the request failed with no paid call.
