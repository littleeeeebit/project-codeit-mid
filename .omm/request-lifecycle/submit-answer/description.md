`submit_answer` runs `_validate_request`, then `_create(..., 'queued', before_insert=admit)`. Inside the mutex transaction it checks for a prior row with the same member and key: a matching input hash returns the existing request, a different one is refused. Otherwise it calls `runner.try_admit()` (refusing with 'too many requests, no paid call' when full) and inserts the `requests` row with `request_json`, `input_hash`, `config_hash` and a trace config snapshot. If `runner.submit` fails, the slot is released and `_fail_unscheduled` marks the request `failed`.
