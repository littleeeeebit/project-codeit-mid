`service.ask` creates the generation ID and computes `target_key`. `submit_answer` runs `_validate_request`: mode, 1–`question_max_characters` characters for paid modes, scope arity per mode (compare exactly 2, corpus 0, others 1–2), no duplicate document, and frozen-run validity. It then runs `_conversation` (refusing a foreign, unfinished or rescoped previous turn) and `_create`, which inserts the row as `queued` inside the transaction only after `runner.try_admit()` succeeds (`before_insert`). The same `(member_id, idempotency_key)` returns the existing request, or raises if the input hash differs. A full queue raises with "(유료 호출 없음)" before any row exists. A failed `runner.submit` releases the slot and marks the row failed.
