`service.ask` mints a fresh `generation_id`, which is also the idempotency key, and builds the `AnswerRequest` with `as_of` set to today. `submit_answer` runs `_validate_request` (mode, 1–2 documents or corpus, compare requires exactly two, question length, frozen-run check) and `_conversation`. `_conversation` refuses a follow-up whose earlier turns belong to another member, are unfinished or used another scope, and collects up to 6 turns plus up to 8 carried evidence units. `_create` inserts a `requests` row with `input_hash`, `config_hash`, `scope_json`, `request_json` and status `queued`, after `runner.try_admit()`. A duplicate key with the same input returns the earlier request; with different input it is refused. It returns `target_key(scope, question, mode, as_of, previous)` for attachment checks. A failure to schedule frees the slot and marks the row `failed` through `_fail_unscheduled`. No paid call has happened by that point.
