`_validate_request` checks the mode, question length, scope rules (compare needs exactly two documents, corpus none), the idempotency key and any frozen verifier run. `_conversation` validates the follow-up chain. `_create` runs in one transaction under the write mutex: an existing key with the same `input_hash` returns the prior request without a new slot, and a different hash is refused. For a new key, `RequestRunner.try_admit` must succeed; a full queue or the update fence refuses with 'no paid call'. Then it inserts `requests(status='queued', request_json=snapshot)`. `runner.submit` queues only the ID; if that fails, the row becomes failed and the slot is freed.
