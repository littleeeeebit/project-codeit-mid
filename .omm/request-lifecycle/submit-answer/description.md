`_create` computes `input_hash` (normalized question, scope, mode, as_of, config, run, previous) and inserts the row inside an immediate transaction. The same member and key with the same hash returns the prior request, and a different hash is refused. `before_insert=admit` runs `runner.try_admit()` only for a new key, and that check includes the update fence. If `runner.submit` fails, the slot is released and the row is marked failed with no paid call (`_fail_unscheduled`).
