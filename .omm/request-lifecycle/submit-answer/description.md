`service.ask` generates the generation id, which doubles as the idempotency key, and calls `submit_answer`. Free modes are inserted as `running` and executed on the HTTP thread. Paid modes are inserted as `queued` only after `RequestRunner.try_admit` takes a slot. That happens inside `_create`'s locked transaction (`before_insert`), so a full queue or an active update fence rejects the request before any row or paid work exists. The response carries `target_key(scope, question, mode, as_of, previous)`, which the screen later uses to decide whether to attach.
