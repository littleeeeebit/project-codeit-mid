Two read-only channels. `GET /api/requests/{id}?generation_id&target` returns `RequestView` and `attachable`, and the turn polls it every 1 s until a terminal status. `GET /api/requests/{id}/stream` is a server-sent event stream: a sync generator calls `answer_progress` every 0.15 s and emits `data:` whenever the provisional `partial_answer` changes, `data: null` when attachment is revoked, and `event: done` once the request has finished. `useAnswerStream` parses the events and, on `done`, triggers `status.reload()` so the validated outcome replaces the provisional text. If the stream drops, the poll still delivers the outcome.
