The api.py route `ask` passes `date.today()` as `as_of`. `service.ask` mints a `generation_id`, which doubles as the idempotency key, and calls `submit_answer`. That function runs `_validate_request` (mode, 1–2 documents or none for corpus, question length, frozen verifier run) and `_conversation`, which refuses invalid chains. Free modes run inline. For paid modes, `_create` inserts the `requests` row with `status='queued'`, the input hash, the configuration-snapshot hash and the request JSON (including capabilities). It does this in one `tx(immediate=True)` after `runner.try_admit()`. A duplicate key with the same input returns the existing request, and the same key with a different input is refused. `runner.submit` failing marks the request failed and frees the slot, with nothing reserved.
