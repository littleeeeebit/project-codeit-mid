Each `requests` row carries request_id, member_id, idempotency_key, generation_id, input_hash, config_hash, scope_json, status, cancel_requested, request_json (snapshot including capabilities and previous_request_id), trace_json (the config snapshot, later the full trace with retrieval, rewrite, admission, usage and billing), result_json (an `AnswerResult` with the evidence map) and mode. `_view` combines a row with its `attempts` into `RequestView`, including the billing rollup (`unknown > pending > reconciled > settled > released`), the open reserved micro-USD and the settled micro-USD.
