`POST /api/requests/{id}/cancel` → `cancel_request` (owner only, one immediate transaction). A `queued` request becomes `cancelled` with a 'no paid call' result. A `running` request gets `cancel_requested=1`, so no further paid stage starts and the result is not attached; an already dispatched call still settles. `POST .../abandon` → `abandon_request` cancels only while the request is still `queued`. The screen uses abandon on context change, so it never cancels running work.
