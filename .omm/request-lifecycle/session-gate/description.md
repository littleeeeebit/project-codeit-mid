`_Session` resolves the member from the cookie, checks the account header, and calls `service.bind_request`, which sets `generation.KEY_SESSION`, `generation.REQUEST_MODEL` and `budget.BILLING_SCOPE` from the member's current key session. The reset runs when the HTTP request ends. The executor and job threads start from `contextvars.copy_context()`, so the member's key, model and billing project travel with the work, and a later change on 설정 never alters an already submitted request.
