`_Session` checks origin, session cookie and account header, then refuses with 403, 503, 401, 409 or 428 as described in overall-architecture/http-api/session-middleware. Before the route runs, `service.bind_request` fixes this member's key session, answer model and billing scope as contextvars. Changing the key or model on 설정 later never alters a request that has already been submitted.
