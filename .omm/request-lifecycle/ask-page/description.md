The trigger is the submit button. The body is `{scope: [{doc_id, source_hash}] | [], question, mode}`, with the header `X-Member`. The response is `Owned {request_id, generation_id, target}`, where `target = service.target_key(scope, question, mode, as_of)`. The page polls `GET /api/requests/{id}?generation_id&target` every second until the status leaves queued/running. `service.may_attach` decides whether the finished answer is still the screen's current answer: same request, generation and target, and not cancelled. Changing the context abandons the owned request, which cancels it only while it is still queued.
