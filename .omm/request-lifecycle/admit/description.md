`api.ask` → `service.ask` creates a fresh `generation_id` and uses it as the idempotency key. `submit_answer` runs `_validate_request`: the mode set; 1–2 documents, exactly 2 for compare, none for corpus; question length; and `_frozen_run_for` for verifier runs. It then runs `_conversation`: previous turns must belong to the same member, be terminal and use the same scope; up to 6 turns are kept, and up to 8 cited evidence units carry over. Free modes call `_create(..., 'running')` and `_execute` inline. Paid modes take a runner slot inside the insert transaction (`before_insert=admit`), so only a new key consumes one, and insert a `queued` row with input_hash, config_hash and the `request_json` snapshot, including capabilities. The same key with the same input returns the earlier request; the same key with a different input is refused. A full queue is refused before any paid work. A failed submit releases the slot and marks the row `failed` (`_fail_unscheduled`).
