`_prepare_paid` chooses `_frozen_prep` (verifier run), `_prepare_compare` (two documents, each retrieved with single-document limits), or `prepare_answer` (single or corpus). `prepare_answer` calls `service.retrieve` with `allow_paid=True`, so an uncached OpenAI query embedding may be the first paid stage, then `_with_carried`, then `_priced`. `_priced` builds `generation.build_messages`, counts tokens exactly (`count_request_tokens`), and estimates the maximum with `budget.estimate`, adding the query-embedding estimate on a cache miss. Empty evidence ends as `insufficient_evidence` with no generation call. A `_checkpoint` before each paid stage raises `_Stop` when the request is cancelled or interrupted.
