On the server, the `stream` route first calls `answer_progress` once, so it refuses before the stream opens. It then yields `data: <json>` whenever `generation.partial_answer(res.partials[id])` changes, `data: null` when a cancel or a different generation id revokes the text, and `event: done` once the status leaves queued or running. On the client, `useAnswerStream` reads the body through fetch and `TextDecoderStream` so it can abort, shows the content as provisional text, and calls the poll's `reload` on `done`. Stream errors are swallowed because the status poll still delivers the outcome. `res.partials` is in-process memory only and is cleared by `_finish`.
