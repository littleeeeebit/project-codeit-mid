This is the path of one 질문하기 turn from `POST /api/ask` to a stored, attachable outcome, as implemented in `service.ask` → `submit_answer` → `RequestRunner` → `run_queued` → `_execute` → `_paid_answer` → `_finish`. Free modes (`metadata`, `inventory`) skip the runner and the gateway: `_metadata_answer` returns typed CSV facts with unknown, zero, conflict or resolved states, and `_inventory_answer` returns the structured requirement list from the active index. The screen polls `GET /api/requests/{id}` and reads the SSE stream while the request runs.
