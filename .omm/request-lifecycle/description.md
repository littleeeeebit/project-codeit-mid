This is one question on the ask screen. The trigger is the form submit in ask-page.tsx. It sends an AskIn body (scope of at most two {doc_id, source_hash}; question; mode single, compare, corpus, metadata or inventory; previous_request_id) and gets back an Owned record {request_id, generation_id, target}. service.ask creates a fresh generation_id (a UUID) that also serves as the idempotency key. target_key hashes scope, question, mode, as_of and previous. The free modes (metadata, inventory) run inline. A paid mode is inserted as queued and handed to the executor. Completion: _finish writes status, trace_json and result_json, and removes the streamed partial. The screen shows the outcome as its answer only when service.may_attach holds (same target, request and generation, not cancelled). Otherwise it stays in the history list while its billing still settles. Cancellation: POST /api/requests/{id}/cancel. Leaving the screen calls /abandon, which cancels only a request still queued.
