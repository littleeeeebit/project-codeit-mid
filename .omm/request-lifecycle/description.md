One paid 질문하기 question from click to validated answer. Trigger: the composer's submit → `POST /api/ask` with scope, question, mode and `previous_request_id`. What crosses each boundary: the HTTP body becomes an `AnswerRequest` with `idempotency_key = generation_id = uuid4`, `as_of = today`. The request row stores `request_json` (snapshot with capabilities), `scope_json`, `input_hash` and a config snapshot. The worker receives only `request_id`. The provider receives the built messages and the strict JSON schema. The screen receives `Owned {request_id, generation_id, target}`, then SSE partials and polled `RequestView`s. Completion: `_finish` writes the final status, `result_json` and `trace_json` (billing from the ledger) and drops `res.partials[request_id]`. Cancellation: queued → cancelled at once with no call. Running → `cancel_requested`; the next `_checkpoint` or the dispatch guard stops new paid stages, while an already-dispatched call still settles. Failure: every exception path ends in `done(...)`, so no row stays `running` except across a crash. Restart recovery then marks it interrupted.
