This traces one paid 질문하기 question from click to rendered answer. Trigger: `AskPage.submit` POSTs `/api/ask` with `{scope:[{doc_id, source_hash}], question, mode, previous_request_id}`. `service.ask` makes a fresh `generation_id` (also the idempotency key) and calls `submit_answer`. That validates the request (`_validate_request`), checks the conversation chain (`_conversation`: same member, terminal, same scope), and persists a `requests` row in `queued` under the idempotency key inside `_create`, consuming a runner slot in the same step. It returns `{request_id, generation_id, target}`, with `target = target_key(scope, question, mode, as_of, previous)`. A worker runs the request while the screen polls status and follows the SSE partial. Free modes (`metadata`, `inventory`) run inline in `submit_answer` and never touch the ledger.
