Trigger: a member presses 답변 받기 (or the compare or corpus variant) on 질문하기. The screen POSTs the scope, question, mode and previous turn. The server persists an input snapshot under a fresh idempotency key, admits the request to the bounded executor, and returns an ownership record. A worker claims the row, runs the free or paid path, and stores the validated outcome. While it runs, the screen polls the request and, for paid modes, reads a server-sent event stream of the unvalidated partial answer. Completion is the stored `result_json`, never the stream. Cancellation sets a flag that stops the next paid stage. A restart marks unfinished work `interrupted` and replays nothing.
