The path of one question from the ask screen to a validated, billed answer. The screen sends `POST /api/ask`. The request is persisted under an idempotency key and runs on the bounded executor. A follow-up is first rewritten into a standalone query (paid). Retrieval and prompt assembly are priced, the answer call streams into memory, and the payload is validated against the evidence. `_finish` stores outcome, trace and billing state together. The screen learns the outcome only by polling, and renders it only while it still asks the same thing.
