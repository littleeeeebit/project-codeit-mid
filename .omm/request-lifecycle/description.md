The path of one 질문하기 (Ask) question from the browser to a stored, validated answer. The screen submits under a fresh generation ID. The service persists the request under that idempotency key before any work, then runs it on the bounded executor. Paid stages each reserve, mark dispatching, call and settle. The screen watches a read-only server-sent event stream of the provisional text, and a 1 s status poll that is the only source of the validated outcome. The outcome is shown as the current answer only while the screen still asks exactly what it asked (`may_attach`); otherwise it stays in 내 최근 요청 (my recent requests) and its billing still settles.
