A paid ask from the screen. (1) `ask-page.tsx` POSTs `/api/ask`. (2) `_Session` resolves the member and binds the key session and model. (3) `service.ask` -> `submit_answer` validates the request, checks the conversation, takes an admission slot and inserts a `queued` row under the idempotency key, then (4) hands the ID to `RequestRunner`. (5) A worker claims the row as `running` in `run_queued` and runs `_paid_answer`. That pipeline does an optional rewrite, retrieval with pricing, generation streamed into `res.partials`, and validation. (6) Each paid stage reserves, dispatches and settles in the ledger. (7) `_finish` stores the result, trace and billing state. (8) Meanwhile the screen polls `GET /api/requests/{id}` and reads the SSE stream. It renders the validated answer only when `may_attach` holds, meaning the same target and generation and no cancellation. Free modes complete inline inside the POST.
