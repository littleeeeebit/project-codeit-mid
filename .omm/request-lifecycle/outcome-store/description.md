`_finish` writes `status`, `trace_json` (config, retrieval, carried evidence IDs, rewrite and generation admissions, usage, settlements, billing attempts) and `result_json`, then pops the partial. The screen renders it only if `service.may_attach(owned, target, view)` holds: the same request, generation and target, and not cancelled. Otherwise it appears only in '내 최근 요청' (`GET /api/requests`), and its billing still settles. A follow-up then cites this request as `previous_request_id`, and `_conversation` re-reads `result_json` from here.
