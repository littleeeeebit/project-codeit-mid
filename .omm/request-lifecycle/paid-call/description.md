After a second `_checkpoint`, `budget.reserve(stage='generation', purpose=res.paid_purpose)` runs; the purpose is `interactive` for the UI and `gold_eval` for `PinnedResources`. Refusals map to `budget_blocked` (evidence still returned) or, for `above_consented_maximum`, `clarification_required`. With no transport the reservation is released and the request ends `technical_error`. `mark_dispatching(attempt, _dispatch_guard)` atomically re-checks the stop. Then `transport.chat(...)` runs inside a `generate-answer` tracing step. `ProviderError(pre_execution)` → `release`; other errors → `mark_unknown`; missing usage → `mark_unknown`; otherwise `settle`. If settlement fails, the attempt becomes `unknown` and the request a technical error. Each outcome is recorded before the result is written.
