`_metered_chat` (service.py:1259) is the one gateway wrapper for chat stages. It runs `budget.reserve` (purpose `interactive` for the app, with an optional consented ceiling). A refusal returns `budget_blocked` or `clarification_required` with no call. If no transport or key is available, the reservation is released and the result is `technical_error`. Next, `budget.mark_dispatching` runs with `_dispatch_guard`, which repeats the cancel and shutdown check inside the same transaction; a refusal for cancellation or interruption raises `_Stop`. Then `transport.chat(..., on_delta)` runs. A pre-execution ProviderError releases the reservation; any other error marks it unknown. A response without usage is marked unknown; otherwise it is settled. A failed settlement is marked unknown so the recovery view shows it. Every outcome is written to the request trace (`admission`, `usage`, `settlement`) and to the Langfuse generation step with cost.
