`run_queued` claims the row with `UPDATE ... SET status='running' WHERE status='queued' AND cancel_requested=0`; if no row is claimed, the worker does nothing (cancelled or interrupted in the meantime). It rebuilds `AnswerRequest` and `Principal` from the persisted snapshot only, never from UI state, then calls `_execute`. The context copied at submit carries the browser's key session, model and billing scope into the worker thread.
