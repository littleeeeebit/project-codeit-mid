`_finish` reads the request's attempts from the ledger and sets the overall `billing_state` by the precedence unknown > pending > reconciled > settled > released. It writes `status`, `trace_json` and `result_json` in one transaction. If the row is no longer `running` (interrupted by shutdown, or cancelled while queued), it keeps that status. If a cancel was requested and the outcome is `completed`, it stores `cancelled`. It then drops the partial buffer.
