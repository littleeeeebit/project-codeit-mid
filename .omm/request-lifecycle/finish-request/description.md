`_finish` runs in one transaction. It derives `billing_state` from all of the request's attempts (`BILLING_PRECEDENCE`: unknown, then pending, reconciled, settled, released, with reserved and dispatching counted as pending), stores `trace_json` and `result_json`, and sets the final status. A row already marked `interrupted` or `cancelled` keeps that status, and a running row with `cancel_requested` that completed becomes `cancelled`. It then removes the request's entry from `res.partials`. `_trace_outcome` writes the trace output and scores. The stored outcome is kept as history even when it will not attach.
