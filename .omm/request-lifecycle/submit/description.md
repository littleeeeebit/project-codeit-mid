submit_answer runs _validate_request (mode, question length, scope count, a frozen verifier run if one is named) and _conversation. The previous turns must belong to this member, be finished and share the same scope, or it raises ServiceError. Inside _create's mutex transaction, an existing (member_id, idempotency_key) row is returned as is, and a different input hash under the same key is refused. For a new key, admit() takes a slot from runner.try_admit, and a full queue is refused before any paid work. If runner.submit then fails, _fail_unscheduled marks the row failed and frees the slot.
