`TurnView` polls `GET /api/requests/{id}?generation_id&target` every second until the status leaves queued or running. `service.may_attach` returns `attachable` only when the request, generation and target all match and the request is not cancelled. While it is live and attachable, `useAnswerStream` reads `/stream`. That server-side generator polls `answer_progress` every 0.15 s and emits `data:` with `generation.partial_answer(content)`, `data: null` when cancellation or a lost generation revokes it, and `event: done` at the end. On done the screen reloads the status and renders the validated result. Leaving the turn calls `/abandon`, which cancels only while the request is still queued.
