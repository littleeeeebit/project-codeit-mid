`cancel_request` turns a queued request into `cancelled` with a result saying no paid call was made. A running request only gets `cancel_requested=1`, and the next `_checkpoint` or `mark_dispatching` guard raises `_Stop('cancelled')`. A call already dispatched still settles. `abandon_request` (sent when a screen leaves a conversation) cancels only queued requests. A controlled stop (systemd `KillSignal=SIGINT`, `TimeoutStopSec=120`) runs `Resources.close` → `RequestRunner.shutdown`: queued requests become interrupted, and running ones too if they do not finish in time. A worker's next stage then sees `res._closed` and stops as interrupted.
