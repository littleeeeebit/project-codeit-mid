`submit_answer` first runs `_validate_request`: mode and length rules; corpus mode takes no documents and compare takes exactly two; it rejects duplicate references and a bad, mismatched or outdated frozen run. `_conversation` refuses a follow-up whose previous turn belongs to another member, has not finished, or used a different scope, before anything is queued. Free modes are created as `running` and executed inline. Paid modes go to `res.runner()`. `_create` inserts the `queued` row in one immediate transaction, calling `admit()` (`RequestRunner.try_admit`: update fence, then a free slot) only for a new key. A full queue raises `ServiceError` with "(유료 호출 없음)" (no paid call). If the executor's `submit` fails, the slot is released and the row marked `failed` (`_fail_unscheduled`). A reused key with different input is refused.
