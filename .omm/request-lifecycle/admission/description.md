`submit_answer` → `_validate_request` (mode, 1–N characters, scope cardinality per mode, no duplicate docs, frozen verifier run) → `_conversation`. The conversation check walks `previous_request_id` up to 6 turns and requires each turn to belong to the same member, be terminal and share the same scope; otherwise it refuses before anything is queued. `_create` then inserts the `requests` row under `application_mutex`: idempotency by `(member_id, idempotency_key)` with input-hash mismatch refused, plus a config snapshot (index version, serving run, prompt version, model, rate version). For paid modes the `admit()` callback takes a runner slot inside that transaction. `runner.submit` failure → `_fail_unscheduled` (status `failed`, slot released, 'no paid call').
