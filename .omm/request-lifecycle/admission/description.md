`submit_answer` → `_validate_request` checks the mode, question length (1..`question_max_characters` for paid modes), duplicate documents, exactly two documents for `compare`, one or two for `metadata`, identifier lengths, and any frozen verifier run (`_frozen_run_for`). `_create` then opens one immediate transaction. If `(member_id, idempotency_key)` already exists with the same `input_hash`, it returns the prior request; a different input raises an error. Otherwise it runs `before_insert=admit` (`RequestRunner.try_admit`, rejecting a full queue with a Korean 'no paid call' message) and inserts the `requests` row with `request_json`, `config_hash` and `status='queued'`, or `'running'` for free modes. If `runner.submit` fails, the slot is released and `_fail_unscheduled` marks the row `failed`.
