`service.ask` creates a fresh UUID used as both the idempotency key and the generation ID, then calls `submit_answer`. `_validate_request` checks the mode, question length (`question_max_characters`), duplicate documents, the scope cardinality per mode (corpus takes none, compare exactly two) and the identifier lengths, and calls `_frozen_run_for`, so a stale verifier configuration is refused before queueing. `_create` runs one short `tx(immediate=True)`. If a row with the same `(member_id, idempotency_key)` exists with the same `input_hash`, it is returned and nothing new runs; a different hash is refused. Otherwise `before_insert=admit` takes an executor slot (a full queue is refused with no paid call) and inserts `requests(status='queued', request_json=snapshot, trace_json={config})`. `runner.submit` failing releases the slot and marks the row `failed` (`_fail_unscheduled`).
