When `_conversation` returns history (up to 6 earlier turns from the same member, all terminal, same scope), `_rewrite` makes a paid call (`stage=query_rewrite`, `standalone-query-1`, at most 1,500 output tokens) that turns the follow-up into one standalone question. `validate_rewrite` enforces a non-empty query within the question limit. An unusable output fails the request as `technical_error`, billed and not retried. The rewritten question drives retrieval and the answer and is returned as `standalone_question`. The answer prompt also receives the conversation: the latest answer as displayed (`_answer_text`, up to 6,000 characters including value tables, requirement rows and listings) and older ones at 1,200. It also receives up to 8 of the previous answer's cited passage units, carried after fresh retrieval and renumbered (`_with_carried`), plus documents cited only through metadata units.
