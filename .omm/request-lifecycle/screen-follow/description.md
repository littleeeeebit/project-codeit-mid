`TurnView` polls `GET /api/requests/{id}?generation_id&target` every 1 s until the status leaves queued/running. `attachable = service.may_attach(owned, target, view)` requires the same request, generation and target and no cancellation. In paid modes, while live and attachable, `useAnswerStream` reads SSE from `/api/requests/{id}/stream`: `data:` carries `partial_answer` JSON shown as provisional text, `data: null` withdraws it after cancel or loss of ownership, and `event: done` triggers an immediate status reload. Only the polled `view.result` renders as the answer. Cancel posts `/api/requests/{id}/cancel`: `queued` → `cancelled` at once with no paid call; `running` → `cancel_requested=1`, so no further paid stage starts, an in-flight call still settles, and the result is stored as history but not attached.
