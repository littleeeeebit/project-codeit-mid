`_paid_answer` checks `_checkpoint` before each paid stage. The stages are: an optional follow-up rewrite (`stage=query_rewrite`, `REWRITE_MAX_OUTPUT_TOKENS` 1500); retrieval, with a possible paid query embedding through `dense.query_vector`/`metered_embed`, stage `embedding`; then generation (`stage=generation`, `generation_max_output_tokens`, reasoning effort from settings). The UI therefore labels a follow-up as two paid calls, or three when the query embedding misses the cache. `streamed(content)` stores the growing raw text in `res.partials[request_id]`. A cancel or shutdown between stages raises `_Stop`, which finishes the request as `cancelled` or `interrupted` without dispatching the next stage. A call already dispatched still settles.
