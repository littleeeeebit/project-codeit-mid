`budget.mark_dispatching(attempt_id, guard)` evaluates `_stop_reason` (cancel requested, cancelled, not running, or resources closing) together with the PostgreSQL ownership, maintenance and unknown-attempt checks, inside the same transaction that moves `reserved`→`dispatching`. On refusal it releases the reservation in that transaction and raises `DispatchRefused`, which `_paid_answer` converts into `_Stop` (cancelled or interrupted). No shutdown or cancel can slip between the check and the network call's durable marker.
