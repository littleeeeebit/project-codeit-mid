`RequestRunner._run` → `run_queued` claims the row with `UPDATE … SET status='running' WHERE status='queued' AND cancel_requested=0`, so a request runs exactly once. It rebuilds the `AnswerRequest` and `Principal` from the persisted snapshot and calls `_execute`, which opens the Langfuse trace, then `_execute_traced`. Inside, `_paid_answer` checks indexing, resolves any frozen verifier run, calls `_checkpoint`, runs `_rewrite` for follow-ups, `_checkpoint` again, then `_prepare_paid`, whose retrieval may include a paid query embedding. A run whose prompt grew past its consented estimate is refused by `_above_consented`. Empty evidence ends as `insufficient_evidence`; otherwise there is one more `_checkpoint`, then `_generate`. `_Stop` exceptions end the request as cancelled or interrupted. `ServiceError` ends it as `clarification_required` with status failed, and any other exception as `technical_error` with status failed.
