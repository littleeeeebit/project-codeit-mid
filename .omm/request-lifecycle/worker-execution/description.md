`run_queued` claims `queued → running` with `cancel_requested = 0` in one transaction (a lost claim returns silently), rebuilds `AnswerRequest` and `Principal` from `request_json`, and calls `_execute`. `_execute` wraps `_execute_traced` in a Langfuse trace. Dispatch by mode: `_metadata_answer` / `_inventory_answer` (free), otherwise `_paid_answer`. All-unavailable documents return `ingestion_unavailable` before any paid stage. `_checkpoint` runs before each paid stage and raises `_Stop` on cancel or interrupt. Exceptions map to outcomes: `_Stop` → its status, `ServiceError` → `clarification_required`/failed, any other exception → `technical_error`/failed, so a request never stays `running`.
