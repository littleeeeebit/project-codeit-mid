`GET /api/requests/{id}` -> `service.request_status` (owner or verifier only, otherwise 403) -> `_view` joins the request with its attempts: the reserved total of open attempts, the settled total, `billing_state` and the result. The route adds `attachable = service.may_attach(owned, target, view)`. Cancel: `POST /cancel` -> `cancel_request` makes a queued request `cancelled` with no paid call; for a running one it sets `cancel_requested=1`, and the next checkpoint or dispatch guard stops it while an in-flight call still settles.
