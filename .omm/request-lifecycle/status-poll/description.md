`GET /api/requests/{id}?generation_id=&target=` calls `request_status` (owner, or any verifier; otherwise `AuthError`) and returns `RequestView` (status, attempts, reserved and settled micro-USD, result) together with `attachable = may_attach(owned, target, view)`. That is true only when request ID, generation and target all match and the request was neither cancelled nor cancel-requested. A non-attachable outcome shows only as 내 최근 요청 history (`GET /api/requests`). `POST .../cancel` makes a queued request `cancelled` at once and sets `cancel_requested` on a running one. `abandon` cancels only queued requests.
