`_finish` reads the request's attempts in one transaction and derives `billing_state` by precedence unknown > pending (reserved/dispatching) > reconciled > settled > released. A row still `running` gets the computed status, or `cancelled` if cancel was requested and the outcome is `completed`. A row already `interrupted` or `cancelled` keeps that status. It then writes `trace_json` and `result_json` and drops the streamed partial. `request_status`/`_view` later report reserved micro-USD for open attempts and settled micro-USD for settled ones. `may_attach` lets the screen render it only for the same request, generation and target, and not cancelled.
