`run_queued` claims the row with `UPDATE … SET status='running' WHERE status='queued' AND cancel_requested=0`; zero rows means it was cancelled first, and the worker exits. It rebuilds `AnswerRequest` and `Principal` from request_json, so the worker never touches UI state. Inside the copied context, `bind_request`'s key session and model still apply. It then enters `_execute` under a Langfuse trace.
