`submit_answer` validates the input (`_validate_request`) and the conversation (`_conversation`). For paid modes it takes a runner slot inside the insert transaction and persists the `queued` row with its input snapshot before any work runs, so reruns and double clicks never start a second call. Refusals are synchronous 400s that say no paid call happened. If `runner.submit` fails, the slot is freed and the row is marked `failed` with `technical_error`.
