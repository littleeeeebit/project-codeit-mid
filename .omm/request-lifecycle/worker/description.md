`RequestRunner._run` → `run_queued` performs an atomic `UPDATE ... SET status='running' WHERE status='queued' AND cancel_requested=0`. A request that was not claimed (cancelled or already taken) is dropped. The worker rebuilds `AnswerRequest` and `Principal` from the persisted `request_json` snapshot (it never touches UI state) and calls `_execute`. `_checkpoint` runs `_stop_reason` before each new paid stage: a cancelled request, a status other than running, or a closing `Resources` raises `_Stop` ('cancelled' or 'interrupted'), and no further paid stage starts.
