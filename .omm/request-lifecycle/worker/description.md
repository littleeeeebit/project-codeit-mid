`run_queued` moves the row from queued to running in one statement, and only if `cancel_requested = 0`, so a request is claimed at most once. It rebuilds `AnswerRequest` and `Principal` from the persisted snapshot; the worker never reads UI state. `_execute` opens `tracing.run`. `_execute_traced` dispatches by mode and maps exceptions to outcomes: `_Stop` gives its own status, `ServiceError` gives clarification_required/failed, and anything else gives technical_error/failed. Every path ends in `_finish`.
