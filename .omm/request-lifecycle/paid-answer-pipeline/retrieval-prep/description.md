There are three paths. A frozen verifier run uses _frozen_prep (no retrieval). compare uses _prepare_compare (one retrieve per side at single-document limits, so each side is measured like the retrieval gate). single and corpus use prepare_answer, then service.retrieve with allow_paid=True, then _priced. _priced builds the messages, counts tokens and estimates generation cost plus an uncached query embedding. Retrieval exceptions end the request technical_error. Empty evidence ends insufficient_evidence with no generation reservation; a paid query embedding may already have been settled. A frozen run whose new estimate exceeds the consented one ends clarification_required.
