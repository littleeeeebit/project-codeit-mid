The `requests` row stores `request_id`, `member_id`, `idempotency_key`, `generation_id`, `input_hash`, `config_hash`, `scope_json`, `mode`, `status` and `cancel_requested`. `request_json` holds the input snapshot including capabilities. `trace_json` holds config, retrieval, rewrite, metadata_query, billing and raw_output. `result_json` holds the `AnswerResult`. `_finish` derives `billing_state` from the request's attempts with precedence unknown > pending > reconciled > settled > released. If the row is no longer `running`, `_finish` keeps the existing status. If it is still running with `cancel_requested` set, a completed outcome is stored as `cancelled`, for history only.
