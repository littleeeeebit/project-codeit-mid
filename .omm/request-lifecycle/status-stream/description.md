Two read-only channels. `GET /api/requests/{id}` returns the `RequestView` (status, billing state, reserved and settled micro-USD, result) and `attachable = may_attach(owned, target, view)`, so an answer renders only while the screen still asks exactly the same thing. `GET /api/requests/{id}/stream` turns `answer_progress` into server-sent events. The partial is exposed only while the request is running, not cancel-requested and owned by the same generation, and is parsed into `{summary, claims}` by `generation.partial_answer`. When the partial is revoked the stream sends `null`; when the request finishes it sends `done`.
