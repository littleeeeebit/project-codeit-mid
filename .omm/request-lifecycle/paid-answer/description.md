`_execute` -> `_execute_traced` -> `_paid_answer`. It first checks for unparsed or unindexed scope (`ingestion_unavailable`). `_checkpoint` stops cancelled or interrupted requests before the first paid stage, which may be the query embedding inside `retrieve(allow_paid=True)`. Retrieval and `_priced` follow (exact prompt token count, plus the embedding price on a cache miss). No evidence ends as `insufficient_evidence` with no reservation. Then a second `_checkpoint`, the reservation and dispatch (ledger-dispatch), the provider call, `validate_answer`, and `done(payload.status, ...)` with claims, missing fields (model and server merged), conflicts, the evidence map, coverage and limitations.
