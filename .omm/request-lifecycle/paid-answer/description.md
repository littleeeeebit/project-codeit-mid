`_prepare_paid` picks the preparation by mode. `prepare_answer` serves single, and corpus with `all_documents`. `_prepare_compare` runs one scoped retrieval per document at single-document limits (halving them under-served what the gate measured). `_frozen_prep` serves verifier runs. Each goes through `service.retrieve` (query embedding paid only when `allow_paid` and the backend is an API), adds metadata evidence units (`metadata_answers.evidence_units`), builds messages (`generation.build_messages`, `grounded-answer-14`) and counts tokens (`o200k_base` plus framing margin) for the estimate. A frozen run whose new estimate exceeds the consented one is refused before any call. With no evidence the answer is `insufficient_evidence` and no generation is paid. Otherwise, after a `_checkpoint`, `_generate` calls `_metered_chat(stage='generation')` with `on_delta`, so the streamed text accumulates in `res.partials[request_id]`.
