`submit_answer` calls `_validate_request`, then `_conversation`, which refuses before queueing if any earlier turn belongs to another member, is unfinished, or used a different scope. `_create` hashes the input and config snapshot and, inside `tx(immediate)`, returns the earlier request for an existing `(member_id, idempotency_key)`, or raises when the same key arrives with different input. For a new key it runs `before_insert = admit` (`RequestRunner.try_admit`, which also checks the update fence), then inserts the `requests` row as `queued` with the `request_json` snapshot. `runner.submit` schedules it. A scheduling failure frees the slot and marks the request failed, and no paid call has happened.
