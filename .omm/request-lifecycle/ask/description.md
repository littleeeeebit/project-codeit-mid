The screen keeps `Owned {request_id, generation_id, target}`, where `target` is `service.target_key(scope, question, mode, as_of, previous)`. It polls GET /api/requests/{id}?generation_id&target. `service.request_status` allows only the owner or a verifier, and `service.may_attach` returns true only while the request, generation and target still match and the request is not cancelled. A non-attachable outcome stays in history ('내 최근 요청'), and its billing still settles. `useAnswerStream` shows the provisional summary and claims until `event: done`, then the poll replaces them with the validated outcome or its failure state.
