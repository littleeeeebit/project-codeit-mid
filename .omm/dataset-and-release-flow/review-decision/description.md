`POST /api/gold/{id}/decide` → `service.gold_decide` → `gold.decide`, in one immediate transaction. The first decision wins. `expected_sha` must equal the stored row hash. A rejection needs categories (and a note for 'other'). The drafter cannot approve. For gold-2 rows, the drafting model cannot approve, and an approval requires `original_inspected`. Approval rewrites the dataset JSONL projection; rejection writes the rejection wiki page. The route docstring adds that whoever started the drafting run cannot approve it; I did not read the service-level enforcement directly.
