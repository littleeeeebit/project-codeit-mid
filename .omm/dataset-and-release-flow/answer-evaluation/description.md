`POST /api/verify/evaluation/plan` → `answers.plan_run('answer-finalists','dev')` prices every remaining row for at most two finalists, by default the activated run and its recorded finalist. `.../start` or `cli run-answers --estimate-id` → `answers.run_answers` then executes rows. For each finalist it builds `PinnedResources`, a `Resources` subclass that serves the recorded run config, charges `gold_eval`, borrows the owner's transport without taking the lock, and mirrors the owner's `_closed`. For each row `_answer_row` calls the normal `service.answer` with key `<run>:<finalist>:<question>:<attempt_no>`. A finished key returns its stored answer. A key with inconclusive billing returns `unknown_billing` and stops the run. Only an unbilled failure retries under a new attempt number. Progress is saved after every row; a budget refusal or new unknown billing stops the run, and rerunning resumes. Scoring, blind review export and import, and `latency-run` (six users × waves) share the same module. There is no paid judge.
