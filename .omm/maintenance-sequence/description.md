Triggered by 검증 → 유지보수 → 유지보수 실행 (`POST /api/verify/maintenance/start` → `start_maintenance` on a daemon thread in the serving process) or by the CLI `maintain --actor` (`_paid_resources`, which refuses while the UI owns the gateway). `maintenance.run` executes the steps in order and reuses everything unchanged, so a rerun with no changed input makes no provider call. It stops at the first failure, at a paid estimate, or at a cancel. A cancel (`POST /api/verify/maintenance/cancel` → `request_cancel`) kills a running parse at once and lets any other step finish first. Nothing already written is rolled back. The run records the serving configuration before and after and activates nothing.
