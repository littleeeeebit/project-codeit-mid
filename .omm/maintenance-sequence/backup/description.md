`step_backup` reuses the newest backup whose table digests (ignoring `audit_events`) still equal the database's and whose dump, copied files and referenced artifacts still match its manifest (`artifacts_digest`). Otherwise it takes a new one with `release.backup(..., share_owner=True)` into `RFP_BACKUP_DIR`, or into a `-backups` sibling of the data directory, never inside the runtime. A new backup that would not restore fails the step and names the problem file.
