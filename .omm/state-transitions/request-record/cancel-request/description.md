`cancel_request` (service.py:1525): a queued request becomes `cancelled` at once with a no-charge result. A running request only gets `cancel_requested=1`; its next checkpoint stops it, and a call already in flight keeps its reservation until usage arrives. `abandon_request` (sent when the screen leaves) cancels only while the request is still queued, so running work and its billing are never orphaned. Only the owning member may cancel.
