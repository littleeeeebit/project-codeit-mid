`start_state` creates run `M-<timestamp>-<hex>`, adds it to `LIVE` and marks every step pending. `run` moves each step to running and then to done, reused, skipped, failed, needs_approval or cancelled. The final run status is one of: `complete`; `unverified` (every step ran, but some originals timed out or the regression found questions whose pinned evidence was replaced); `needs_approval` (a paid embedding or regression estimate); `failed` (a step error, or the service stopping); `cancelled` (`request_cancel` was admitted while the run was in `LIVE`, including late during the last step). `maintenance_status` reports a run recorded as `running` with no live thread as `interrupted`. The state is written atomically after every step and progress tick, and a report pair is written under `reports/`.
