maintenance.state.json holds a run (`M-<timestamp>`) with status running, then complete, unverified, needs_approval or failed. Each step is pending, then running, then done, reused, skipped, needs_approval or failed. `run` (maintenance.py:359) stops at the first failed step or paid estimate. It ends `unverified` when the regression lists questions whose pinned evidence was replaced by a re-parse. It records serving before and after (expected unchanged) and the count of provider attempts. `service.maintenance_status` reports a run left `running` with no live thread as `interrupted`.
