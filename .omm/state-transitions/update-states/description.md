`$STATE/result.json` is written only by `update.sh` via `result()` (a tmp file, then `mv`). States: `running` (written before the marker is removed), then `up_to_date`, `failed` (nothing changed), `succeeded`, `rolled_back` or `rollback_failed`. A cut-off run leaves `$STATE/deploying`; the next run sees it and redeploys from the recorded commit (`RECOVERING=1`). If that fails before any change, it writes `interrupted`. `UpdateWatch.last_result` also reports a `running` result older than 30 minutes as `interrupted`. On the app side, `fenced()` is true while `accepting`, while the marker exists, or while the result says `running`.
