`requests.status` moves through these transitions: `queued` (created by `_create` for paid modes) → `running` (claimed in `run_queued`; free modes and `answer()` insert as `running`) → `completed` or `failed` (`_finish`). `queued` → `cancelled` happens through `cancel_request`. A running request with `cancel_requested` ends `cancelled` if it would have completed. `queued` or `running` → `interrupted` happens on `RequestRunner.shutdown` or on `recover_requests` at the next startup, and is never replayed. `_finish` never overwrites a status that already left `running`.
