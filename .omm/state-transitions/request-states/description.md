Transitions observed in `service.py`. `queued`→`running` happens in `run_queued` (conditional update, only when not cancel-requested). `running`→`completed`/`failed`/`cancelled` happens in `_finish`. `queued`→`cancelled` happens in `cancel_request`. `queued`→`failed` happens in `_fail_unscheduled`. `queued`/`running`→`interrupted` happens in `RequestRunner.shutdown` (running only if futures are still pending) and in `recover_requests` at startup. Terminal states are never re-run; an interrupted request stays history and must be asked again.
