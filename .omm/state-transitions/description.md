Two persisted state machines carry correctness: `requests.status` and `attempts.state`. They are coupled at exactly one point, the dispatch transaction, where `_stop_reason` reads the request while `mark_dispatching` moves the attempt. Controlled stop, restart recovery, cancel and the update fence all act on these rows and never on in-memory state, so a crash leaves a conservative, inspectable record. The maintenance run has a separate file-backed machine.
