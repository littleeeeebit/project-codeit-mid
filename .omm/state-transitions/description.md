Persisted state machines that change runtime behaviour. Request status (`requests.status`) and billing attempt state (`attempts.state`) are coupled: the stop check in `mark_dispatching` reads request status, and `_finish` and `_view` derive `billing_state` from the request's attempts. Serving activation is a pointer (`app_settings active_run/active_index`) that every request reads. Gold candidate state and maintenance run state govern the evaluation datasets and the repair sequence.
