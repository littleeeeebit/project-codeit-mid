The `requests.status` column. Free modes are inserted directly as `running`. Paid modes start `queued`. `run_queued` claims `queued → running` only when `cancel_requested = 0`. `cancel_request` makes `queued → cancelled` conclusive (no dispatch ever happened). On a running request it only sets `cancel_requested = 1`: the next `_checkpoint` or `mark_dispatching` guard stops further paid stages, and an in-flight call still settles. Controlled shutdown (`RequestRunner.shutdown`) and restart recovery (`recover_requests`) mark queued and running rows `interrupted` and replay nothing. `_finish` writes the terminal status, `completed` or `failed`, and keeps `cancelled` or `interrupted` when they were set first.
