requests.status: queued → running (`run_queued` claim) → completed or failed (`_finish`). queued → cancelled directly (`cancel_request`, with a 'no paid call' result). running + cancel → `cancel_requested=1`; the next `_checkpoint` or dispatch guard raises `_Stop('cancelled')`, and a completion is stored as cancelled. queued or running → interrupted by `RequestRunner.shutdown` or `recover_requests`. Free modes are inserted as running and finish inline. TERMINAL_STATUSES gate conversation follow-ups.
