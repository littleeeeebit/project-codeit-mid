The `maintenance/state.json` run status is running → complete | unverified | failed | needs_approval, and each step is pending → running → done | reused | skipped | failed | needs_approval. `run()` stops at the first `StepFailed`/exception (`failed`, `stopped_at`) or `NeedsApproval` (a paid embedding or regression row priced but not approved). It becomes `unverified` when the regression step reports questions whose evidence a re-parse replaced (`lost_to_reparse`). `interrupted` is not persisted: `service.maintenance_status` derives it when the state says running but no thread is alive. The report records serving before and after (`unchanged` must hold), provider calls since the start, and whether everything was reused.
