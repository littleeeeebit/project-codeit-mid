What every request serves, resolved by `service.active_serving` from `app_settings.active_run` and `active_index`, and changed only by `evaluation.activate_decision`. That function is reached through `activate-run` (CLI), a decision file, or 실험 비교 → `POST /api/verify/experiments/activate`. Activation validates the run (`decision_errors`: index and matrix verify, current policy, pinned revision and prefixes) and then writes `active_run`, `active_index` and an `activations` row with the previous config in one transaction. Maintenance and comparison never activate anything.
