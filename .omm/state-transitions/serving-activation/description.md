`app_settings.active_index` and `active_run` decide what every request retrieves with. `evaluation.activate_decision`, reached from the CLI `activate-run` or from POST /api/verify/experiments/activate, validates the run with `decision_errors` + `run_errors` (current EVAL_VERSION, matching population and finalist, embedding pinned to the registry). In one transaction it then writes the new `active_run`/`active_index` and appends an `activations` row holding the previous configuration. `Resources.index()`/`dense()` reload lazily on the next request, and `retire_inactive` unloads GPU models that are no longer used. Request config snapshots record `serving.run_id/mode/dense_version`, and a frozen verifier config becomes unusable for generation once serving changes.
