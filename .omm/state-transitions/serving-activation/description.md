`app_settings.active_run` (JSON from `evaluation.serving_config`: mode, index_version, dense_version, embedding, reranker, limits, eval_version) and `active_index`. Only `evaluation.activate_decision` writes them. The CLI `activate-run` and the UI `activate_experiment` both reach it after `decision_errors` passes (artifacts verify, current `EVAL_VERSION`, same evaluated population). It appends to `activations` with the previous value. `active_serving` may downgrade on read: a stale corpus route or an unknown embedding model serves the keyword default or K1, and HR under an old eval policy serves H without the reranker.
