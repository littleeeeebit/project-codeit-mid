There is no activation (keyword default on `active_index`) until a person activates a run. `active_serving` can downgrade a stored activation at read time (stale corpus route, unknown embedding model, stale rerank policy) without rewriting it. Each request snapshots `serving.run_id/mode/dense_version`, `index_version`, prompt version, model, rate version and a settings fingerprint into `trace_json.config` and its `config_hash`, so a later activation never changes how a past answer is described. Verifier-run generation is refused when serving changed since the run was frozen (`run_generation_block`).
