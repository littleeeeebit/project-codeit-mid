`app_settings.active_run` (JSON from `evaluation.serving_config`) and `active_index` are written together by `activate_decision` in one immediate transaction, with the previous value kept in `activations`. `service.active_serving` reads them for every request and degrades without writing anything: a corpus-route mismatch serves the keyword default, an embedding model outside the registry serves `kiwi_bm25`, and an HR run from an older `EVAL_VERSION` serves as H. Before any activation, `build-keyword` alone moves `active_index`.
