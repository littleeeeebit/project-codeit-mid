With nothing activated, serving is the keyword default on `active_index`, and a structural `build-keyword` may move that pointer. `activate_decision` sets `active_run` and `active_index` and appends to `activations`; after that, only another activation changes serving. `active_serving` derives the effective state at read time: activated; fallen back to the keyword default (`activated_corpus_route_requires_rerun`); keyword because the embedding model is unknown; or hybrid without the reranker (`stale_policy`). `_config_snapshot` records the serving run, mode and dense version in each request's `trace_json` and `config_hash`. `index()` and `dense()` reload on version change without a restart.
