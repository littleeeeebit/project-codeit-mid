The app settings `active_index` and `active_run` decide what serves. `build_keyword_index(activate=True)` moves `active_index` only on the phase-1 default path. `evaluation.activate_decision` validates the decision (`decision_errors`: the index and matrix verify, the run is under the current policy, a non-OpenAI embedding matches its pinned revision). It then writes `active_run`, `active_index` and an append-only `activations` row (with the previous configuration) in one transaction. It is reached from `activate-run` or from `POST /api/verify/experiments/activate` with the picker's name. Each request reads the pointer through `active_serving`, and `Resources` reloads the index, dense matrix and reranker lazily on the next request.
