This is how the shared codeit instance updates itself from the page. The serving process records its commit at startup and polls GitHub main. When a member presses update, the process only writes a marker file after confirming no paid work is open. A root-owned systemd path unit runs the updater script, which fast-forwards, rebuilds, restarts and health-checks, or rolls back. The process never runs git or systemctl, and no request carries a branch or commit.
