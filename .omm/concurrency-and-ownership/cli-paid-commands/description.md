`build-dense`, `run-answers`, `latency-run`, `run-judges`, `compare` with paid rows, and the CLI `maintain` construct a full `Resources` and therefore need the gateway. They fail while the UI server holds it, which is why the README and runbook say to stop the UI first. Budget administration (`unresolved`, `settle`, `reconcile`, `adjust`, `paid`, `audit`, `set-limit`) uses `dispatch=False` and runs next to the server. `check` and `load-check` use temporary databases on `RFP_POSTGRES_TEST_DSN`, and `restore-check` uses `RFP_RESTORE_DATABASE_DSN`.
