`Resources.close()` sets `_closed` (new submissions are refused, `_dispatch_guard` returns 'interrupted', and jobs see `closing()`), then calls `runner.shutdown(shutdown_wait_seconds)` and joins the job threads until the same deadline. If any thread is still alive, it runs `recover_requests` and `budget.recover`. It then closes the transport and flushes tracing after the workers, releases the gateway owner, and exits the database lifecycle. An in-flight provider call keeps its `dispatching` attempt and still settles if it returns before the process exits.
