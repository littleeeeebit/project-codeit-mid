`tx(conn, immediate=True)` locks the single `application_mutex` row `FOR UPDATE`, which makes idempotent insert, slot admission, reservation, dispatch marking, settlement and finishing linearizable across threads (and across processes such as the ledger-only CLI). `SET lock_timeout='5s'` and `statement_timeout='60s'` bound the waits; a timeout during `reserve` returns `ledger_unavailable` (fail closed). No transaction spans network inference (the `store.py` header).
