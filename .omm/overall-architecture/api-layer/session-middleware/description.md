`_Session` is pure ASGI middleware on `/api/*`. In order, it: (1) refuses with 403 any non-GET/HEAD/OPTIONS whose `Origin` netloc is neither the Host nor, with `BIDMATE_LOCAL_MEMBER`, the dev origins :8510; (2) returns 503 when `login.problem` is set (sign-in settings missing); (3) passes the three sign-in paths; (4) resolves the `bidmate_session` cookie through `login.member` and answers 401 when there is none; (5) returns 409 with `X-BidMate-Account-Changed` when `X-BidMate-Account` names someone else; (6) returns 428 for a state-changing call with no account header. It then stores `scope.state.member` and calls `service.bind_request(res, member)`. That binds the contextvars `generation.KEY_SESSION`, `generation.REQUEST_MODEL` and `budget.BILLING_SCOPE` for the request, and every thread started from it inherits them through `contextvars.copy_context()`. The bindings are reset when the request ends.
