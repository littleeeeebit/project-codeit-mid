`app.state.update` is `UpdateWatch.from_env(service.build_head())`. `build_head` runs `git rev-parse HEAD` once (lru_cache) and returns `unknown` outside a checkout. The watch is configured only when both `BIDMATE_UPDATE_REQUEST` and `BIDMATE_UPDATE_STATE_DIR` are set. Its daemon thread calls `refresh()` every `POLL_SECONDS` (300). `refresh` runs `compare`: GET `/repos/{repo}/commits/main` with the sha media type, then `/compare/{running}...{latest}`. Only `status == ahead` makes an update `available`; a 404 or a diverged/behind comparison sets a note instead. A network error keeps the previous check and adds a note. `last_result()` reads the root-written `result.json`, truncates fields to 500 chars, and reports a `running` result older than 30 minutes as `interrupted`. `fenced()` is `accepting or in_progress()`. `in_progress()` reads the marker before the result, matching update.sh, which writes `running` before it removes the marker.
