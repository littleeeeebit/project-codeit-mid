For HWP, `ocr.merge_hwp` replaces each `picture` marker that pyhwp's walk left (`walk_hwp(markers=True)`) with the `image_text` of that embedded picture's finished read, or drops it, and counts OLE objects, drawings and undecodable images as `ocr_unavailable`. For PDF, `ocr.merge` inserts one `image_text` element per finished region of the original next to the text around the image. Both return a fingerprint suffix that becomes part of the parser fingerprint. OCR itself (`ocr.run`, CLI `ocr`) reads the HWP file's embedded images (WMF/EMF rendered to bitmaps) and the PDF's raster regions with PaddleOCR-VL on the GPU, re-reads flagged regions with gpt-5-mini through the budget gateway (`ocr` envelope), and caches results under `.runtime/ocr/<hash>/`. The Hancom print is not used.
