`maintenance.run` is started from `cli maintain` or 검증 → 유지보수 (`service.start_maintenance`, one background thread). It runs `STEPS` in order and writes the run state to `.runtime/maintenance/state.json` after every change, plus a JSON and Markdown report. It stops at the first failed step, at a paid estimate (`NeedsApproval`), or at a cancel. It never activates anything and records serving before and after. A run is `unverified` when a parse timed out or when a re-parse removed questions from the rebuilt rows.
