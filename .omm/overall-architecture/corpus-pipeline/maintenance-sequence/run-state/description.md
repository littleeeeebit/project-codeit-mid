`start_state` adds the run ID to `LIVE`. `request_cancel(run_id, by)` admits a cancel only for that live run, so a late cancel never hits a successor. The loop maps outcomes: `Stopped` with a cancel becomes `cancelled`, `Stopped` from a closing service becomes `failed` ('rerun to continue'), `NeedsApproval` becomes `needs_approval`, and other exceptions become `failed` with a traceback. A cancel admitted during the last step still ends the run `cancelled`. `service.maintenance_status` shows a `running` state with no live thread as `interrupted`. Nothing already written is rolled back.
