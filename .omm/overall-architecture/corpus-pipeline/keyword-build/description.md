`build_keyword_index` selects parsed sources by review policy and freezes each document's title and institution terms (`metadata_term_snapshot`). It chunks every active extraction with `chunking.build_profile`: structural by default, or the fixed `fixed-256-32`, `fixed-512-64` and `fixed-800-96` comparison profiles, with the requirement inventory always built from structure. It tokenizes the payloads with Kiwi, writes the index directory through a temporary directory and an atomic rename, and replaces the DB rows in one transaction. It moves `active_index` only for the structural profile and only when no `active_run` exists, so after a selection only `activate-run` changes serving (`cli.cmd_build_keyword`).
