On a pyhwp failure, `ingestion._parse_source` calls `load_hwp_hwpx(original)` (`storage/hwp_loader.py`, `LOADER_ADAPTER_VERSION = hwp-loader-adapter-2`). It adds the warning `pyhwp_failed` plus the loader's warnings and switches the fingerprint to `parser_fingerprint('hwp_loader')`. The adapter uses `HwpHwpxLoader(mode='elements', include_tables=False, on_error='raise', ...)` and emits paragraph elements located as `{format: hwp_loader, path: loader/e<i>, order_basis: loader_grouped_elements, native_order_verified: false}`. A load exception returns `hwp_loader_failed`, an invalid result shape `hwp_loader_result_invalid` (discarding partial elements), and nothing usable `hwp_empty_output`. Only these reasons quarantine the source. Missing dependencies or a bad path propagate as errors, not document failures.
