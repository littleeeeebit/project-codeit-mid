`activate-run` (CLI, a decision file, or the 실험 비교 view through `service.activate_experiment`) calls `evaluation.activate_decision`. It requires `decided_by`, a current-policy (`EVAL_VERSION`) complete run, verified index and matrix, a pinned embedding revision and prefix match, and a valid finalist. It then writes `app_settings.active_run` (the run's mode, index, dense version, reranker, embedding and limits) and `active_index`, and appends `activations` with the previous value, all in one transaction. Every request re-reads it through `active_serving`, so the switch is immediate and process-wide. The reranker gate is shown but not required.
