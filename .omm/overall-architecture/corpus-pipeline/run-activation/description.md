`evaluation.activate_decision(settings, run_id, decision, actor)` runs `decision_errors`: index and matrix verify, the run is current-policy, and a pinned non-OpenAI embedding still matches. In one transaction it then writes `active_run` (the `serving_config` plus `activated_at`) and `active_index`, and appends an `activations` row holding the previous config. This is reached from CLI `activate-run` and from `POST /api/verify/experiments/activate` (`service.activate_experiment`, which requires a non-empty `decided_by`). The next `active_serving` read in any request picks it up.
