`requests` has one row per idempotency key per member: `input_hash`, `config_hash`, `scope_json`, `status`, `cancel_requested`, `request_json` (the snapshot workers rebuild from), `trace_json` and `result_json`. A reused key with different input is refused. `verifier_runs` holds frozen retrieval traces. `corrections` and `audit_events` record who did what (hub username). `app_settings` holds `active_run` and `active_index`; `activations` is the append-only activation history.
