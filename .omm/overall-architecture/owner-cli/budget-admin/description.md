Options and audit behaviour differ per command (`src/rfp_assistant/cli.py`). Read-only, no audit event: `budget-status` and `budget-report` (no options), `unresolved` (no options) and `audit [--limit N] [--actor]`. Audited with `--reason` and `--actor` (default `owner-cli`): `settle --attempt-id ... --evidence`, `adjust --key --amount-usd --evidence` and `paid on|off` (sets paid_enabled and PostgreSQL paid_admission together). Audited with required `--actor` and `--reason`: `set-limit --usd` and `set-envelopes --file`. `reconcile --file <record.json>` takes no other option: it records the audit event as `owner-cli`, with the record's `reason` field (default `provider reconciliation`). `configure-budget --start --end --prior-use-usd --prior-use-evidence --confirm-rates` writes no audit event; it appends to the budget settings history as `owner-cli`. Ledger-only commands use Resources(dispatch=False), so they can run beside the serving process without the gateway lock.
