`src/rfp_assistant/cli.py` contains the owner and maintenance commands: `init --paid-disabled`, `manifest`, `ingest`, `import-reviews`, `recover-source`, `identity`, `resolve-metadata`, `review`, `fidelity`, `ocr`, `build-keyword`, `plan-embeddings`, `build-dense`, `evaluate-retrieval`, `trial-reranker`, `compare-runs`, `draft-activation`, `activate-run`, `validate-gold`, `freeze-dataset`, `plan-run`, `run-answers`, `latency-run`, `export-review`/`import-review`, `freeze-release`, `backup`, `restore-check`, `release-report`, `configure-budget`, `budget-status`, the ledger commands, `gold ...`, `check` and `load-check`. Paid commands use `_paid_resources` (`service.Resources(settings)`); with a key present, that claims the gateway lock, so they refuse while the UI owns it. Ledger-only commands (`settle`, `adjust`) use `_ledger_owner`, which pins `FakeTransport`, so they never dispatch and can run beside the server while recording the typed `--actor`. `check` and `load-check` run against a temporary `RFP_DATA_DIR` with `OPENAI_API_KEY` removed and the fake provider only. `build-keyword` moves `active_index` only for the structural profile and only before any `activate-run` selection exists.
