`cli.main` parses a command and opens the right lifecycle. `check` and `load-check` use isolated test databases (`RFP_POSTGRES_TEST_DSN`), `restore-check` uses `RFP_RESTORE_DATABASE_DSN`, and `error-analysis` (and chunking stage review with `--inputs-from`) runs with no database. Everything else enters `database_lifecycle`, requires the validated import, runs `init_schema` (except the read-only `budget-report`) and dispatches through `COMMANDS`. Paid commands build `service.Resources(settings)` (`_paid_resources`), which takes the same gateway lock as the server, so they refuse while the UI runs. Budget administration uses `Resources(dispatch=False)` beside it.
