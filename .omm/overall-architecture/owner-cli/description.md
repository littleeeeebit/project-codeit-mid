`python -m rfp_assistant.cli <command>` (cli.py:924 main). `check` and `load-check` run against isolated temporary databases on RFP_POSTGRES_TEST_DSN with the fake provider. `restore-check` restores into RFP_RESTORE_DATABASE_DSN. Every other command enters `store.database_lifecycle`, refuses an unvalidated database and runs `init_schema` (except the read-only `budget-report`). Paid maintenance commands build a full `service.Resources(settings)` (`_paid_resources`), which takes the gateway lock and so refuses while the UI runs. Ledger-only owner commands (settle, adjust, reconcile, paid, audit, unresolved) use `Resources(dispatch=False)`; attribution and auditing differ per command. `settle`, `adjust` and `paid on|off` take `--reason` and `--actor` (default `owner-cli`) and record an audit event. `reconcile --file <record.json>` takes no other option: it runs as the fixed `owner-cli` principal and records its audit event with the record's `reason` field (default `provider reconciliation`). `unresolved` (no options) and `audit [--limit N] [--actor]` only read and record nothing. `set-limit` and `set-envelopes` require `--actor` and `--reason` and record an audit event; `configure-budget` takes neither and appends to the budget settings history as `owner-cli`. The commands cover the whole data-flow perspective: manifest, ingest, fidelity, OCR, build-keyword, plan-embeddings, build-dense, evaluate-retrieval, trial-reranker, compare, activate-run, gold, validate-gold, freeze-dataset, plan-run, run-answers, freeze-release, backup, restore-check, release-report, maintain, judges and budget configuration.
