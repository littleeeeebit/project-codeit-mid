`answers.plan_run` prices every remaining attempt. `begin_answers` publishes `config.json`. `run_answers` answers each finalist's rows on a thread pool, each through `PinnedResources`: a `Resources` subclass whose `serving()` returns the recorded run's configuration, which charges `gold_eval` and borrows the owner's transport and lock. `_answer_row` derives the idempotency key `<run>:<finalist>:<question>:<n>` and calls `service.answer` (the same execution as an interactive request). It never resends a key whose call may have been billed, and stops every worker on `budget_blocked` or a new `unknown_billing`. Sealed runs (`sealed.begin`) run once per test set; any later run is labelled a post-test regression.
