Thin handlers, each calling one service function: `_account_routes` (info, budget, key, model, update), `_ask_routes` (`/api/documents`, `/api/ask`, `/api/requests`, the SSE `/stream`), `_request_routes` (cancel, abandon, export, evidence, original download), `_verify_routes` (traces, evaluation, judges, maintenance, experiments, fidelity, corrections, gold second review) and `_dataset_routes` (drafting and gold queue, registered last so `/api/gold/{candidate_id}` does not shadow `/api/gold/recent`). The SSE handler is a sync generator. It calls `service.answer_progress` once before opening, so an unauthorized request is refused, then every 0.15 s until the request finishes. It emits `data:` only when the partial text changes, and a final `event: done`.
