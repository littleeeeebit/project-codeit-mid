`maintenance.run` executes `STEPS` in order: backup → restore_check → ingest → fidelity → keyword → embedding → regression → report. It persists the state after every step. It stops at the first `StepFailed` or `NeedsApproval` (a paid embedding stops at its estimate) and checks `closing()` before each step. It records the serving configuration before and after and the number of paid attempts since the start, and it ends `unverified` when a re-parse left gold questions without pinned evidence. It activates nothing. The UI starts it through POST /api/verify/maintenance/start (`service.start_maintenance`), and the CLI through `maintain`.
