`stage-review run <stage> --base <ref> --cand <ref>` → `stage_review.run`. It freezes inputs, copies `stage_review_worker.py` into the run folder, and checks out each ref in its own git worktree. It runs the worker as an isolated subprocess (`python -I -B`) with secrets stripped from the environment and `default_transaction_read_only` for the retriever and chunking stages. Free stages are scored into `view.json`. Paid stages (generation, ocr) stop at `needs_approval` and are immediately repriced on the ledger (`on_ledger('reprice')`). `approve` → `stage_review_paid.approve`. `resume` rechecks the estimate and refs, then hands each candidate `OPENAI_API_KEY` from the approved environment only. In the worker, generation builds its own `service.Resources` (gateway owner) and answers under idempotency keys `<run>:<candidate>:<question>:<n>`, so lost or already-billed answers are never paid twice. See state-transitions/stage-review-run.
