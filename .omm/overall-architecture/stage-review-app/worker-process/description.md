`execute` starts `python -I -B worker.py <worktree> <stage> <inputs> <config> <output> <mode>` with all secret environment variables (`OPENAI_`, `GEMINI_`, `LANGFUSE_`, ...) removed, HF offline, and `PGOPTIONS=default_transaction_read_only=on` for retriever, chunking and OCR estimate passes. It times out after 3600 s. For generation in `paid` mode, the worker builds its own `service.Resources(s)` as gateway owner of the shared ledger and answers each frozen row through `answers._answer_row`, using idempotency keys `<run>:<candidate>:<question>:<n>`. `capped_reservations` monkeypatches `budget.reserve` to cap every reservation at the approved maximum minus what the ledger already committed for that key prefix. Answers already finished are kept, answers billed but lost are shown as `lost` and never paid again, and the run stops on `blocked` / `unknown_billing`.
