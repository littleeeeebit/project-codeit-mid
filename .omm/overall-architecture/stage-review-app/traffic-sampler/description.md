`evaluation/traffic_review.py` reads one window of 질문하기 requests from the serving database. It uses a single session with `default_transaction_read_only=on` and reads only request rows whose idempotency key equals their UUID generation id and that name no verifier run. Each request's `request_json`, `result_json` and `trace_json` are frozen into a `traffic-*` run folder. Every member ID is replaced by an HMAC pseudonym whose key stays in `<data>/review/traffic/`. `write_out` is the only writer into the folder, and it refuses any file in which a known member ID survived. `draw` groups requests by mode, outcome, validation failure and document. It takes a representative per group (failures, then non-answers, then larger groups) and adds proportional extra picks under a recorded seed, with a reason for each pick. The view has the generation answer shape with one candidate, `traffic`, so the review server, the note store and the taxonomy treat it like a gold run, labelled `traffic`.
