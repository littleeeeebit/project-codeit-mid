`write_decision` validates the decision: the chosen candidate must be a completed candidate (or none), every other completed candidate needs a rejection reason, and notes may only name questions or documents present in the view. It then writes `<data>/review/decisions/<run-id>.json` (schema `review-decision-1`) and `.md`, and returns a short agent prompt pointing at both. The Markdown's next step tells the agent what to do. If the chosen ref works through `review-variant.json`, the agent reproduces the configuration with `compare`/`activate-run` and does not merge the file. If the chosen ref changes code, it is carried forward as a PR. With no candidate chosen, nothing is merged.
