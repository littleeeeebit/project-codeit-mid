`stage_review.run(settings, stage, base, cands, inputs_from)` first freezes the inputs. For retriever these are the serving activation, its index and vectors, and the dev questions plus the needle set. For chunking they are the elements of every document in the serving index. It then creates one git worktree per ref under `.runtime/review/worktrees/`, where `.` means the working tree with uncommitted files. It runs the worker for each ref, scores every candidate with the same scorer, and writes `run.json`, `inputs/`, `candidates/` and `view.json`. Afterwards the worktrees are removed and pruned. A failed candidate stays in the run with its reason.
