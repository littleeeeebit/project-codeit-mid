`service/service.py` holds the behaviour the routes and the CLI call. Its process owner `Resources` holds every shared handle. `RequestRunner` executes paid questions; background threads run drafting, answer evaluation, judge runs and maintenance; and the update fence from `service/update.py` closes new paid admission while a server update may restart the process. The CLI and tests call the same functions synchronously (`service.answer`), and the HTTP path calls them through `submit_answer`.
