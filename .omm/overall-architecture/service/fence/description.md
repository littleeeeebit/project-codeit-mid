`UpdateWatch.fenced()` is true while `accepting` is set, the marker file exists, or the updater's result.json says `running`. `_refuse_while_updating` checks it inside `RequestRunner.try_admit`, `_start_job`, `start_drafting` and `start_maintenance`. `update.request_update` raises the fence under `_runner_lock`, then calls `open_paid_work`. That function reads, in this order: live job threads and admitted slots, then queued or running request rows, then the ledger's open or unknown attempts. It refuses the update if anything is open; otherwise it writes the marker atomically and records a `request_update` audit row.
