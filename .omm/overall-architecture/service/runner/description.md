`RequestRunner` combines a `ThreadPoolExecutor(request_workers)` with `BoundedSemaphore(request_admission)` (the README gives 6 workers and 12 admitted requests). `try_admit` runs under `Resources._runner_lock` together with `_refuse_while_updating`, so an update that has been accepted never races a new request. `submit` wraps the work in `contextvars.copy_context().run`, so the worker thread keeps the member's key session, model and billing scope bound by the HTTP middleware. `_run` calls `run_queued` and then frees the slot. `shutdown` stops accepting, waits, cancels futures that have not started, and in one transaction marks queued rows `interrupted`, plus running rows when futures are still pending.
