Paid or long work that verifiers start from the screens runs on daemon threads that are recorded in `res._jobs`, so `close()` joins them. `start_answer_evaluation` runs `answers.run_answers` against a consented estimate. `start_judges` runs `judges.run`. `start_drafting` runs `drafting._generate` with gpt-6-luna, charged to `gold_eval` and kept under the consented maximum. `start_maintenance` runs `maintenance.run` over STEPS (backup, restore_check, ingest, fidelity, keyword, embedding, regression, report). `_EVAL_LOCK` allows one evaluation or judge run at a time, and drafting and maintenance each allow one. Each job publishes its run before the start call returns. A failure is written to `last-error.txt`, `error.txt` or `interrupted.txt` in the run folder. The `closing` lambdas stop work between rows, and rerunning resumes.
