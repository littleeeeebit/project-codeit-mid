`storage/postgres.py` (connections, transactions, lock, validation) and `storage/store.py` (schema). Tables observed in `store.py`: corpus (`sources`, `documents`, `extractions`, `elements`, `extraction_inputs`, `fidelity_checks`, `reviews`, `metadata_resolutions`, `institution_types`), retrieval (`indexes`, `chunks`, `requirements`, plus vector-store tables `embedding_payloads`/`embedding_sets`), serving (`app_settings` keys `active_index` and `active_run`, `activations` history), requests (`requests` with `request_json`/`result_json`/`trace_json`, `request_listings`, `verifier_runs`), ledger (`attempts`, `adjustments`, `budget_settings`, `embedding_estimates`, `eval_estimates`), review (`gold_candidates`, `gold_reviews`, `corrections`, `audit_events`), and control (`application_mutex`, `database_control`, `schema_migrations`, `migration_import`, `migration_validation`). `tx(conn, immediate=True)` takes `SELECT … FROM application_mutex FOR UPDATE`, so every writing transaction that asks for immediacy is serialized database-wide. `read_snapshot` gives a REPEATABLE READ, READ ONLY view.
