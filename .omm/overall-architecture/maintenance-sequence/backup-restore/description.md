`step_backup` reuses the newest backup whose stable table digests (audit_events excluded) equal the database's and whose dump, copied files and referenced originals, extractions and index files still hash-match (`artifacts_digest`). Otherwise it runs `release.backup` into `<backup_root>/<UTC stamp>`, fails if the new backup would not restore, and records it in backups.json. `step_restore_check` creates a scratch database `rfp_mrestore_<uuid>` on the same server, points RFP_RESTORE_DATABASE_DSN at it temporarily, runs `release.restore_check` with paid admission off, and always drops the scratch database. A pass is bound to the artifact digest, so it can be reused.
