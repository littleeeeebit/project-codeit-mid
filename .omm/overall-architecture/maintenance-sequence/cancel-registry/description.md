Module globals: `LIVE` (run_ids admitting a cancel) and `CANCELS` (run_id → {by, at}), guarded by CANCEL_LOCK. `start_state` creates `M-<stamp>-<6 hex>` and adds it to LIVE before the thread starts. `request_cancel(run_id, by)` is admitted only while that run is in LIVE. `service.cancel_maintenance` also requires a live maintenance thread; a stale id gets '…이미 끝났습니다'. `maintenance_status.cancelling` is true while the live run's id is in CANCELS.
