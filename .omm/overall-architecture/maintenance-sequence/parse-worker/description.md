`ParseWorker.__call__` lazily spawns one `multiprocessing` 'spawn' child (`_parse_child`, its own process group on POSIX), waits up to 120 s for 'ready', then sends (settings, src, original) per file over a Pipe. `_wait` polls every 0.2 s. `stop()` true → `close()` and `Stopped`; past `parse_timeout_seconds` → `close()` and `ParseTimedOut`; EOF → `IngestionError` with the exit code; a child exception is re-raised with its traceback as a note. `close()` runs `taskkill /F /T` on Windows (killing converter descendants such as hwp5proc) or `killpg SIGKILL` on POSIX, then `proc.kill()` and join. The next file starts a new child. All DB writes stay in the parent.
