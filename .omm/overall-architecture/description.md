RFP assistant (입찰메이트) is a single-process Python application with one Next.js front end. `rfp_assistant.api:app` (FastAPI, `src/rfp_assistant/api.py`) does three things: it wraps the `service` module one function per route, mounts the static Next.js export from `web/out` last so `/api/*` stays the API's, and on lifespan start creates the one process-wide `service.Resources` via `service.app_resources()` -> `get_resources(load_settings())` -> `Resources(settings, recover=True)`. That object owns everything else: the paid-gateway lock, the OpenAI transport, the bounded request executor, the shared Kiwi analyzer, and the lazily loaded keyword index, dense matrix and reranker. Owner maintenance (`python -m rfp_assistant.cli`) builds its own `service.Resources` against the same database. A paid CLI command with an API key therefore tries to claim the same gateway lock and fails with `GatewayLockError` while the UI runs. Every paid call (answer generation, query embedding, corpus embedding, gold drafting, evaluation answers) goes through one ledger in `budget.py` and one transport in `generation.py`. The exception is the Gemini OCR fallback, which keeps its own JSONL ledger. Free paths (document search, metadata and inventory modes, evidence browsing, verifier traces, fidelity pages) never touch the transport.
