The live system is one Python process: `uvicorn rfp_assistant.api:app --workers 1`. `api.create_app` mounts the `/api/*` routes first and the static Next.js export (`web/out`) last, so one port serves both the screens and the API. Each route calls exactly one `service` function. FastAPI's lifespan calls `service.app_resources()` → `get_resources(load_settings())`, which builds one `Resources(settings, recover=True)` for the process. That object owns the PostgreSQL pool (`postgres.lifecycle`), the database-wide paid-gateway advisory lock (`postgres.GatewayOwner`), the provider transport, the loaded keyword/dense indexes, the bounded request executor and the background jobs. Every paid provider call goes through the ledger in `budget.py` (reserve → mark_dispatching → settle/release/unknown). Corpus artifacts (extractions, keyword indexes, embedding sets, evaluation runs) are produced offline by the owner CLI (`python -m rfp_assistant.cli ...`) and the in-app maintenance job. The server only reads them, through the `active_run`/`active_index` rows in `app_settings`. Langfuse tracing observes requests and never gates them.
