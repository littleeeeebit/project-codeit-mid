RFP assistant (BidMate) is a single-process FastAPI application. It serves a statically exported Next.js UI, and every action goes through one Python service layer on top of PostgreSQL 18.6 + pgvector 0.8.6. The browser posts a question about one or two selected Korean RFPs, or about the whole corpus. `service.submit_answer` persists the request under an idempotency key and runs it on a bounded in-process executor. The worker retrieves evidence (Kiwi BM25, optionally fused with pgvector dense search and a local reranker), reserves the maximum cost in a shared ledger, makes one `gpt-6-luna` call through the provider transport, validates every citation, and stores the result on the request row. The browser polls that row. Offline work (ingestion, fidelity checks, index builds, embedding, comparison matrices, answer and judge evaluation, the sealed run, backup and restore) runs through the owner CLI or through background threads in the same server process. It uses the same `Resources` owner, ledger and database-wide gateway lock. What serves is decided only by an explicit activation recorded in `app_settings.active_run`.
