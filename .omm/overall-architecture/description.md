BidMate (the RFP assistant) is a single-process Python application. It answers grounded questions about historical Korean RFP documents and charges each paid model call to one shared budget ledger in PostgreSQL. One uvicorn worker runs `rfp_assistant.api:app`, which `create_app` in src/rfp_assistant/api.py builds. That process serves the statically exported Next.js screens from web/out and the /api routes, and each route delegates to one function in src/rfp_assistant/service/service.py. The service layer owns a process-wide `Resources` object: the settings, the keyword index and dense index loaded once and cached, the paid transport, and the bounded request executor. The CLI (src/rfp_assistant/cli.py) is a second entry point. It builds its own `Resources`, or calls corpus and evaluation modules directly, for owner maintenance: manifest, ingest, OCR, fidelity, index builds, evaluation runs, activation, and budget administration. All durable state lives in one validated PostgreSQL 18.6 + pgvector 0.8.6 database. This covers documents, extractions, chunks, requests, the attempts ledger, audit events and embedding vectors. Bulk artifacts (element JSONL, index directories, OCR caches, run outputs) live under the data directory (`RFP_DATA_DIR`, default .runtime) and are hash-referenced from database rows. What serves users is decided only by the `active_run` and `active_index` rows in `app_settings`, which `activate_decision` in src/rfp_assistant/evaluation/evaluation.py writes after a person picks a row. Every OpenAI call goes through `generation.OpenAITransport` (src/rfp_assistant/gateway/generation.py) after `budget.reserve` and `budget.mark_dispatching` have recorded it in the ledger.
