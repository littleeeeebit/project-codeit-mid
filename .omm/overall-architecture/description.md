BidMate (입찰메이트) is an internal assistant over about 100 historical Korean RFPs. Members search projects, scope a question to one or two documents or to the whole corpus, and get one metered, citation-checked answer whose evidence opens next to the original. The backend is one Python package, src/rfp_assistant. FastAPI (api.py) serves it, and the same process also serves the static Next.js export from web/out. It must run in exactly one uvicorn worker, because paid requests run on that process's own executor and the process holds a database-wide PostgreSQL advisory lock that makes it the only paid gateway. Every record lives in PostgreSQL 18.6 with pgvector 0.8.6, reached through RFP_DATABASE_DSN: documents, extractions, chunks, requests, the billing ledger, gold rows and vectors. File artifacts (extraction element files, keyword index directories, run reports, comparison tables, maintenance state) live under .runtime and are hash-checked at startup. Free work never reaches a provider: search, filters, evidence browsing, retrieval traces, and metadata or requirement-inventory answers. Paid work always goes through budget.reserve → budget.mark_dispatching → transport call → settle, release or unknown: answer generation, follow-up rewriting, uncached query and corpus embeddings, gold drafting, Luna judge calls and answer evaluation. Offline corpus work runs through cli.py or the 검증 (verify) screens: manifest, ingest, fidelity check, OCR, keyword index, embeddings, frozen evaluation runs, comparison matrices, backup and restore. Nothing changes what serves until a person activates a run (evaluation.activate_decision).
