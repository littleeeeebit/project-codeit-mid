An internal assistant for historical Korean RFPs. A consultant searches projects, scopes a question to one or two documents (or the whole corpus), gets one metered, citation-checked answer, and opens the original evidence. At runtime it is one uvicorn process. It must run with exactly one worker (`uvicorn rfp_assistant.api:app --workers 1`). That process serves the static Next.js export from `web/out` and the FastAPI routes in `api.py`, and each route calls one function in `service/service.py`. All records live in one validated PostgreSQL 18.6 + pgvector 0.8.6 database named by `RFP_DATABASE_DSN`. Immutable files under `RFP_DATA_DIR` (`.runtime/`) sit beside the database: extraction artifacts, keyword index directories, run folders, maintenance reports and review runs. Every paid OpenAI call goes through `gateway/budget.py` in a fixed order: reserve, mark dispatching, call, then settle or mark unknown. This applies to answers, follow-up rewrites, metadata query translation, query embeddings, gold drafting, judges and the OCR fallback. The serving process holds a database-wide advisory lock while it dispatches. Corpus building, evaluation and activation run from the CLI (`cli.py`) against the same database. A separate stage-review app (`review/server.py`) shows comparisons of git refs on frozen inputs. It never pays and never loads a model.
