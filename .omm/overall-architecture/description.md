BidMate (RFP assistant) runs as a single Python process. `uvicorn rfp_assistant.api:app --workers 1` serves the FastAPI routes in src/rfp_assistant/api.py. When web/out exists, it also serves the statically exported Next.js screens, mounted last at `/` so `/api/*` stays with the API. Every route calls exactly one function in src/rfp_assistant/service.py. That module owns the process-wide `Resources`: the loaded keyword index, dense matrix, reranker, provider transport, request executor and gateway ownership. A question is retrieved inside the selected scope (one or two documents, or every indexed document) by src/rfp_assistant/retrieval.py. The answer is generated through the metered gateway: `service._metered_chat` uses budget.py for reservation and settlement and generation.py for the OpenAI or Fake transport. It is then validated against the evidence quotes and persisted in PostgreSQL. Indexes, runs, comparison tables, datasets and reports are written by the owner CLI pipelines (src/rfp_assistant/cli.py). These are immutable file artifacts under the data directory (default `.runtime`), and PostgreSQL rows point to them by version and hash. What serves users changes only when a person activates a run: `evaluation.activate_decision` writes `app_settings.active_run` and `active_index`.
