BidMate (입찰메이트) is an internal assistant for historical Korean RFPs. Members pick one or two documents, or all of them. They ask a scoped question, get one metered answer grounded in cited evidence, and can open the original. One uvicorn process (`rfp_assistant.api:app`, run with `--workers 1`) serves two things. The first is the static Next.js export in `web/out`. The second is the `/api` routes, each of which calls exactly one function in `service/service.py`; `tests/test_api.py` enforces that import boundary. The service owns everything that runs: retrieval over a versioned Kiwi BM25 index and pgvector embedding sets, the paid gateway (a budget ledger plus the single OpenAI call site), Langfuse tracing, and background paid jobs. All durable state lives in one PostgreSQL 18.6 database with pgvector 0.8.6, plus hashed artifact files under `.runtime`. Corpus building, index builds, evaluation, activation and budget administration run from the owner CLI (`cli.py`), and from a few verifier routes that call the same functions. The CLI uses the same `Resources` owner and the same database-wide gateway advisory lock as the server. That is why paid CLI work refuses to run while the serving process holds the lock. Paths and behaviour here come from reading `api.py`, `service.py`, `budget.py`, `generation.py`, `tracing.py`, `retrieval.py`, `vector_store.py`, `dense.py`, `ingestion.py`, `fidelity.py`, `drafting.py`, `gold.py`, `maintenance.py`, `update.py`, `auth.py`, `store.py`, `cli.py` and the web client hooks. `chunking.py`, `compare.py`, `judges.py`, `sealed.py`, `release.py` and `postgres_backup.py` are described from their entry points and docstrings, not traced line by line.
