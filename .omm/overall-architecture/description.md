BidMate is one uvicorn process (`rfp_assistant.api:app`, `--workers 1`) that serves two things: the static Next.js export from `web/out`, and a FastAPI layer in which each route calls exactly one function in `service/service.py`. The FastAPI lifespan creates a single process-wide `Resources` object through `service.app_resources()` -> `get_resources(settings)` -> `Resources(recover=True)`. That object owns the PostgreSQL pool, the paid-gateway advisory lock, the loaded keyword index, the pgvector set handle, the optional local reranker, the OpenAI transport and the bounded request executor. Free work reads PostgreSQL and the `.runtime` artifact files: document search, metadata and requirement-inventory answers, evidence, originals and verifier traces. Paid work always follows reserve -> mark_dispatching -> provider call -> settle, release or unknown in `gateway/budget.py`: follow-up rewriting, uncached query embeddings, answer generation, gold drafting, answer evaluation and judge runs. The owner CLI (`cli.py`) runs corpus processing, index builds, retrieval evaluation, the sealed run and budget administration. From the Verify (검증) screen, the maintenance sequence, development answer evaluation, judge runs and activation run inside the serving process. Observed: screens reach the backend only through same-origin fetch and SSE to /api, and no policy decision is made in `web/`.
