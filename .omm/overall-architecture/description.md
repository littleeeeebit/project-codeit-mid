Bidmate (입찰메이트) is an internal assistant over about 100 historical Korean RFP originals (HWP and PDF). It runs as one FastAPI process. That process serves a static Next.js export, the consultant and verifier screens, plus a JSON/SSE API. Every API route goes through a session middleware into plain functions in service.py. Those functions own one process-wide `Resources`: the active keyword index, the dense matrix, the reranker, the OpenAI transport, Langfuse tracing and a bounded request executor. Answers are produced by scoped retrieval (`service.retrieve` → `retrieval.retrieve`) followed by one or two metered chat calls through the budget gateway (`_metered_chat` → `budget.reserve` / `mark_dispatching` / `settle`). Every durable record lives in one PostgreSQL 18.6 + pgvector 0.8.6 database: documents, extractions, elements, chunks, requests, traces, the ledger, audit events and vectors. The module that opens connections and holds the database-wide gateway advisory lock is storage/postgres.py. Offline work runs through `python -m rfp_assistant.cli`: manifest, ingest, OCR, fidelity, index and dense builds, evaluation, activation, backup/restore and stage review. Nothing offline changes what serves until a person activates a run. A separate standard-library review server (review/server.py) shows frozen stage-review and traffic run folders, and records decisions, span notes and failure-type decisions as files under `<data>/review`. It never runs a pipeline or pays.
