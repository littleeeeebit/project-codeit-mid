BidMate (입찰메이트) runs as one Python process. `rfp_assistant.api:create_app` builds a FastAPI app that serves the JSON API under /api/* and mounts the static Next.js export from `web/out` at `/`. Each API route calls one function in `service/service.py`, which owns the process-wide `Resources`: the Kiwi analyzer, the loaded keyword and dense indexes, the reranker, the OpenAI transport, Langfuse tracing and the paid-gateway advisory lock. All persistent state lives in one PostgreSQL 18.6 + pgvector 0.8.6 database named by `RFP_DATABASE_DSN`. That covers documents, extractions, chunks, indexes, vectors, requests, ledger attempts, app settings such as `active_run`, and audit rows. Indexes and run artifacts also have files under `RFP_DATA_DIR` (.runtime). Every paid OpenAI call follows the same path: an atomic reservation in `gateway/budget.py`, a dispatch marker, the call in `gateway/generation.py`, then settlement. Offline work goes through `cli.py`: ingest, index builds, evaluation, activation and budget administration. Long jobs (drafting, answer evaluation, judges, maintenance) can also start from the screens as background threads in the server. This branch adds a self-update path. `service/update.py` compares the running commit with GitHub main, and a member's request writes a marker file. Root-owned systemd units turn that marker into `tools/infra/update.sh`, which fast-forwards, rebuilds, restarts and rolls back on failure.
