BidMate (입찰메이트) answers questions about historical Korean RFPs. Everything runs in one Python process: `uvicorn rfp_assistant.api:app --workers 1`. On startup, `api.create_app` enters its lifespan, which calls `service.app_resources()` → `get_resources(load_settings())` → `Resources(settings, recover=True)`. That constructor does five things in order. (1) It opens the bounded psycopg pool through `store.database_lifecycle`. (2) It refuses to start unless `postgres.require_imported_database` finds a complete `migration_import` with a passing `migration_validation` and unchanged artifact hashes. (3) It runs `init_schema`. (4) It takes the database-wide `pg_try_advisory_lock(GATEWAY_LOCK)` in `postgres.GatewayOwner`. (5) It recovers leftovers: unfinished requests become `interrupted`, `dispatching` attempts become `unknown`, and `reserved` attempts are `released`. The same process serves the static Next.js export (`web/out`, mounted at `/` after every `/api/*` route) and the JSON/SSE API. A browser calls a route; each route calls exactly one `service` function. Service functions orchestrate three things: retrieval over a keyword index loaded from `.runtime/indexes/<version>` plus pgvector embedding sets; paid OpenAI calls through the reservation ledger in `budget.py`; and persistence in PostgreSQL. Building the corpus is offline owner work through `python -m rfp_assistant.cli` (manifest, ingest, fidelity/OCR, build-keyword, build-dense, compare, activate-run). A few of these also run from the 검증 screen in background threads (maintenance, experiment activation). Langfuse tracing (`tracing.py`) is optional and observability-only: admission and settlement never read it.
