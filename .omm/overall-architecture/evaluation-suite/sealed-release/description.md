`sealed.freeze_release` records the release candidate: activated run, code, metric, prompt, model, rate and settings hashes, frozen dev and test manifests, and the selected answer run. The sealed test set then runs once through `plan-run --action sealed` and `run-answers`; any later run is labeled post-test (`sealed_run_id(..., post_test)`). `release.write_release_report` combines hard checks and quality targets in `decide_status` into ready, limited or blocked. `release.backup` and `restore_check` provide the backup evidence. Sealed questions and labels never leave the service: `SealedState` exposes only size and freeze state.
