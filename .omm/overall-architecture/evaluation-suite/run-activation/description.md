`activate_decision` runs for `activate-run`, a decision file, or `service.activate_experiment` from the verify screen. It checks `decision_errors`: index and matrix verification, current-policy run, pinned embedding revision and prefixes, and a finalist on the same population. Then, in one transaction, it writes `app_settings.active_run` (`serving_config`: mode, index_version, dense_version, reranker, embedding, limits, eval_version) and `active_index`, and appends an `activations` row holding the previous value. `service.active_serving` reads it on every request, and `Resources.index()`, `dense()` and `reranker()` reload when the version changes.
