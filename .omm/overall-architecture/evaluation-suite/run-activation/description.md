`activate_decision(settings, run_id, decision, actor)` validates through `decision_errors` (complete current-policy run, finalist on the same population, ready index and matrix). It then writes, in one transaction: `app_settings.active_run` = `serving_config(run_id, config)` plus `activated_at`; `active_index` = the run's index; and an append-only `activations` row with the previous configuration. It is reached by `cli activate-run` (decision file or flags) and by `POST /api/verify/experiments/activate`, which requires `decided_by`. The next `Resources.index()`, `dense()` and `reranker()` call picks the change up through `active_serving`, with no restart.
