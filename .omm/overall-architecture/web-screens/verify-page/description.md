The verification page is a set of sections: trace, compare, evaluation, judges, dataset/gold, ingestion, corrections (history) and exports. On load it polls `GET /api/verify/overview`, `/api/verify/fidelity`, `/api/verify/ingestion` and `/api/verify/traces`. The trace section (`trace.tsx`) loads `GET /api/verify/trace-sources` and creates a frozen retrieval-only run with `POST /api/verify/traces`. It reads runs with `GET /api/verify/traces/{run_id}`, compares two runs with `GET /api/verify/compare?a&b`, and can request one paid answer from a frozen run with `POST /api/verify/traces/{run_id}/generate`, then polls `GET /api/requests/{request_id}`. Evaluation (`evaluation.tsx`) calls `POST /api/verify/evaluation/plan`, then `/start` with the estimate ID. Judges (`judges.tsx`) do the same through `/api/verify/judges/plan|start|progress|results|disagreements`. Fidelity (`fidelity.tsx`) shows rendered pages and confirms with `POST /api/verify/fidelity/{source_hash}/confirm`. The history section (`records.tsx`) polls `GET /api/verify/history` every 5 s. Exports are plain links to `/api/requests/{id}/export` and `/api/verify/traces/{run_id}/export`.
