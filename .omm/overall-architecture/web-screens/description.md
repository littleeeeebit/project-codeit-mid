A Next.js app (`web/`) built as a static export that the API process serves. It has four screens: 질문하기 (`AskPage`), 검증 (verify tabs), 데이터셋 만들기 (dataset drafting and review) and 설정 (settings). Every call goes through a typed `openapi-fetch` client generated from `web/openapi.json`. The screens hold no business logic: `service.py` makes every decision, including whether a result may attach to the current screen (`may_attach`). Screens poll with `usePoll`. The ask page also streams provisional answer text over SSE.
