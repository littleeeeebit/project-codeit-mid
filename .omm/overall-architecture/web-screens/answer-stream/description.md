`useAnswerStream` starts only for paid modes, while the turn is live and not revoked. It reads `GET /api/requests/{id}/stream?generation_id=` with `fetch` and an `AbortController`, splitting the server-sent events by hand. A `data:` event replaces the provisional `{summary, summary_evidence_ids, claims}`, and `data: null` withdraws it. `event: done` calls the status poll's `reload`, so the validated answer replaces the provisional text at once. Errors are swallowed on purpose: the status poll still delivers the outcome if the stream drops. Late events from a request the screen has left are dropped by the key check.
