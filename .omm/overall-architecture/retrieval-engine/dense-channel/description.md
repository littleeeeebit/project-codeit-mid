`DenseIndex.search(query_vector, allowed, k)` searches the activated vector set. `DenseIndex.load` verifies the set against the base index version, and the vectors live in pgvector (`retrieval/vector_store.py`). In hybrid modes this channel is skipped, with limitation `no_lexical_match:dense_not_used`, when there is no lexical, exact or name-only match, because nearest neighbours always exist and would be arbitrary passages. If the matrix model or dimensions differ from the run's embedding, `service.retrieve` drops dense and never pays for a query vector the matrix cannot score.
