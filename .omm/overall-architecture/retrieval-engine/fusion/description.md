`retrieval.fuse` (retrieval.py:508) computes weighted RRF (`rrf_fuse`, sum of weight/(k+rank)) over the lexical and dense rankings. With `fusion=keyword_first` the leading `keyword_head` BM25 rows stay in BM25 order and only the rest follow RRF, so a dense row can never displace a protected keyword match. The result is truncated to `fused_top_k`. If a hybrid mode has no lexical and no exact match, dense is not used at all (`no_lexical_match:dense_not_used`), because nearest neighbours always exist even when nothing is relevant.
