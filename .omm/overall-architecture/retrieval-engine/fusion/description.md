`fuse()` → `rrf_fuse([lexical, dense], rrf_k, [1.0, dense_weight])`. With `fusion == keyword_first`, the leading `keyword_head` BM25 rows stay in BM25 order and the rest follow the RRF order, so a dense row can never displace a protected keyword match. The result is truncated to `fused_top_k`. When hybrid finds no lexical match and no exact code, dense is skipped (`no_lexical_match:dense_not_used`), because nearest neighbours alone are not evidence.
