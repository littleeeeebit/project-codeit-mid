`dense.query_vector` looks up a pgvector-cached query vector by normalized text, model and dimensions. On a miss there are three paths: a local model embeds on the GPU for free; Gemini charges its own cap ledger; OpenAI goes through `metered_embed` (stage `embedding`, the request's purpose) only when `allow_paid` and a `request_id` are present, under the same dispatch guard. `DenseIndex.search` (vector_store.py) runs `EXACT_SQL` cosine ordering over `embedding_set_rows` restricted to the allowed `row_order`s. It uses HNSW only when the run selected `dense_search: hnsw`. A missing matrix, mismatched base index, missing vector or wrong dimensions falls back to `kiwi_bm25` and is recorded in `fallback`. A hybrid question with no lexical match does not use dense neighbours (`no_lexical_match:dense_not_used`).
