`PgDenseIndex.search(query, allowed, k, settings)` runs `EXACT_SQL`: cosine distance `<=>` over `embedding_set_rows` joined to `embedding_payloads`, restricted to `row_order = ANY(allowed)` and ordered by distance then chunk ID. HNSW (`HNSW_SQL` with an iterative strict-order scan) runs only when the activated run selected `dense_search: hnsw`. `PgDenseIndex.load` verifies the set and source identity, row order, model, dimensions and policy, and every vector's checksum and unit norm. Query vectors come from `dense.query_vector`: a cache hit by payload hash, otherwise paid through `metered_embed` only when `allow_paid` and a request ID exist. In hybrid modes, dense search does not run when neither a lexical nor an exact match exists (`no_lexical_match:dense_not_used`).
