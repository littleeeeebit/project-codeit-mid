`dense.query_vector` looks up the query embedding cache by normalized text, model and dimensions. On a miss it embeds locally on the GPU (free), through Gemini under its own cap, or through OpenAI with `metered_embed` (ledger stage `embedding`), but only when `allow_paid` and a request id are given. `PgDenseIndex.load` verifies set identity, row order, per-row checksums and alignment with the keyword index chunk order. `search` runs `EXACT_SQL` or `HNSW_SQL` (depending on `settings.dense_search`) restricted to the allowed row ids. When the dense set, the query vector or the dimensions are missing, the mode falls back to kiwi_bm25 and the reason is recorded in `fallback`.
