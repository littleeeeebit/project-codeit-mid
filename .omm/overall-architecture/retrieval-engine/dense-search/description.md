`PgDenseIndex.search` (in `vector_store.py`, loaded through `dense.DenseIndex.load`) runs `EXACT_SQL`: cosine distance over `embedding_set_rows JOIN embedding_payloads` filtered by `set_version` and `row_order = ANY(allowed)`. `HNSW_SQL` with transaction-local `hnsw.ef_search` and `iterative_scan=strict_order` is used only when the activated run selected `dense_search: hnsw`. If the hybrid lexical channel finds nothing, dense is skipped (`no_lexical_match:dense_not_used`) because nearest neighbours always exist and would be arbitrary passages.
