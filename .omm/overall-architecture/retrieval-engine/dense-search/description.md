`vector_store.PgDenseIndex` runs `EXACT_SQL`: cosine distance over `embedding_set_rows` joined to `embedding_payloads` for the set version, restricted to the scope's `row_order` values. An HNSW path (`HNSW_SQL`, with session settings that force the index scan) exists only for runs that selected `dense_search: hnsw`. When there is no lexical match in hybrid mode, dense search is skipped (`no_lexical_match:dense_not_used`), because nearest neighbours always exist and would otherwise return arbitrary passages.
