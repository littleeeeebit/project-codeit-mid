PgDenseIndex.search runs EXACT_SQL (cosine `<=>` over embedding_set_rows joined to embedding_payloads, filtered to the admitted row_order list), or HNSW_SQL with transaction-local planner settings when the run selected dense_search=hnsw. The query vector comes from dense.query_vector: a cache hit on embedding_payloads is free. A miss is paid through metered_embed only when allow_paid and a request_id exist (paid answers). Free callers get cache=miss and the mode falls back to kiwi_bm25. In hybrid modes, dense search does not run at all when there is no lexical or exact match (no_lexical_match:dense_not_used), so nearest neighbours never become evidence on their own.
