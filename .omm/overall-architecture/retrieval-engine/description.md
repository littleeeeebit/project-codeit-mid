`service.retrieve` resolves the scope and loads `res.index()`. It retires GPU models the activated configuration no longer uses, applies the run's settings (`res.run_settings`), obtains a query vector when the serving mode is dense, and calls `retrieval.retrieve` inside a `retrieve-evidence` trace step. Stage by stage, this is described under `retrieval-pipeline`. The result is a `RetrievalResult` with the packed `EvidenceUnit`s (E1…En), candidates per channel, limitations such as `index_outdated:` and `activated_run_stale:corpus_route`, any fallback, and timings.
