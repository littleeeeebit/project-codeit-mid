`service.retrieve` resolves the scope (`_resolve_scope`, or `corpus_scope` for all documents) and loads `res.index()` and `res.serving()` (`active_serving`: the activated run from `app_settings.active_run`, else the keyword default `kiwi_bm25`). It calls `retire_inactive`, applies `run_settings(cfg)` so serving reproduces the evaluated limits, embedding and reranker, and fetches a query vector through `dense.query_vector` only for dense modes; it is paid only when `allow_paid`. It then calls the pure function `retrieval.retrieve`. Outdated indexes (`index_compatibility`), a stale corpus route and unavailable stages are appended to `limitations` instead of failing.
