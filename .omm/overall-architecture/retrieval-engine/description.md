`service.retrieve` resolves the scope (`_resolve_scope`, or `corpus_scope` for All documents), loads the active serving configuration, retires GPU models that configuration no longer uses (`retire_inactive`), applies the activated run's settings (`run_settings`) plus any narrowing limits, fetches a query vector when the mode is dense, and calls `retrieval.retrieve`. It annotates `limitations` with `index_outdated:*`, `activated_run_stale:corpus_route` and `*_unavailable`, and wraps everything in a `retrieve-evidence` trace step.
