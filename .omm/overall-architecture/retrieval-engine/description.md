`service.retrieve` authorizes the caller, resolves the scope (or the whole corpus via `corpus_scope`) and loads the active `KeywordIndex`. It applies the activated run's settings (`run_settings`) and any narrowing limits (`_narrow_limits`, which never raises a limit). For dense modes it gets a query vector from `dense.query_vector`: from the cache, from a local GPU model, or as a paid gateway embedding only when `allow_paid`. It then calls `retrieval.retrieve` inside a `retrieve-evidence` trace step and appends limitations such as `index_outdated:`, `activated_run_stale:corpus_route` and `dense_unavailable`. The modes are K0 `whitespace_bm25`, K1 `kiwi_bm25`, D `dense`, H `hybrid` and HR `hybrid_rerank`. When a dense matrix, query vector or reranker is missing, `_available_mode` falls back and records why in `fallback`.
