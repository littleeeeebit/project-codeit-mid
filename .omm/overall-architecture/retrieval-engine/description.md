`service.retrieve` (service.py:591) resolves the scope and loads the active keyword index, the serving configuration and the run settings (`Resources.run_settings` overrides embedding, depths, fusion and evidence limits with what the activated run measured). For dense modes it obtains a query vector, then calls `retrieval.retrieve` (retrieval.py:519). The result is a `RetrievalResult` holding candidates per channel, ranking, packed EvidenceUnits (E1..En), exclusions with reasons, limitations, timings and any fallback. Limitations such as `index_outdated:*`, `activated_run_stale:corpus_route`, `dense_unavailable` and `scope_redundant_terms:*` travel into the trace and the answer.
