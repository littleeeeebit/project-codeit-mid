`service.retrieve` resolves the scope: a selection maps to `(DocRef, active_extraction_id)` pairs, and `all_documents` uses `corpus_scope`. It reads the serving config and, for dense modes, obtains a query vector, then calls `retrieval.retrieve(...)` inside the Langfuse span `retrieve-evidence`. The keyword index (BM25 over the persisted `tokens.jsonl`) is held in memory. Dense search runs as SQL against pgvector. The output is a `RetrievalResult` carrying numbered `EvidenceUnit`s (E1..En), candidates per channel, the ranking, exclusions with reasons, limitations, timings and any fallback. The README records the current serving config (run `H-0fffb2a6ec`): hybrid keyword-first fusion, 50 candidates per channel, 10 evidence units, exact pgvector search.
