`service.retrieve` resolves the scope: the selected (`DocRef`, active extraction) pairs, or `corpus_scope` for all documents. It also picks the serving mode and settings and fetches a query vector: from the cache, or through the gateway when the caller is a paid request. It then calls `retrieval.retrieve`, which produces a `RetrievalResult`: candidates per channel, ranking, packed `EvidenceUnit`s (`E1`…), exclusions, limitations and timings. Modes are `whitespace_bm25` (K0), `kiwi_bm25` (K1), `dense`, `hybrid` and `hybrid_rerank`. The README records the serving configuration as hybrid keyword-first fusion over exact pgvector search: run `H-0fffb2a6ec` with 50 candidates per channel, a BM25 head of 6, RRF k 60, dense weight 1.0 and 10 evidence units.
