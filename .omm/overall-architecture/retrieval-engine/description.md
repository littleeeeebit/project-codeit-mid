`service.retrieve` resolves the scope (or `corpus_scope` for all documents) and the activated configuration (`res.serving()` and `run_settings`). In dense modes it obtains a query vector, then calls `retrieval.retrieve`, which is pure computation over the loaded `KeywordIndex` (BM25Okapi over Kiwi tokens persisted with the index) and `PgDenseIndex`. The result's `limitations` record every fallback: `index_outdated:`, `activated_run_stale:corpus_route`, `dense_unavailable`, `hybrid->kiwi_bm25:<reason>`, `scope_redundant_terms:`, `linked_evidence_missing:`. Serving keeps answering, visibly degraded, and the configuration is never rebuilt during a question.
