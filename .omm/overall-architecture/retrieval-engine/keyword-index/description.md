KeywordIndex.load verifies the `indexes` row's manifest hash and every file hash (chunks.jsonl, tokens.jsonl, requirements.jsonl, scope-terms.json) under RFP_DATA_DIR/indexes/<version>. It rebuilds BM25Okapi from the persisted Kiwi tokens and loads elements per extraction. It maps source_hash → extraction from the `extractions` table so serving reads through the extraction the index holds, not a newer re-parse. build_keyword_index (CLI build-keyword, maintenance step_keyword) writes the directory atomically and inserts `chunks` and `requirements` rows. It moves app_settings active_index only when activate=True.
