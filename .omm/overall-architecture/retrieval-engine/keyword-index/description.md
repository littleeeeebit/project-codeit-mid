`build_keyword_index` runs from the CLI `build-keyword` command and from maintenance. It selects parsed sources by review status (reviewed-only, or including `unreviewed` and `auto_flagged`), chunks each active extraction with `chunking.build_profile`, tokenizes with the Kiwi `Analyzer`, and freezes per-document title and institution terms (`metadata_term_snapshot`). It writes an immutable directory under `indexes/<version>`: chunks.jsonl, tokens.jsonl, requirements.jsonl, scope-terms.json and manifest.json, written to a temp directory and then renamed. `_record_index` replaces the `indexes`, `chunks` and `requirements` rows in one transaction. The version is a hash of the config. `KeywordIndex.load` is what `Resources.index()` caches. The `active_index` pointer moves only when no `active_run` exists (cli.py `cmd_build_keyword`).
