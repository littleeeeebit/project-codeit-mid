`build_keyword_index` chunks every parsed source allowed by the review policy with `chunking.build_profile`. It tokenizes with the Kiwi `Analyzer` and freezes the title and institution terms (`metadata_term_snapshot`). Files are written into a temporary directory that is renamed into `indexes/<version>`, where the version hashes the configuration. `_record_index` writes the `indexes`, `chunks` and `requirements` rows in one transaction and moves `active_index` only when `activate` is set. `KeywordIndex.load` verifies the manifest hash and every file hash, checks that token rows align with chunk rows, rebuilds `BM25Okapi`, loads the elements of each extraction and maps each source to the extraction this index holds (`source_extraction`).
