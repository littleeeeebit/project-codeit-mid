`build_keyword_index` selects parsed sources whose `review_status` is in the allowed set (`auto_verified`, `sample_checked`, `reviewed`, plus `unreviewed`/`auto_flagged` with `--include-unreviewed`). It chunks each active extraction through `chunking.build_profile`, tokenizes with the Kiwi `Analyzer`, and freezes each document's title/institution terms (`metadata_term_snapshot` → `scope-terms.json`). The version is the first 16 hex characters of sha256 over the config: chunker, analyzer, IDF policy, review scope, extractions, metadata-terms hash. Files are written to a temp dir and renamed into `.runtime/indexes/<version>`. `_record_index` writes `indexes`, `chunks` and `requirements` rows in one transaction and sets `active_index` only when `activate=True`. `KeywordIndex.load` verifies the manifest hash and every file hash, then rebuilds BM25 from the persisted tokens.
