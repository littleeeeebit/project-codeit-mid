`_execute` (service.py:1068) opens one Langfuse run per request and calls `_execute_traced`. That function dispatches to `_metadata_answer` or `_inventory_answer` (free, built from CSV or resolved metadata and from the index's requirements inventory) or to `_paid_answer`. `_paid_answer` checks availability, resolves a frozen verifier run if one is given, checkpoints, and loads the conversation (`_conversation`: up to 6 earlier turns of the same member and scope, plus up to 8 cited evidence units carried from the previous answer). If there is history, it rewrites the follow-up through `_rewrite`. It then retrieves and prices (`prepare_answer`, or `_prepare_compare` with one single-document retrieval per side), checkpoints again, calls `_metered_chat` with `on_delta` streaming into `res.partials`, and validates with `generation.validate_answer`. `_finish` stores the result and trace. Any `_Stop` becomes cancelled or interrupted, `ServiceError` becomes `clarification_required`/failed, and any other exception becomes `technical_error`/failed, so no request is left running.
