There are two kinds of single-instance daemon thread that borrow the owner's gateway.

- Drafting. `start_drafting` re-runs `plan_drafting` and refuses unless `max_micro_usd <= consented_max` and the plan fits both the `gold_eval` envelope and the cap. It writes `<data>/drafts/<run_id>/request.json`, then runs `drafting._generate(..., guard=lambda conn: 'interrupted' if res._closed else None)`. That loop reserves each call (`stage='gold_drafting'`, `purpose='gold_eval'`, `member_id='api-gpt-6-luna'`), marks it dispatching, and settles or marks it unknown. A failure writes `error.txt`, or `interrupted.txt` when the service is closing. `drafting_runs` derives each run's status from those files (`receipt.json`, `candidates.jsonl`, `invalid.json`).
- Answer evaluation. `start_answer_evaluation` accepts only `answer-finalists` estimates (sealed runs are CLI-only), rechecks the estimate, and runs `answers.run_answers` in a thread. A failure is written to `last-error.txt`.
