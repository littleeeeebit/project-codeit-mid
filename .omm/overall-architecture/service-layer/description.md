`src/rfp_assistant/service.py` holds every public operation the screens and CLI call, plus the process-wide resource owner and the bounded request executor. Each public function starts with `_authorize(res, principal, ...capabilities)`. The UI visitor holds every capability, while in-process callers may pass narrower principals. Paid answer requests are persisted in `requests` under an idempotency key before any work and executed by `RequestRunner` workers that receive only request IDs. Drafting, answer evaluation and judge runs are separate background threads registered in `Resources._jobs`, so `close()` joins them.
