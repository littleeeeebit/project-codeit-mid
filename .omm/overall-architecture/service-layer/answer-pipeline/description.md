`_execute` dispatches by mode: `metadata` -> `_metadata_answer`, `inventory` -> `_inventory_answer` (both free and deterministic, from CSV facts and the index's `requirements.jsonl`), otherwise `_paid_answer`. It maps `_Stop` to cancelled or interrupted, `ServiceError` to `clarification_required`/failed, and any other exception to `technical_error`/failed. Every exit calls `_finish`, which rolls up the request's attempts from the ledger and writes `status`, `trace_json` and `result_json`. A request already marked interrupted or cancelled keeps that status. `compare` mode uses `_prepare_compare`: one scoped retrieval per document at half the unit and token budget, then a second pass that may widen a side cut by `token_budget`/`unit_limit` using what the other side left. Evidence is renumbered `E1..En` and the global ceiling is checked defensively. `generation.validate_answer(required_doc_ids=...)` rejects an answer that drops a side. See request-lifecycle/paid-stages for the paid sequence.
