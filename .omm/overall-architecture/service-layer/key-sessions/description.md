Members enter their own OpenAI key on 설정. `service.set_api_key` validates its format, calls `generation.check_api_key` (a free metadata read that also returns the provider project used as billing scope) and `_selectable` (the model must be allowed and priced). It then creates a fresh `secrets.token_urlsafe(32)` session and stores a per-session OpenAI client in `OpenAITransport._sessions`. The API sets that session ID as an HttpOnly, SameSite=strict cookie. The key exists only in process memory, never in a row, log or trace; the audit event records who set it and the model. `OpenAITransport._client` picks the session client from `KEY_SESSION`, falls back to the server-environment key, or raises a pre-execution `ProviderError(NO_API_KEY)` so nothing is charged. A key change keeps calls already in flight on the old client (`_retired`).
