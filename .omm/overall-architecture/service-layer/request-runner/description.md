`RequestRunner(res)` wraps `ThreadPoolExecutor(max_workers=request_workers)` (README: 6) and `BoundedSemaphore(request_admission)` (README: 12). `submit_answer` calls `try_admit()` (non-blocking) inside `_create`'s `before_insert` callback, so only a new idempotency key consumes a slot and a full queue is refused before anything is persisted or paid. `submit(request_id)` schedules `_run`, which calls `run_queued` and always releases the slot. `shutdown(wait)` stops accepting, waits, cancels unstarted futures, and marks queued requests `interrupted`. Running requests are marked `interrupted` only when some futures are still pending; their dispatching attempts settle if the provider call returns.
