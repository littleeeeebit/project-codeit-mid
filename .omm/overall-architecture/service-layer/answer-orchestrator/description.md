Free modes (`metadata`, `inventory`) run inline in `submit_answer`; paid modes (`single`, `compare`, `corpus`) are queued. `_validate_request` checks the mode, question length (1..`question_max_characters` for paid modes), scope cardinality per mode (corpus: none; compare: exactly two; others: one or two), the idempotency key, and any frozen verifier run. `_create` inserts `requests` under (`member_id`, `idempotency_key`), returning the prior row for the same `input_hash` and refusing a reused key with different input. `_execute` opens a Langfuse root trace seeded by `request_id`. `_paid_answer` steps through: an ingestion-unavailable short circuit -> `_checkpoint` -> retrieval (`prepare_answer`, `_prepare_compare` (one scoped retrieval per side at single-document limits) or the corpus scope) -> `insufficient_evidence` if nothing was packed -> `_checkpoint` -> `budget.reserve` (stage `generation`, purpose `interactive`, with a ceiling for frozen runs) -> `budget.mark_dispatching` with `_dispatch_guard` -> `transport.chat` -> `budget.settle` or `mark_unknown` -> `generation.validate_answer` -> `done()`. `done()` calls `_finish`, which writes status, `trace_json` and `result_json`, derives `billing_state` from all of the request's attempts (unknown > pending > reconciled > settled > released), and keeps an already cancelled or interrupted status.
