`POST /api/verify/traces` -> `run_trace` -> `verifier_trace` performs a free, retrieval-only run. It builds an immutable `verifier_config` (serving snapshot plus clamped limit overrides, hashed into `config_id = vc-...`), retrieves with `allow_paid=False` (dense uses only cached query vectors), prices the exact prompt via `_priced`, and inserts a `verifier_runs` row with the full trace. `POST /api/verify/traces/{run_id}/generate` -> `generate_from_run` submits a paid request with idempotency key `vgen-<run_id>`, so repeated presses return the same request. On execution, `_frozen_run_for` re-verifies question, scope, mode and as-of date. `resolve_verifier_config` recomputes the config ID and refuses if the index, serving run, prompt or model changed. `_frozen_prep` reprices the stored evidence without retrieving again, and `budget.reserve(ceiling_micro_usd=frozen estimate)` refuses with `above_consented_maximum` if rates rose. `compare_verifier_runs` diffs config, top-5 ranking and packed evidence keys.
