`verifier_trace` (reached through `run_trace`, `POST /api/verify/traces`) runs retrieval only, with an optional mode override and narrowing limits. The configuration is frozen by `verifier_config` into a content-hashed `config_id` (`vc-…`). The run stores the exact prompt token count, the paid estimate and the query-embedding miss estimate in the `verifier_runs` table as `vr-…`. It is free: a dense mode uses only cached query vectors, and a miss falls back to kiwi_bm25 with the reason in the trace. `generate_from_run` submits `AnswerRequest(idempotency_key='vgen-<run_id>', config_id, verifier_run_id)`, so pressing generate repeatedly yields one request. `_frozen_run_for` refuses a request whose question, scope, mode or as-of date differs from the run. `resolve_verifier_config` refuses one whose recomputed config ID changed (index, serving run, prompt or model). `run_generation_block` explains why generating is blocked. `compare_verifier_runs` diffs configuration, top-5 and packed evidence. `record_run_correction` appends a quoted, element-checked correction that never edits datasets or runs.
