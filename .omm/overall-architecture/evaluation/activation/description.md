`activate_decision(settings, run_id, decision, actor)` validates the decision with `decision_errors` and `run_errors`. It requires `decided_by`, a current-policy complete run, a pinned embedding policy and a valid finalist. In one immediate transaction it writes `app_settings.active_run` (`serving_config`), sets `active_index` to the run's index and appends an `activations` row holding the previous configuration. `activate-run` from the CLI and `/api/verify/experiments/activate` (`service.activate_experiment`) share this path. The serving process picks the change up on the next `active_serving` read, and `Resources.index()` reloads when the version differs.
