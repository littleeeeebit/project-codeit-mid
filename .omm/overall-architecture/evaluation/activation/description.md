activate_decision runs decision_errors and run_errors (index and matrix verified, current policy, finalist on the same population). Then, in one transaction, it sets app_settings active_run (serving_config) and active_index, and appends a row to activations that includes the previous config. Two callers use it: the CLI command activate-run, and POST /api/verify/experiments/activate through service.activate_experiment, which records the actor as verify:<member>.
