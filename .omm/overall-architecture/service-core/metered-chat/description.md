`_metered_chat` runs one paid chat call in this order. `budget.reserve` reserves the maximum cost at the ledger's rate, under the shared cap, the `interactive` envelope and an optional consented ceiling. `res.paid_refusal()` checks for a key and releases the reservation if there is none. `budget.mark_dispatching` runs with `_dispatch_guard`, so the cancel and interrupt check happens in the same transaction. `_call_and_settle` calls `transport.chat` inside a Langfuse generation span. A pre-execution `ProviderError` releases the attempt. Any other error, or a response without usage, calls `mark_unknown`. A successful call settles, and a settlement exception is also kept `unknown`. Refusals are returned through the caller's `fail(...)` as `budget_blocked`, `clarification_required` or `technical_error`. It never retries.
