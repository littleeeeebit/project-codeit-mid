`_metered_chat` is the only way a request reaches a chat model. Steps: `budget.reserve` (maximum cost) → `res.paid_refusal()` (no key: release) → `budget.mark_dispatching(attempt, _dispatch_guard)`, where the request's stop check runs in the same transaction → `_call_and_settle`. That runs `transport.chat` inside a Langfuse generation step, then `budget.settle` on usage. A pre-execution `ProviderError` leads to `release(confirmed_pre_execution=True)`. Other errors, a missing usage block or a failed settlement lead to `mark_unknown`. It never retries. Refusals map to the outcomes `budget_blocked`, `clarification_required` (above the consented maximum) or `technical_error`.
