`_metered_chat` is the only path from a request to a chat call. It calls `budget.reserve`, which returns `budget_blocked` for `paid_disabled`, `cap_exhausted`, `envelope_exhausted` and similar, and `clarification_required` for `above_consented_maximum`. It then calls `res.paid_refusal()`, which releases the reservation as `provider_unavailable` when the member has no key. `budget.mark_dispatching` runs with `_dispatch_guard`, so the stop check and the dispatching marker share one transaction. `_call_and_settle` calls `transport.chat`. A `ProviderError` with `pre_execution` releases the reservation (confirmed); any other failure marks it `unknown`. Missing usage marks it `unknown`. Otherwise it calls `budget.settle`, and a settlement exception marks the attempt `unknown` with `settlement_failed`. It never retries.
