`metadata_answers.route` is new on this branch. For every non-frozen corpus question, a paid `metadata_query` call translates the question into a structured query, which `metadata_query.validate_query` checks. If the model says this is not a metadata question, or validation fails, the router returns None and the passage path continues, with the reason traced. Otherwise it does four things. It classifies unclassified institutions in batches of 60 into `institution_types` (`ON CONFLICT DO NOTHING`, so the first type is kept). It runs `mq.run_query` deterministically over CSV and resolved metadata. It separates matches from 확인 필요 review rows (missing or zero amount, conflict, missing date, unclassified). And unless the query is `count_only`, it describes each match from its 3 best overview passages (BM25 on a fixed overview query), in batches of 12 that are priced against `budget.headroom` first. The result is `answered` with a `listing`. Over-allowance, invalid or stopped batches leave rows undescribed and add limitations instead of failing.
