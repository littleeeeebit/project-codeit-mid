`ask` → `submit_answer` (or `answer` for synchronous CLI and evaluation callers) → `_validate_request` + `_conversation` + `_create`. Free modes `metadata`/`inventory` execute inline. Paid modes `single`/`compare`/`corpus` are queued. `_execute` opens a Langfuse root `answer-question` seeded by request ID, then `_execute_traced` dispatches to `_metadata_answer`, `_inventory_answer` or `_paid_answer`. `_paid_answer` checks document availability, resolves a frozen verifier run (`_frozen_run_for`), calls `_checkpoint`, optionally `_rewrite`s a follow-up (stage `query_rewrite`), `_prepare_paid`s (per-side retrieval for compare, `all_documents` for corpus), returns `insufficient_evidence` when nothing was packed, `_generate`s (stage `generation`, streamed into `res.partials`) and `_validated`s. Every exit goes through `done` → `_finish`, which writes status, trace and result, and the billing state derived from the ledger. `_Stop` maps to cancelled/interrupted. `ServiceError` maps to `clarification_required`/failed. Any other exception maps to `technical_error`/failed, so no request is left running.
