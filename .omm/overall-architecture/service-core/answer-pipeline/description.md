The entry points are `ask` → `submit_answer`. Free modes (`metadata`, `inventory`) execute inline. Paid modes (`single`, `compare`, `corpus`) are persisted by `_create` under (member_id, idempotency_key) with status `queued`; a repeated key with a different input hash is refused, and the same key returns the existing request. The worker runs `run_queued`: it claims queued→running exactly once, rebuilds the Principal from the `request_json` snapshot and calls `_execute`, which opens one Langfuse trace seeded by request_id. `_paid_answer` then works through the request: it resolves the scope (refusing documents that are not ingested), handles a follow-up through a `_rewrite` paid call, runs `_prepare_paid` (retrieval plus `_priced` token counting and estimate), and returns `insufficient_evidence` when retrieval finds no evidence. Otherwise it calls `_generate` (streaming into `res.partials`) and `_validated` (`generation.validate_answer` against the allowed evidence IDs, stored quotes and document IDs). `_finish` writes status, trace and result and drops the partial. `_checkpoint` runs before every paid stage and raises `_Stop` for cancelled or interrupted requests.
