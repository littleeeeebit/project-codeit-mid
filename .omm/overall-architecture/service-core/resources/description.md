Constructed as `Resources(settings, recover=True)` through `get_resources` / `app_resources`. `_initialize` calls `require_imported_database`, `init_schema` and `budget.ensure_budget_row`, then `_own()`. `_own` either borrows this process's live `GatewayOwner` or takes `pg_try_advisory_lock`. When it takes the lock it runs `recover_requests` (queued and running requests become interrupted) and `budget.recover` (dispatching attempts become unknown, reserved ones are released). Nothing is replayed. `serving()` returns `active_serving(settings)` from the `app_settings` keys `active_run` and `active_index`. If the activated run was measured under another corpus route, uses an unknown embedding model, or is an HR run from an older evaluation policy, `serving()` returns a fallback configuration instead. `index()` and `dense()` load lazily per version under `_index_lock`. A dense set that fails verification is remembered in `_dense_failed`, and retrieval falls back to K1. `close()` rejects new work, waits `shutdown_wait_seconds` for the runner and jobs, recovers if any job is still alive, closes the transport and tracing, then releases the lock.
