`Resources.__init__` enters `database_lifecycle`, which creates the pool. `_initialize` then calls `postgres.require_imported_database`, `init_schema` and `budget.ensure_budget_row`. With `recover=True` or a transport, it claims gateway ownership through `_own` → `postgres.gateway_lock`, or borrows the owner another `Resources` in the same process already holds. A fresh claim runs `recover_requests` and `budget.recover`. The transport is a `FakeTransport` when `provider == 'fake'`. Otherwise it is an `OpenAITransport` when `OPENAI_API_KEY` is set, or it is created lazily the first time a member enters a key on 설정. `index()`, `dense()` and `reranker()` load the artifacts named by `active_serving()`, which reads the `app_settings` keys `active_run` and `active_index`. They reload when the activated version changes. A dense set that fails verification is cached as failed and reported through `stage_errors`. `close()` stops admission, waits up to `shutdown_wait_seconds` for the runner and jobs, recovers anything still running, then closes the transport and tracing and releases the lock. It is registered with both `threading._register_atexit` and `atexit` so that SIGINT from systemd closes it while workers are still alive.
