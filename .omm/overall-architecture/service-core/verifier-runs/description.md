`verifier_trace` runs retrieval only, for free: a dense mode uses only cached query vectors and shows the price of a miss. It runs under an optional narrowing configuration (`verifier_config`, with limits clamped by `_narrow_limits`) and stores the full trace, token count and estimate in `verifier_runs` as `vr-…`. `generate_from_run` later submits an answer whose `verifier_run_id` makes `_frozen_run_for` reuse exactly that evidence. If the prompt or the rates now exceed the estimate the person saw, `_above_consented` or the reservation's `ceiling_micro_usd` refuses before dispatch.
