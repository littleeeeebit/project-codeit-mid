`verifier_trace` (`POST /api/verify/traces`) is a free, retrieval-only run. Dense modes use only cached query vectors and show the cost of a miss instead of paying for it. The run is frozen into `verifier_runs` with a versioned `verifier_config` (serving snapshot plus clamped limit overrides, giving a `config_id`), the exact token count and the paid estimate. `generate_from_run` submits a paid request with `idempotency_key = vgen-<run_id>`, so repeated presses create one request. `_frozen_run_for` checks the question, scope, mode and as-of date, and `resolve_verifier_config` recomputes the config ID: if serving, index, prompt or model changed, the request is refused. `_frozen_prep` reprices the frozen evidence without retrieving again, and the reservation uses that estimate as `ceiling_micro_usd`. Corrections (`record_run_correction`) and exports (`redact`) also live here.
