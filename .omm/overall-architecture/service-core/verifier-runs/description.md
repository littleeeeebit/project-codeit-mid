`verifier_trace` (POST /api/verify/traces) runs a retrieval-only pass with `allow_paid=False` and `price_query_embedding=False`, under a content-addressed `verifier_config` (`vc-` + hash of the serving snapshot, mode, narrowed limits, prompt version and model). It stores the result in the `verifier_runs` table with the exact prompt token count and the paid estimate. `generate_from_run` submits a paid request with idempotency key `vgen-<run_id>`. `_frozen_run_for` and `resolve_verifier_config` then refuse it if the question, scope, as-of date or recomputed config id has changed. `_frozen_prep` re-prices the frozen evidence instead of retrieving again, and `_metered_chat` gets `ceiling=frozen estimate`, so the ledger refuses `above_consented_maximum`.
