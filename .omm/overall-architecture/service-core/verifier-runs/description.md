`verifier_trace` (via `run_trace`, `POST /api/verify/traces`) runs retrieval only, with a cached query vector at most (`allow_paid=False`). It prices the prompt (`_priced`) and inserts a `verifier_runs` row with the config snapshot, trace, exact token count and estimate. `generate_from_run` submits an `AnswerRequest` with `idempotency_key = vgen-<run_id>` and `verifier_run_id`, so repeated clicks map to one request. In `_paid_answer`, `_frozen_run_for` checks that the question, scope, mode and as_of match and that the config still resolves. `_frozen_prep` then re-prices the frozen evidence without retrieving again. Generation is refused if the estimate grew beyond the frozen one, and the frozen estimate becomes the reservation `ceiling`.
