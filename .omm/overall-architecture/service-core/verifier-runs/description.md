`verifier_trace` is a free, retrieval-only run. It uses only cached query vectors and reports the cost of a cache miss instead of paying it. It is frozen into the `verifier_runs` table under `vr-<hex>` with the config snapshot (`verifier_config`), exact prompt token count, estimate, stage errors and document states. `generate_from_run` submits an `AnswerRequest` with idempotency key `vgen-<run_id>` and `verifier_run_id`, so repeated clicks map to one request. In `_paid_answer`, `_frozen_run_for` makes such a request use `_frozen_prep`: the run's exact evidence with no new retrieval, and the run's estimate as the reservation ceiling. If serving or prompts changed in a way that raises the estimate, generation is refused with `clarification_required`.
