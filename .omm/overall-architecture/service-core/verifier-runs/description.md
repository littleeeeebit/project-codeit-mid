`run_trace` calls `verifier_trace`. It builds an immutable `verifier_config` (serving snapshot plus clamped `_narrow_limits`, hashed into `vc-...`) and retrieves free of charge: dense modes use only cached query vectors and price the miss instead of paying for it. It records the trace and the paid estimate, and inserts a `verifier_runs` row `vr-...`. `generate_from_run_id` submits an `AnswerRequest` with idempotency key `vgen-<run_id>`, so pressing the button again returns the same request. `_paid_answer` then reuses the frozen evidence (`_frozen_prep`) without new retrieval or query embedding. It refuses when the new estimate exceeds the frozen one, and `budget.reserve(ceiling_micro_usd=...)` refuses with `above_consented_maximum`. `record_run_correction` stores a correction proposal against one packed evidence unit, and nothing is auto-applied.
