`service.ask` mints `generation_id = uuid4()`, uses it as the idempotency key, and calls `submit_answer`. That runs `_validate_request` first: mode, question length, scope count per mode, no duplicate document, key length, and a frozen verifier run check. It then runs `_conversation`, which refuses a broken or foreign conversation before anything is queued. Free modes (`metadata`, `inventory`) are created as running and executed inline on the HTTP thread. Paid modes call `_create` with `before_insert=admit`. Inside the same transaction, `runner.try_admit()` takes an admission slot, and a full queue is refused with 'no paid call'. The row is inserted as `queued` with `request_json` (the input snapshot), `input_hash`, a `config_hash` and `trace_json.config`, and `runner.submit(request_id)` follows. A repeated key with the same input returns the existing request; a different input under the same key is refused. The returned `target` is `target_key(scope, question, mode, as_of, previous)`.
