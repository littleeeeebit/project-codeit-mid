verifier_trace runs retrieval only, with an immutable verifier_config (serving snapshot plus clamped limit overrides, via _narrow_limits). It prices the prompt without paying for a query embedding and inserts a verifier_runs row (run_id 'vr-…'). generate_from_run submits a paid request with idempotency key 'vgen-<run_id>' and verifier_run_id. _frozen_run_for then requires the same question, scope, mode and as-of date and a still-valid config. _frozen_prep reuses the frozen evidence and does no new retrieval. budget.reserve gets ceiling_micro_usd = the frozen estimate, so a rate or prompt change refuses with above_consented_maximum before dispatch.
