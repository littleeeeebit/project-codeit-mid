`_execute` opens one Langfuse trace per request, seeded with the request ID, and calls `_execute_traced`. That dispatches by mode. `metadata` and `inventory` are free and complete inline from CSV metadata or the index's requirement rows. `single`, `compare` and `corpus` go to `_paid_answer`. Every exit path goes through `done()` → `_finish`, which derives the billing state from the request's ledger attempts (precedence unknown > pending > reconciled > settled > released) and writes `status`, `trace_json` and `result_json`. Exceptions are mapped: `_Stop` becomes cancelled or interrupted, `ServiceError` becomes `clarification_required` with request status failed, and anything else becomes `technical_error` with request status failed. The full path is in `request-lifecycle`.
