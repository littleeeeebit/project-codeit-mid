Paid batch work started from the 검증/데이터셋 screens runs on daemon threads that share this process's transport and gateway lock. The threads are `start_drafting` (`drafting._generate`, `gold_eval` envelope, never above the consented maximum), `start_answer_evaluation`, `start_judges` (`judges.run`) and `start_maintenance` (`maintenance.run`). `_EVAL_LOCK`/`_DRAFT_LOCK` allow one of each kind at a time. Each thread is appended to `res._jobs` under `_runner_lock` so `close()` joins it, and each receives `closing=lambda: res._closed` or a guard that refuses dispatch once shutdown begins. Results are written as files under `.runtime` (for example `drafts/<run>/output/receipt.json`, `maintenance/state.json`), not as request rows.
