`start_drafting` (gpt-6-luna drafting through `drafting._generate`, charged to `gold_eval` and capped at the consented maximum), `start_answer_evaluation` (`answers.run_answers`, development only, never sealed), `start_judges` (`judges.run`) and `start_maintenance` (`maintenance.run`) each publish their run first, then start one daemon thread under a copied context. `_start_job`, or the inline equivalent, registers the thread in `res._jobs` under `_runner_lock`, so `close()` joins it. `_EVAL_LOCK` allows only one evaluation or judge run at a time, and maintenance and drafting each allow one at a time. Failures are written to `last-error.txt`, `error.txt` or `interrupted.txt` in the run directory, and finished rows are kept, so a rerun resumes.
