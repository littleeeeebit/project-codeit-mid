These verifier actions run on daemon threads appended to `Resources._jobs` so `close()` can join them: `start_answer_evaluation` (answers.run_answers), `start_judges` (judges.run), `start_drafting` (drafting._generate, never above the consented maximum) and `start_maintenance` (maintenance.run). `_EVAL_LOCK` and the `_refuse_closed_or_busy` check allow at most one evaluation or judge run at a time, one drafting run and one maintenance sequence. Each run is published to disk before the start call returns. Failures are written to `last-error.txt`, `error.txt` or `interrupted.txt` in the run directory, and settled calls stay settled.
