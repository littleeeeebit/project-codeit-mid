Daemon threads started by service functions and recorded both in module-level registries (`_EVAL_JOBS`, `_JUDGE_JOBS`, `_DRAFT_JOBS`, `_MAINTENANCE_JOB`) and in `res._jobs`. `close()` and `open_paid_work` see them through `res._jobs`. `start_answer_evaluation` runs `answers.run_answers` with `PinnedResources`: the run's recorded serving configuration, the `gold_eval` envelope, and the borrowed transport. `start_judges` runs `judges.run`, `start_drafting` runs `drafting._generate` within the consented maximum, and `start_maintenance` runs `maintenance.run`. Only one answer evaluation or judge part runs at a time (`_EVAL_LOCK`), along with one drafting run and one maintenance run. Each start checks `res._closed`, `paid_refusal()` and the update fence under `_runner_lock`. Each run is written to disk before the start returns, so the overview lists it at once. A job's exception goes to `last-error.txt`/`error.txt`, and finished rows stay. Rerunning resumes, using idempotent keys `<run>:<finalist>:<question>:<n>` in answers.py.
