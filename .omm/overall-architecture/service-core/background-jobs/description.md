start_answer_evaluation and start_judges each take _EVAL_LOCK. They refuse when the service is closing or another evaluation or judge thread is alive, publish the run synchronously (answers.begin_answers / judges.begin, so the overview lists it immediately) and start one daemon thread registered in res._jobs through _start_job. answers.run_answers drives service.answer through PinnedResources, which pin a finalist's retrieval config, row by row. It stops on the first budget block or new unknown billing and resumes on rerun. Thread failures are written to last-error.txt in the run directory.
