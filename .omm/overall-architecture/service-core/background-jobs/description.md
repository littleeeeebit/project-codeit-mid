Daemon threads registered in module globals: `_DRAFT_JOBS`, `_EVAL_JOBS`, `_JUDGE_JOBS` and `_MAINTENANCE_JOB`. Each is appended to `res._jobs` under `res._runner_lock` so that `close()` joins it. `start_drafting` re-plans and checks the consented maximum, writes `request.json` under the drafts directory, and runs `drafting._generate` with `res.transport` and a guard that returns 'interrupted' once `res._closed`. Its ledger calls use purpose `gold_eval`. `start_answer_evaluation` (answers.begin_answers/run_answers) and `start_judges` (judges.begin/run) share `_EVAL_LOCK`, and `_refuse_closed_or_busy` allows only one of them at a time. `start_maintenance` runs `maintenance.run`. Failures are written to `last-error.txt`, `error.txt` or `interrupted.txt` in each run directory. Run state is read back from files plus thread liveness.
