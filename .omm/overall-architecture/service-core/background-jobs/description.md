Paid or long jobs started from the UI run as daemon threads in the server process, registered in `res._jobs` so `close()` joins them. `start_answer_evaluation` (`answers.run_answers`) and `start_judges` (`judges.run`) share `_EVAL_LOCK` and `_refuse_closed_or_busy`, so only one of the two runs at a time. `start_maintenance` allows one `_MAINTENANCE_JOB`. `start_drafting` allows one drafting job under `_DRAFT_LOCK`. Each job is published before the start call returns (`begin_answers`, `judges.begin`, `maintenance.start_state` + `_write`, `drafts/<run>/request.json`), so the next poll lists it. Running state is derived from thread liveness plus files on disk; a failure is written to `last-error.txt` or `error.txt`.
