Each long paid or heavy job runs in a daemon thread started under `res._runner_lock` and appended to `res._jobs`, so that `close()` joins it. `start_drafting` (`drafting._generate`, charged to `gold_eval`, capped at the consented maximum) allows one drafting run at a time. `start_answer_evaluation` (`answers.run_answers`) and `start_judges` (`judges.run`) share `_EVAL_LOCK`, so only one of them runs at a time. `start_maintenance` (`storage/maintenance.run`) allows one sequence per process. Each job publishes its run, as files or rows, before the start call returns. It records failures to `last-error.txt`, `error.txt` or `interrupted.txt` and resumes on rerun. Maintenance runs backup → restore_check → ingest → fidelity → keyword → embedding → regression → report. It stops at the first failed step or at a paid embedding estimate (`needs_approval`) and never activates anything.
