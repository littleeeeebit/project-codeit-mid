Paid and long-running verifier jobs run as daemon threads in a copied context, registered in `res._jobs` so `close()` joins them. `start_answer_evaluation` calls `answers.run_answers` with `res`, which goes through the same answer path. `start_judges` calls `judges.run`. `start_drafting` calls `drafting._generate` with `res.transport`, a guard that returns `interrupted` once `res._closed`, and `res.tracing`. `start_maintenance` calls `maintenance.run`. Only one evaluation or judge run (`_EVAL_LOCK`), one drafting run (`_DRAFT_LOCK`) and one maintenance run may be live at a time. A failure writes `last-error.txt`, `error.txt` or `interrupted.txt` into the run directory, and rerunning resumes.
