`ask` creates a UUID that serves as both the idempotency key and the generation id, then calls `submit_answer`. That function runs `_authorize` (consultant or verifier), `_validate_request` and `_conversation`, which checks the previous turn. Free modes (`metadata`, `inventory`) are created as `running` and executed inline on the HTTP thread. Paid modes (`single`, `compare`, `corpus`) call `_create(..., 'queued', before_insert=admit)`, where `admit` takes a runner slot through `try_admit`. That is refused under the update fence or when the queue is full, with the message '요청이 많아…' and no paid call. If the same key arrives with a different `input_hash`, the request is refused. If it arrives with the same hash, the existing request id is returned without taking a slot. If `runner.submit` raises, the slot is released and `_fail_unscheduled` marks the row failed.
