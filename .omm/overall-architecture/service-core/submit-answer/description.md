service.ask makes a fresh generation_id, used as both idempotency key and generation ID. submit_answer then runs _validate_request: mode in single/compare/corpus/metadata/inventory, 1–2 documents (exactly 2 for compare, none for corpus), question length, and frozen verifier run checks. _conversation checks every previous turn: same member, terminal status, identical scope, at most 6 turns; it also collects up to 8 cited evidence units to carry. _create inserts the `requests` row (input_hash, config_hash, scope_json, request_json snapshot) under (member_id, idempotency_key) in one immediate transaction. An existing key with the same input returns the prior request; a different input raises. For paid modes, the before_insert hook takes a runner slot via try_admit; a full queue is refused with no paid call. The row starts as `queued` and the ID goes to runner.submit. A submit failure releases the slot and marks the row failed.
