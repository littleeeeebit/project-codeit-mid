`src/rfp_assistant/service/service.py` holds everything the screens and the CLI call. Public functions authorize a `Principal` through `_authorize`; every signed-in member holds every capability, and CLI or tests may pass narrower principals. They work against one `Resources`. Paid answering is split into admission (`submit_answer`), background execution (`run_queued` → `_execute`) and read-only observation (`request_status`, `answer_progress`). Long verifier and dataset jobs run on daemon threads registered in `Resources._jobs`, so `close()` joins them.
