`service/service.py` holds the behaviours both screens and the CLI call. `Resources` is the process-wide owner of the database lifecycle, gateway ownership, the transport, the loaded indexes and models, the in-memory per-member API keys and the streamed partial answers. Paid answers run on `RequestRunner`, a bounded executor. Drafting, answer evaluation, judge runs and maintenance each run on their own background thread, registered in `Resources._jobs` so `close()` joins them. `service/update.py` raises a fence that stops new paid work while an accepted update may restart the process.
