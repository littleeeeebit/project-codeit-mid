`service/service.py` is the behaviour layer every screen and CLI path calls. It owns the per-process `Resources` (settings, the loaded keyword, dense and reranker indexes, the transport, tracing and the gateway owner), the bounded `RequestRunner`, the answer pipeline, verifier trace runs, budget and settings actions, and the background jobs: drafting, answer evaluation, judges and maintenance. Every public function first calls `_authorize(res, principal, ...)`. Without a login, the UI visitor holds every capability; the CLI and tests may pass narrower principals.
