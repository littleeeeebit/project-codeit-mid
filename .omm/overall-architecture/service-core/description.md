`service/service.py` is the behaviour layer that both the API and the CLI call. `Resources` owns process-wide state. `submit_answer` (API) and `answer` (CLI, synchronous) create and run requests. `_paid_answer` runs the sequence of follow-up rewrite, metadata routing, retrieval and pricing, streamed generation, and validation. `_metered_chat` is the only path from a request to a paid chat call. Background jobs (maintenance, judges, answer evaluation, drafting) are threads registered in `res._jobs`, so `close()` joins them and an update counts them as open work.
