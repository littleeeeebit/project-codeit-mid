`service/service.py` is the behaviour layer that the screens, the CLI and the tests call. Every public function first calls `_authorize(res, principal, …capabilities)`. Every signed-in web member holds every capability (`auth.visitor`), while in-process callers can pass narrower principals. `Resources` is the singleton owner of shared state. Answers run on a bounded executor, and longer paid jobs (drafting, answer evaluation, judges, maintenance) run as tracked daemon threads. An update fence from `service/update.py` blocks new paid work while a server update may restart the process.
