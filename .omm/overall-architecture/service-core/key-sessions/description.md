`set_api_key` validates the key with a free metadata read (`generation.check_api_key`, which also returns its billing project), checks that the model is allowed and has a rate, and creates a new random key session. `Resources.set_api_key` then registers a dedicated OpenAI client for that session and maps the member to it. The key exists only in the transport's memory. The audit row records who set a key and the billing scope, never the key. Requests already running keep their old session and client (`OpenAITransport._retired`). `set_generation_model` changes the model for future requests only. The env `OPENAI_API_KEY` serves a context with no session key, which in practice means the CLI and members' own PCs.
