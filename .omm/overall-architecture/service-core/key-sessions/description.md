`service.set_api_key` validates the key with a free metadata read (`generation.check_api_key`) and creates a fresh `secrets.token_urlsafe(32)` session. `Resources.set_api_key` stores it in `OpenAITransport._sessions` (one SDK client per session) and records who and when in `Resources.key_sources`; it never stores the key. `OpenAITransport._client` picks the client for `KEY_SESSION`, falls back to the server-environment key (personal machines and the CLI; the shared VM has none, so there a browser without its own key gets no client), and otherwise raises `ProviderError(NO_API_KEY, pre_execution=True)`, which releases the reservation. Keys live only in process memory, so a restart requires every member to enter theirs again. A key change always opens a new session, and each HTTP request binds its session, answer model and billing project when it begins, so calls already running finish on the old client, which stays open until `close()`.
