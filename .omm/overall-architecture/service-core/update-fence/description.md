`open_paid_work` reads, in order, live job threads and `runner.admitted` (under `_runner_lock`), then `requests` rows in queued/running, then `budget.snapshot` (unknown, open attempts, pending micro-USD). It reports `open` with a Korean reason. The order is deliberate: work writes its ledger rows before its thread or slot ends, so whatever ended before being counted has already left its open attempts in the ledger. `request_update` sets `watch.accepting = True` under `_runner_lock` (refusing if already fenced), counts open paid work, refuses if any, otherwise writes the marker, clears `accepting`, and appends an `audit_events` row `request_update`. `_refuse_while_updating` is checked by `try_admit`, `_refuse_closed_or_busy`, `_start_job`, `start_drafting` and `start_maintenance`.
