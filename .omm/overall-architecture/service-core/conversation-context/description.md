`_conversation` walks the `previous_request_id` chain, newest first, for up to `CONVERSATION_TURNS = 6` turns. Each earlier request must belong to the same member, be terminal and have the identical `scope_json`; otherwise it raises before the new request is queued. Each turn contributes its `standalone_question` (or its question, or the free-mode label) and `_answer_text(result)`: summary, claims, metadata facts, conflicts, requirement rows in the on-screen order from `inventory_display_order`, and missing fields. The latest answer keeps 6,000 characters and older ones 1,200. Up to `CARRIED_EVIDENCE = 8` evidence units cited by the previous answer are returned for `_with_carried`. A verifier-run request cannot continue a conversation.
