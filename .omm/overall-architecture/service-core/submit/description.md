`submit_answer` validates the request (`_validate_request`: mode, 1–2 docs, compare needs exactly 2, corpus none, question length) and the conversation chain (`_conversation`: same member, terminal turns, same scope). It then persists `requests` in one transaction under `(member_id, idempotency_key)` with `input_hash` and a config snapshot. A repeated key with the same input returns the existing request; a different input is refused. Paid modes take a runner slot in `before_insert` (`try_admit`, which also checks the update fence). A full queue is refused before anything is reserved. `service.ask` uses a fresh UUID as both idempotency key and generation ID. traffic_review relies on that to recognise Ask requests.
