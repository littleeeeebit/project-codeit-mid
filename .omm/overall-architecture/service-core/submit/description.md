`ask()` creates a fresh `generation_id` (also the idempotency key) and calls `submit_answer`. That function runs `_validate_request` (mode/scope rules: compare needs exactly two documents, corpus needs none; length limits; frozen verifier run checks), then `_conversation` (every earlier turn must belong to this member, be finished, and share the same scope, otherwise the request is refused before it is queued), then `_create`. `_create` inserts the `requests` row with the input snapshot, input hash and config hash inside one `tx(immediate=True)`. A repeated key with the same input hash returns the earlier `request_id`. A repeated key with a different input raises. Paid modes take a `RequestRunner` slot inside that transaction (`before_insert=admit`); a full queue is refused with "(유료 호출 없음)". Free modes (`metadata`, `inventory`) run inline.
