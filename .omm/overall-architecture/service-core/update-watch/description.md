`UpdateWatch` records the running commit (`build_head`, via `git rev-parse HEAD`) and polls the public GitHub API every 300 s for `main`'s head and the compare commits. `POST /api/update` → `request_update` raises `accepting` under `_runner_lock` and calls `open_paid_work`. That counts live job threads, admitted slots, queued or running requests and, read last, open ledger attempts. If paid work is open, the update is refused. Otherwise it atomically writes a marker file at `BIDMATE_UPDATE_REQUEST`. A root-owned systemd path unit runs `tools/infra/update.sh`, which fast-forwards to origin/main, rebuilds, restarts, health-checks and rolls back on failure, writing `result.json` into the state directory. `fenced()` is true while the request is being accepted, while the marker exists, or while the result says running. `Resources.update_fence` points at it, and `_refuse_while_updating` checks it at every paid admission.
