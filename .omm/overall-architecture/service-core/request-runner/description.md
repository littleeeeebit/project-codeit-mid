`RequestRunner` is a `ThreadPoolExecutor(max_workers=request_workers)` plus a `BoundedSemaphore(request_admission)`; README gives 6 workers and 12 admitted requests. `try_admit` acquires a slot under `_runner_lock` after `_refuse_while_updating`. Inside `_create`'s transaction it runs only for a new idempotency key, so a duplicate key returns the existing request without taking a slot. `submit` sends only the request ID under a copied context. `_run` calls `run_queued` and always releases the slot. `shutdown` stops accepting, waits, cancels futures not yet started, and marks queued (and, if workers are still running, running) requests interrupted.
