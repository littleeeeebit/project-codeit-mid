`RequestRunner` wraps a `ThreadPoolExecutor(max_workers=request_workers)` and a `BoundedSemaphore(request_admission)`; the README states 6 workers and 12 admitted. `submit_answer` admits through `try_admit()` inside `_create`'s `before_insert` hook, so only a new idempotency key uses a slot. A full queue raises `ServiceError` before anything is persisted or paid. Workers receive only a request_id; `_run` → `run_queued` → `_execute`, and the slot is released in `finally`. `shutdown` stops accepting work, waits, cancels futures, then marks queued requests `interrupted`, and marks running ones `interrupted` too if any future is still pending.
