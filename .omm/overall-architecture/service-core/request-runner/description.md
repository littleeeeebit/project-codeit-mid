A `ThreadPoolExecutor` with `request_workers` threads (6) and a `BoundedSemaphore` of `request_admission` slots (12). `try_admit` acquires a slot under `_runner_lock` after checking the update fence, inside the same transaction callback that inserts the queued row (`_create(before_insert=admit)`), so a duplicate idempotency key never consumes a slot. `submit` runs `run_queued` in a copied context; `_run` always releases the slot. `shutdown` stops accepting, waits, cancels queued futures, and marks queued requests (and running ones when workers are still busy) `interrupted`.
