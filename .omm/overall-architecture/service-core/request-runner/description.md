`RequestRunner` wraps `ThreadPoolExecutor(request_workers)` with a `BoundedSemaphore(request_admission)`. `try_admit` runs under `res._runner_lock` together with the update fence, so an accepted update never races a new request. `submit` passes only the request ID, through `contextvars.copy_context().run`, so the member's bound key session travels with it. `shutdown` stops accepting, waits, cancels unstarted futures, and marks queued requests `interrupted`, and running ones too if they did not finish. Their dispatching attempts stay as they are and become `unknown` at the next startup.
