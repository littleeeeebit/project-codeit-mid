`RequestRunner` wraps a `ThreadPoolExecutor(max_workers=request_workers)` and a `BoundedSemaphore(request_admission)`. The README states 6 workers and 12 admitted requests. `try_admit` runs inside the `_create` transaction, before the queued row is inserted, under `res._runner_lock` together with the update fence check. A full queue raises a `ServiceError` before any row or paid work exists. `submit` hands only the `request_id` to the executor, inside a copied contextvars context. `_run` calls `run_queued` and always frees the slot. `shutdown` stops accepting new work, waits a bounded time, cancels unstarted futures and marks the remaining queued rows interrupted, and the running rows too when workers did not finish.
