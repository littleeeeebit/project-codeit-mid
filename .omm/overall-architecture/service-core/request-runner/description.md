`RequestRunner` is a `ThreadPoolExecutor(max_workers=settings.request_workers)` plus a `BoundedSemaphore(settings.request_admission)`. The README states 6 workers and 12 admitted requests. `submit_answer` calls `try_admit` inside `_create`'s insert transaction (`before_insert`), so a duplicate idempotency key never takes a slot, and a full queue raises `ServiceError` before any row or paid work exists. `submit` runs `run_queued` inside `contextvars.copy_context()`, so the worker sees the HTTP request's key session, model and billing scope. `_run` releases the slot when it finishes. `shutdown(wait)` stops accepting new work, waits for in-flight futures, cancels queued futures, then marks queued rows interrupted, and running rows too if any future is still pending. A worker that was mid-call keeps its attempt `dispatching`, so it can still settle or turn unknown after a restart.
