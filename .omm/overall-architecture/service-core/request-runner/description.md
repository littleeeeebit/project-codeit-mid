`RequestRunner` wraps `ThreadPoolExecutor(max_workers=request_workers)` and the admission semaphore. `submit(request_id)` runs `_run` under a copied context, so the member's key session, model and billing scope travel with the work. `_run` calls `run_queued`, then releases the slot. `shutdown` stops accepting, waits for the bounded deadline and cancels unstarted futures. It sets queued rows to `interrupted` and also running rows when some futures are still pending. Workers only ever receive request IDs.
