`RequestRunner` wraps a `ThreadPoolExecutor(request_workers)` (6 workers) and a `BoundedSemaphore(request_admission)` (12 slots). `submit_answer` calls `_create(..., 'queued', before_insert=admit)`, so a slot is taken only for a new idempotency key, inside the transaction that inserts the row. `try_admit` runs under `res._runner_lock` and first calls `_refuse_while_updating`. `submit` passes `contextvars.copy_context().run`, so the worker inherits the member's key session, model and billing scope. `_run` → `run_queued` claims `queued → running` exactly once (`AND cancel_requested = 0`) and rebuilds the `AnswerRequest` and `Principal` from `request_json`. `shutdown` stops accepting work, waits a bounded time, marks queued rows `interrupted` and, if workers are still pending, running rows too.
