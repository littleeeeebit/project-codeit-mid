`RequestRunner` wraps a `ThreadPoolExecutor(request_workers)` and a `BoundedSemaphore(request_admission)`; the README gives 6 workers and 12 admitted requests. Workers receive only request IDs. `_run` calls `run_queued`, which atomically moves `queued` → `running` only when `cancel_requested = 0`. It then rebuilds `AnswerRequest` and `Principal` from the persisted `request_json` and calls `_execute`. The slot is released in `finally`. `shutdown` stops accepting, waits a bounded time, and marks queued requests `interrupted` (running ones too if futures are still pending).
