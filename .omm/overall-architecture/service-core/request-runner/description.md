`RequestRunner` is a `ThreadPoolExecutor(request_workers)` plus a `BoundedSemaphore(request_admission)`; the README gives 6 workers and 12 admitted requests. `try_admit` runs inside `_create`'s insert transaction, and only for a new idempotency key. `submit` runs `run_queued` in a copied `contextvars` context, so the worker pays with the submitting browser's key session. `shutdown` stops accepting and waits. It then marks `queued` requests `interrupted`, and marks `running` requests `interrupted` if any futures are still pending. Workers receive only request IDs and never touch UI state.
