Two halves. The runner (`evaluation/stage_review.py`, `stage_review_paid.py`, `traffic_review.py`, invoked as `cli stage-review …`) freezes inputs and runs a baseline ref and candidate refs of one stage (retriever, chunking, generation, OCR) in isolated git worktrees. It scores them with one scorer and writes `.runtime/review/runs/<run-id>/` (`run.json`, `inputs/`, `candidates/`, `view.json`). The app (`review/server.py`, standard library only, its own loopback port, built from `review/`) only reads run folders and writes notes, decisions and taxonomy decisions. It never runs a pipeline, loads a model or pays.
