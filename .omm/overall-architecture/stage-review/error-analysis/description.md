`evaluation/error_analysis.py` folds the append-only stores under `<data>/review`: `annotations/<run>.jsonl` (`live_notes`, `reviewed_answers`), `taxonomy/proposals/*.json`, `taxonomy/history.jsonl` (the commit log) and `taxonomy/versions/v<N>.json` (snapshots). `export` writes the unassigned live notes and a `prompt.md` into `taxonomy/exports/<export-id>/`. `propose` validates the agent's `failure-taxonomy-proposal-1` file: only `name`/`definition`/`notes` keys, a Korean one-line name, a one-sentence definition, existing live notes not held by another type, and no duplicate name. `decide` applies accept, rename, merge, split or reject: it writes the version snapshot first, then appends to history, so a failed snapshot commits nothing. `progress`, `run_counts` and `release_summary` count answers with a type over answers a person reviewed. `suggest_export` writes one accepted type's search bundle (definition, approved and rejected spans, every stored generation answer) into `taxonomy/suggest-exports/<id>/`. `suggest` validates the agent's `failure-type-suggestions-1` file: the type must be accepted, each span verbatim in its stored field, with a one-line reason, and not already filed, waiting or rejected. Valid files go to `taxonomy/suggestions/*.json`. `decide_suggestion` approves (it appends an `origin: ai_suggested` note to the run's annotations, then a `suggestion-approve` history record that adds it to the type without a version bump) or rejects with a reason. Approved notes never make an answer reviewed and are counted apart (`ai_answers`). `rereview` lists answers marked fine before a type's `since`.
