For generation and OCR, each candidate first runs in `estimate` mode with no key and records the token bound of every call it may make. `reprice` turns those bounds into an `estimate.json` at the ledger's current rates, for what is left. `approve` records the approver's name in the run and the audit log, and refuses an estimate that has expired (24 h) or no longer fits the envelope. `resume` (via `on_ledger`, which opens the shared ledger's lifecycle only now) calls `require_approved` and `recheck` (inputs, worker, rate card, refs, remaining budget), refuses a ref that moved or a working tree that changed, and only then passes `OPENAI_API_KEY` through `approved_env`. Afterwards `ledger_spend` and `score_generation`/`score_ocr` write `view.json`. A run stays `stopped` until every approved candidate completes. `rescore` re-scores stored outputs with no calls.
