`<data>/review/runs/<run-id>/` holds `run.json` (schema `review-run-1`, full commits, input and worker hashes, scorer fingerprint, host and packages per candidate), `inputs/`, `candidates/<id>.json` (raw output, estimates, paid configs), `view.json` (what the app shows), and `docs/` or `images/` for chunking and OCR. `review/server.py check_run` requires `run.json` and `view.json` to name the same run, stage and candidates. Export zips the folder plus its `annotations.jsonl`. Import extracts to a temp directory, validates and stores the notes under the write lock, then renames the folder into place, so a failed import leaves no run behind.
