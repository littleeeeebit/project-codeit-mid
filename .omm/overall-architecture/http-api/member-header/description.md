`_member` reads the `X-Member` header (default `owner`), percent-decodes it and returns `service.visitor` → `auth.visitor`. That is a `Principal(name[:40], all CAPABILITIES)`. Service functions still call `_authorize`/`require_any`, so in-process callers (CLI, tests) can pass narrower principals. Ownership checks compare `member_id`: a request can be read only by its member or a verifier, and cancelled only by its member.
