`/api/auth/login` redirects to the hub's authorize URL with a state cookie scoped to /api/auth/. It first redirects to the registered host when the request came through another address, such as an SSH tunnel. `/api/auth/callback` compares state with `secrets.compare_digest`, then calls `Login.sign_in(code)` (src/rfp_assistant/service/auth.py). That call exchanges the code with JupyterHub from the server and checks `BIDMATE_ALLOWED_USERS`. The route then sets the HttpOnly SameSite=Lax `bidmate_session` cookie on path /api/ only and deletes the legacy cookie on path /. `/api/auth/logout` and `/api/auth/me` complete the set. Sessions live in server memory, so a restart signs everyone out.
