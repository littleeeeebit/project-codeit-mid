`_Session.__call__` handles every `/api/` request in this order. (1) A state-changing request whose `Origin` is neither the request's own Host nor, in local mode, one of `DEV_ORIGINS` gets 403. (2) A sign-in configuration problem (`login.problem`) gets 503. (3) The three sign-in paths pass through. (4) `login.member(cookie)` must resolve, or the request gets 401. (5) An `X-BidMate-Account` header naming another member gets 409 with `X-BidMate-Account-Changed`, and a state-changing call without the header gets 428. (6) The member is stored in `scope.state`, and `service.bind_request(res, member)` sets three contextvars: `generation.KEY_SESSION`, `generation.REQUEST_MODEL` and `budget.BILLING_SCOPE`. The reset runs after the response. Any thread the request starts copies that context (`contextvars.copy_context().run`), so a request keeps the member's key, model and billing project for its whole life.
