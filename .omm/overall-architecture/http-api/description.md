`src/rfp_assistant/api.py` is a thin HTTP layer. Its module docstring says it imports nothing from the package except `service`, and `tests/test_api.py` checks this. Middleware `_KeySession` reads the `bidmate_key_session` cookie on every HTTP request and calls `service.bind_request`, which sets three context variables for that request and every thread it starts (via `contextvars.copy_context`): `generation.KEY_SESSION`, `generation.REQUEST_MODEL` and `budget.BILLING_SCOPE`. The `_member` dependency turns `X-Member` into `service.visitor(name)`. `ServiceError` maps to 400; the other shell errors (for example `auth.AuthError`) map to 403. Route groups: `_routes` (info, budget, settings, documents, ask, requests, stream, cancel, abandon, export, evidence, originals); `_verify_routes` (`/api/verify/*` and `/api/gold/recent|reject-categories|{id}/second-review`); `_dataset_routes` (`/api/drafting/*`, `/api/gold/pending|{id}|{id}/decide`). `_dataset_routes` is registered after the verify routes so that `/api/gold/{candidate_id}` does not shadow them. The SSE route `/api/requests/{id}/stream` first calls `answer_progress` once to refuse before opening. It then loops: call `answer_progress`, sleep 0.15 s, emit `data:` when the partial changes, and emit `event: done` when the request is finished. Response models (`Answer`, `RequestView`, `TraceRun` and others) are read-only pydantic mirrors (`from_attributes`) of service dataclasses.
