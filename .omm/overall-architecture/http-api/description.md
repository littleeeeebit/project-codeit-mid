`create_app(resources=None)` has a lifespan that calls `service.app_resources()`, which calls `get_resources(load_settings())`, which builds `Resources(settings, recover=True)`; the lifespan closes it on shutdown. The `_KeySession` ASGI middleware reads the `bidmate_key_session` cookie and calls `service.bind_request`. That sets the contextvars `generation.KEY_SESSION`, `generation.REQUEST_MODEL` and `budget.BILLING_SCOPE` for the HTTP request. Background work started by the request copies this context, so a request keeps the key, model and billing project it began with. `_member` turns `X-Member` into `auth.visitor(name)`, a Principal with every capability. `ServiceError` maps to 400 and `AuthError` maps to 403 with the Korean message. Routes are registered in three groups. `_routes` covers info, budget, settings, documents, ask, requests, stream, cancel, abandon, export, evidence and originals. `_verify_routes` covers `/api/verify/*` and the gold second review. `_dataset_routes` covers `/api/drafting/*`, `/api/gold/pending`, `/api/gold/{candidate_id}` and decide. It is registered last so that `/api/gold/{candidate_id}` cannot shadow `/api/gold/recent`. The static `web/out` mount is added after every route. The Pydantic models (`Answer`, `RequestView`, `TraceRun`, …) are read-only mirrors of service dataclasses built with `from_attributes`.
