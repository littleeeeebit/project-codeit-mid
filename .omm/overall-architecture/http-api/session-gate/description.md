ASGI middleware _Session applied to /api/* only. In order: (1) a non-GET with a foreign Origin gets 403; (2) login.problem (missing sign-in environment) gets 503; (3) the sign-in routes pass through; (4) no session cookie gets 401; (5) an X-BidMate-Account header naming another member gets 409 with X-BidMate-Account-Changed; (6) a state-changing call without the header gets 428. It then stores the member in scope.state and calls service.bind_request. That sets the KEY_SESSION, REQUEST_MODEL and BILLING_SCOPE contextvars for the member's key, chosen model and billing project, and resets them when the request ends.
