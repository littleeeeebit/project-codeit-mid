`maintenance.run` executes `STEPS` in order: backup, restore_check, ingest, fidelity, keyword, embedding, regression and report. Each step reuses unchanged inputs. A paid embedding stops at its estimate, and a failed step stops the sequence and records its name and reason. The regression step (`compare.regression`) compares K1 and the serving configuration on the served index against the rebuilt one, and names any questions the reparse lost (`lost_to_reparse`), which makes the run `unverified`. When started from the UI, it runs on the server's gateway thread with `closing=lambda: res._closed`.
