`maintenance.run` (CLI `maintain`, or the route `/api/verify/maintenance/start` in a background thread) runs `STEPS` in order: backup, restore_check (a scratch database), ingest, fidelity (changed only), keyword, embedding, regression and report. Each step writes state after it finishes. `NeedsApproval` (a paid embedding) stops the run as `needs_approval`, and any exception stops it as `failed` at that step. `closing()` makes a stopping service end the run. The result is `unverified` when a re-parse dropped questions from the regression table. The report records serving before and after and the paid attempts since start.
