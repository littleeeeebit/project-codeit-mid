`maintenance.run` executes `STEPS` in order: backup, restore_check (into a scratch database), ingest, fidelity, keyword, embedding, regression, report. Each step reuses unchanged work. A paid embedding raises `NeedsApproval` and stops at its estimate. A failed step stops the sequence with its name and reason. Regression compares K1 and the serving configuration on the served and rebuilt index. A run whose reparse lost questions ends `unverified`. State is written to the data directory so `maintenance_status` can report an interrupted run. It never activates anything.
