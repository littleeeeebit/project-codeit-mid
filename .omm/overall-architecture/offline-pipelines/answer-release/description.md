`plan-run`/`run-answers`, or the evaluation screen, generate development answers for at most two finalists. Each answer goes through `service.answer` on a `PinnedResources`, which serves the finalist's recorded configuration and charges `gold_eval`. A rerun resumes without re-sending finished rows or rows with unknown billing. `export-review` and `import-review` carry blind human verdicts; there is no paid judge in scoring. `freeze-release` records the release candidate, and the sealed set then runs once. `release-report` returns blocked (a hard check failed), limited (unverified, unmeasured, missed or pilot-only) or ready. `backup` and `restore-check` dump the database and verify the dump in an isolated database with paid admission off.
