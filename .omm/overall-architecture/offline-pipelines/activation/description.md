`evaluation.activate_decision` is reached from the CLI `activate-run` or from POST /api/verify/experiments/activate. It first runs `decision_errors` and `run_errors`: the run must be on the current EVAL_VERSION with an unchanged population, the index manifest and dense set must verify, a non-OpenAI embedding must match its pinned policy, and a reranker run must record its concurrency bound. It then writes `active_run`, `active_index` and an `activations` history row (keeping the previous configuration) in one transaction. Nothing else changes serving.
