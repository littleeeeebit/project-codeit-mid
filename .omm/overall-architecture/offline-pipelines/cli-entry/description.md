`cli.main` parses about 60 subcommands and dispatches through `COMMANDS`. `restore-check` uses `RFP_RESTORE_DATABASE_DSN`. `check` and `load-check` use isolated temporary databases on `RFP_POSTGRES_TEST_DSN` with `provider=fake`. `stage-review run chunking --inputs-from` runs without a database. Every other command enters `database_lifecycle`, requires a validated import (except `init`), runs idempotent schema statements (except the read-only `budget-report`) and calls the handler. Paid commands build a full `service.Resources` (taking the gateway lock), while budget administration uses `Resources(dispatch=False)` beside the running server. Known errors print `error: ...` and return 1.
