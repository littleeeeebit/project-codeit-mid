`request_update` sets `watch.accepting = True` under `res._runner_lock`, refusing if the watch is already fenced. It then calls `open_paid_work(res)`, which counts live `_jobs` threads and `RequestRunner.admitted` slots, then `requests` rows in queued/running, then the ledger `snapshot`. A nonzero count, an open attempt, pending micro-USD or unknown billing refuses the request with a Korean reason. If nothing is open it writes the marker (`write_request`: .part file then `os.replace`), clears `accepting` in `finally`, and records the audit row `request_update`.
