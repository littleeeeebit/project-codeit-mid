`Resources.update_fence` is set to `UpdateWatch.fenced` by the API lifespan, and `_refuse_while_updating` raises `UPDATING`. It is checked under `_runner_lock` in `RequestRunner.try_admit`, `_refuse_closed_or_busy`, `_start_job`, `start_drafting` and `start_maintenance`. Free modes and reads are not fenced. After a restart, the new process stays fenced while `result.json` still says `running`.
