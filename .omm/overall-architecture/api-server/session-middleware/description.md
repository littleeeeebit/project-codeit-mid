The `_Session` ASGI middleware wraps every `/api/` path. In order it: refuses a state-changing call whose Origin is not the host (403); returns `login.problem` as 503 when sign-in is misconfigured; lets only `/api/auth/login|callback|logout` through without a session; resolves the `bidmate_session` cookie (path `/api/`) to a member (401 if none); refuses a mismatched `X-BidMate-Account` (409 with `X-BidMate-Account-Changed`) or a missing header on a write (428). It then calls `service.bind_request`, which sets the contextvars `generation.KEY_SESSION`, `generation.REQUEST_MODEL` and `budget.BILLING_SCOPE` from that member's current key session. Work started by the request inherits them: `RequestRunner.submit` copies the context. So a running answer keeps the key, model and billing project it began with.
