`maintenance.run` executes `STEPS` in order: backup → restore_check → ingest → fidelity (changed HWP only) → keyword (`build_keyword_index(..., activate=False)` with the served index's profile and review scope) → embedding (`compare.ensure_dense`; free locally, else `NeedsApproval` with an estimate) → regression (`compare.regression`) → report. Each step is reused when its inputs did not change. The first `StepFailed`, exception or `NeedsApproval` stops the sequence. `closing()` stops it when the service stops. State is written to `state.json` after every step, with final reports under `reports/<run_id>.json|md`. The final status is complete, unverified (a reparse orphaned pinned gold evidence), failed, needs_approval or interrupted (a running state with no live thread, per `service.maintenance_status`). `serving.unchanged` asserts it activated nothing.
