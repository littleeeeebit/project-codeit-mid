storage/postgres.py wraps psycopg. `Connection` with `bind_sql` translates the `?` placeholders used throughout the code. `lifecycle` / `open_db` manage a bounded pool. `require_server` pins PostgreSQL 18.6 (and pgvector 0.8.6 on pooled connections). `require_imported_database` / `validation_ready` refuse a database without a validated migration import or with an open recovery fence. `init_schema` applies migrations and seeds `database_control` with `paid_admission=false`. storage/store.py re-exports these and adds `app_settings` (the active index and run), atomic file writes and JSONL helpers. postgres_backup.py and maintenance.py implement verified custom-format dumps, `restore-check` into an isolated database (which leaves paid admission off), and the maintenance sequence. The main tables touched by the traced paths are `documents`, `sources`, `extractions`, `extraction_inputs`, `elements`, `indexes`, `chunks`, `requirements`, `requests`, `attempts`, `adjustments`, `budget_settings`, `database_control`, `app_settings` and the audit table (via `_audit`).
