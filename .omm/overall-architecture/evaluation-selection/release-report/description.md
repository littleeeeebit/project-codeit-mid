`freeze-release` records the release candidate: activated run, code, metric, prompt, model, rate and settings hashes, and frozen dev and test manifests. The sealed set then runs once; any later run is labelled a post-test regression. `release-report` decides `ready` only if every hard check passes and every quality target (`release.TARGETS`, `LATENCY_TARGETS_MS`, also served to the screen) is met on sealed gold. Otherwise it reports `limited` or `blocked`. `backup` and `restore-check` provide the backup evidence.
