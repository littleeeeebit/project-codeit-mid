The Next.js screens: `web/src/app/page.tsx` (질문하기, ask), `verify/page.tsx` (검증), `dataset/page.tsx` (데이터셋 만들기) and `settings/page.tsx` (설정). They are exported to web/out and served by the API on the same port. `web/src/lib/api.ts` builds an openapi-fetch client typed from `api-schema.d.ts`, which `tools/openapi.py` regenerates. It has two middlewares. On a 401 outside /api/auth/ it calls `window.location.replace('/api/auth/login')`. On every request it sets `X-BidMate-Account` to the account the page loaded as, and it reloads the page on a 409 that carries `X-BidMate-Account-Changed`. The ask flow (`components/ask/ask-page.tsx`): `postAsk` POSTs /api/ask with scope pairs (doc_id, source_hash), question, mode and previous_request_id, and keeps the returned `Owned {request_id, generation_id, target}`. `usePoll` GETs /api/requests/{id}?generation_id&target every 1000 ms until the status is terminal. `useAnswerStream` (`lib/use-answer-stream.ts`) reads the SSE stream through fetch, so it can abort and send the account header. `data: null` withdraws the provisional text, and `event: done` triggers an immediate status reload. A validated answer renders only when the response says `attachable`. Leaving the screen sends POST /abandon with keepalive, and the cancel button POSTs /cancel. The verify page calls /api/verify/* (traces, compare, evaluation plan/start, judges, maintenance, experiments/activate, fidelity, corrections, history). The dataset page calls /api/drafting/* and /api/gold/*.
