`OpenAITransport.chat` first calls `owner_check`, then selects the client: the one for `KEY_SESSION` (a member's key from 설정), else the server-environment key, else a pre-execution `NO_API_KEY` error. It calls Chat Completions with a strict `response_format`, `reasoning_effort` and `max_completion_tokens`. When given `on_delta` it streams with `include_usage`, and `_drain` passes the accumulated content to the callback. SDK 4xx errors (auth, permission, bad request, not found, rate limit, unprocessable) count as `pre_execution=True`. Timeouts, 5xx errors and failures mid-stream do not. `set_key` replaces a session's client while calls already in flight finish on the old one. `FakeTransport` stands in when the provider is `fake`.
