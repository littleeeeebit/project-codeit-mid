`service._metered_chat` handles chat calls (answer `generation`, follow-up `query_rewrite`); `dense.metered_embed` handles query and corpus embeddings, and drafting has its own copy of the same sequence. `_metered_chat` maps outcomes to request results: `above_consented_maximum` → clarification_required; not admitted → `budget_blocked`; no key or provider → release, then technical_error; `DispatchRefused` with a STOPS reason → `_Stop` (cancelled or interrupted), any other refusal → budget_blocked; a 4xx `ProviderError` (pre_execution) → release; a timeout, 5xx or any other exception → `mark_unknown`; a missing usage block → unknown; a settlement failure → unknown with technical_error.
