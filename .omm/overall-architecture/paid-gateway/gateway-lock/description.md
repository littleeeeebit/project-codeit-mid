`postgres.GatewayOwner` holds `pg_try_advisory_lock(GATEWAY_LOCK)` on one dedicated connection for the life of the owner. `borrow_owner` lets another `Resources` in the same process share it, counting users so the last release closes the session. `owner_guard(conn)` verifies inside ledger transactions that this backend still holds the lock in `pg_locks`. `check` runs before provider calls. Paid CLI commands (`_paid_resources`, `drafting.generate`, the stage-review worker) take the same lock, so they refuse while the server runs.
