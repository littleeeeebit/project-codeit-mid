Runs require_owner(db), then one immediate transaction that takes the application_mutex row lock. Refusal reasons, checked in order: owner_guard (recovery/validation or ownership lost), paid_disabled, postgresql_maintenance (database_control.paid_admission false), frozen, unknown_rate, unknown_purpose, above_consented_maximum (a caller's ceiling), cap_exhausted (cap minus spent minus pending), envelope_exhausted. On admission it inserts an attempts row in state `reserved` with price_json (model, rates, rate_version and, if bound, billing_scope). Database lock or connection errors fail closed as ledger_unavailable.
