`mark_dispatching(db, attempt_id, guard)` runs the owning request's `_stop_reason` (cancelled, or interrupted because the request is no longer running or the service is closing), `owner_guard`, the paid-admission flag and a check for any `unknown` attempt, all in one transaction. On refusal it releases the reservation (`stopped_before_dispatch:<reason>`) and raises `DispatchRefused`. Otherwise it moves the attempt to `dispatching` with `dispatched_at`. This one transaction is what keeps a cancelled or shut-down request from slipping a call past the check.
