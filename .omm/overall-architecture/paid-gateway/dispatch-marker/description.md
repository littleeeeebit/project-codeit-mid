`mark_dispatching(db, attempt_id, guard)` runs the owning request's guard in the same transaction (`_dispatch_guard` → `_stop_reason`: cancelled, or interrupted when the request is no longer running or the service is closing). It also checks `owner_guard`, `paid_admission`, and that no attempt anywhere is `unknown`. On a refusal it moves the attempt reserved → released with `stopped_before_dispatch:<reason>` and raises `DispatchRefused`, which `_paid_answer` turns into `_Stop`. Otherwise reserved → dispatching with `dispatched_at`. Because the check and the marker share one transaction, a shutdown cannot slip in between them.
