`mark_dispatching(attempt_id, guard)` evaluates the request's `_stop_reason` (cancelled, interrupted, or closing resources), `owner_guard`, `paid_admission`, and whether any `unknown` attempt exists anywhere, all in the same transaction as the `reserved → dispatching` update. Any refusal moves the attempt to `released` with `stopped_before_dispatch:<reason>` and raises `DispatchRefused`. `_metered_chat` turns cancelled/interrupted into `_Stop`, which becomes request status `cancelled`/`interrupted`, and anything else into `budget_blocked`.
