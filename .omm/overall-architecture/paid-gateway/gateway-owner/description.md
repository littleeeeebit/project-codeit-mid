`postgres.GatewayOwner` holds `pg_try_advisory_lock(GATEWAY_LOCK)` on one dedicated autocommit connection. Several `Resources` in one process share it through `borrow_owner` and a user count, and the last `release` closes the connection. `check()` (the transport's `owner_check`) and `owner_guard(conn)` (inside admission and dispatch transactions) verify the lock is still granted and that recovery or validation is not blocked. A lost lock is never reconnected. `ocr.RemoteReader.__enter__` takes the same lock and runs the same recovery, so an OCR run and the serving app cannot both own one ledger.
