`budget.reserve` first calls `require_owner`, then opens one `tx(immediate=True)`, which locks the `application_mutex` row. In that transaction it runs `owner_guard`, then checks `paid_enabled`, `database_control.paid_admission` (`postgresql_maintenance`), `frozen_reason`, a known rate, a known purpose envelope, the consented `ceiling_micro_usd` (`above_consented_maximum`), the cap (`cap - spent - pending`, `cap_exhausted`) and the envelope (`envelope_exhausted`). Only if all pass does it insert the attempt as `reserved`, with `price_json` freezing rates, rate version and billing scope. Database operational errors return `ledger_unavailable` (fail closed). A refusal becomes a `budget_blocked` request outcome without a provider call.
