PUT /api/settings/api-key → `service.set_api_key` validates the key format, calls `generation.check_api_key` (a free `models.retrieve` that reads the `openai-project` header as the billing scope, falling back to a sha256 key digest), checks the rate with `_selectable`, creates a new random session through `Resources.set_api_key`, and writes an audit row without the key. `bind_request` then puts the member's current session, model and billing scope into the `KEY_SESSION`, `REQUEST_MODEL` and `budget.BILLING_SCOPE` contextvars for each HTTP request. Worker threads inherit them through `copy_context`, so a later key or model change never affects a request that was already submitted.
