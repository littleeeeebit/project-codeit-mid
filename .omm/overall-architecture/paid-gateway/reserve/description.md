`budget.reserve(db, request_id, member_id, stage, purpose, model, input_tokens, max_output_tokens, count_method, ceiling_micro_usd)` first runs `require_owner(db)`. Under the application mutex (`tx(immediate=True)` → `SELECT … FROM application_mutex FOR UPDATE`) it refuses with a reason in this order: ownership (`owner_guard`), `paid_disabled`, `postgresql_maintenance` (`database_control.paid_admission`), `frozen`, `unknown_rate`, `unknown_purpose`, `above_consented_maximum` (a frozen verifier run's estimate as ceiling), `cap_exhausted` (cap − settled − adjustments − open reservations), `envelope_exhausted`. Otherwise it inserts an `attempts` row with state `reserved`, reserving `max_cost`: every input token priced at the cache-write rate plus full output. It also bumps `ledger_revision`. A database error or lock timeout returns `ledger_unavailable` (fail closed).
