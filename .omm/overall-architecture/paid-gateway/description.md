Every paid provider call by the server goes through one path: reserve the maximum cost, mark it dispatching under the request's stop check, call the provider, then settle, release or keep it unknown. That path is `service._metered_chat` for chat (query rewrite and answer generation) and `dense.metered_embed` for embeddings. Nothing retries automatically: the SDK runs with `max_retries=0`, and a failed stage ends the request. The ledger lives in PostgreSQL (`attempts`, `adjustments`, `budget_settings`). Owner budget administration (settle, reconcile, adjust, paid on/off, audit) is CLI only.
