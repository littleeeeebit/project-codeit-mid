Every paid call (answer generation, follow-up rewrite, query embedding, drafting, evaluation, judges, maintenance embedding) uses the same ledger protocol in `budget.py` against the `attempts` table, behind the gateway owner. `service._metered_chat` is the interactive implementation: reserve → `paid_refusal` check → `mark_dispatching(guard)` → `transport.chat` → settle / release / mark_unknown. It never retries; SDK clients are built with `max_retries=0`.
