Every provider call, whether answer generation, follow-up rewrite, query or corpus embedding, drafting or a judge, goes through the same ledger state machine in `gateway/budget.py` and the single SDK call site in `gateway/generation.py`. Admission is checked before dispatch, all inside PostgreSQL transactions serialized by the `application_mutex` row lock: ownership, paid switch, `database_control.paid_admission`, frozen state, rate, envelope, cap and consented ceiling. The SDK runs with `max_retries=0` and a finite timeout. Nothing retries automatically.
