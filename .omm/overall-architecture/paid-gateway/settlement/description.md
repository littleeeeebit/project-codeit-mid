`settle` is idempotent per attempt. It prices actual usage (prompt, cached, completion and cache-write tokens) with the reserved price snapshot and stores the response id. When the cost exceeds the reservation it freezes the ledger (`budget_settings.frozen_reason`), which stops new paid work until inspected. For an attempt that was already reconciled, it books a negative `late-settlement` adjustment. `release` applies to reserved attempts, and to dispatching ones only when the failure is confirmed pre-execution. `mark_unknown` applies to dispatching attempts only. The operator paths `settle_from_evidence`, `reconcile` and `add_external_adjustment` are exposed in `service.py`.
