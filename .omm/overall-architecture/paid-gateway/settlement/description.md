`_call_and_settle`. On a usage-bearing response it calls `budget.settle`, which computes the cost from the frozen rates; a duplicate settle is a no-op and an overrun freezes the ledger. With no usage it calls `mark_unknown`. On a pre-execution `ProviderError` it releases with `confirmed_pre_execution`. On any other exception, or a failed settle, it marks the attempt unknown (`settlement_failed:` for the latter). The request then fails with a `technical_error` stating that cost stays pending.
