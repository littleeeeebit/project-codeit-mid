`service._call_and_settle` and `dense.metered_embed` handle the outcome. A pre-execution error calls `release(..., confirmed_pre_execution=True)`. A post-execution error, an unexpected exception or a missing `usage` calls `mark_unknown`. Returned usage calls `settle` exactly once: it computes the cost from uncached, cached and cache-write tokens and stores the usage and response ID. A cost above the reservation sets `budget_settings.frozen_reason`, which stops new paid work until inspected. Settling an attempt that was already `reconciled` adds a negative `late-settlement:` adjustment. A failed settlement write keeps the attempt unknown and fails the request. The owner's `reconcile` imports a closed interval's provider total per billing scope and turns the covered unknown attempts into `reconciled`.
