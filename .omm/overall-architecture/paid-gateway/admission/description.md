`budget.reserve` runs in one immediate transaction. It refuses with a reason and no attempt row in these cases: lost gateway ownership; `paid_enabled=0` (`paid_disabled`); `database_control.paid_admission=0` (`postgresql_maintenance`); a set `frozen_reason`; an unknown model rate; an unknown purpose envelope; a maximum above a consented ceiling (`above_consented_maximum`); cap minus settled minus pending below the maximum (`cap_exhausted`); or the envelope exhausted. Otherwise it inserts an `attempts` row in state `reserved`. The maximum is `max_cost` (every input token priced at the cache-write rate plus the full output allowance), and the row stores the price, rate version and billing scope. Database operational errors fail closed as `ledger_unavailable`. Purposes include `interactive` (serving), `gold_eval` (drafting, answer runs, stage-review generation), `judge_eval`, `embedding` and `ocr`.
