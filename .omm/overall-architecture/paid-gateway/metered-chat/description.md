`_metered_chat(stage, step, messages, response_format, input_tokens, max_output_tokens, record, fail, ceiling, on_delta)` works as follows. A refused admission returns `fail('budget_blocked')`; above a consented verifier ceiling it returns `clarification_required`. With no transport it releases with `provider_unavailable`. `DispatchRefused` with a stop reason raises `_Stop`; any other refusal is `budget_blocked`. A `ProviderError` with `pre_execution` is released as confirmed pre-execution; otherwise the attempt is marked unknown. Any other exception is marked unknown. A response without usage is marked unknown. Otherwise it settles; a settlement failure is marked unknown. It records admission, usage and settlement into the request trace.
