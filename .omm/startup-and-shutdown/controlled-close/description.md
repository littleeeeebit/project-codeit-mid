`Resources.close` marks the resources closed: `runner()` refuses with a Korean message and checkpoints see 'interrupted'. It calls `RequestRunner.shutdown(shutdown_wait_seconds)` and joins background jobs until the shared deadline. If any job is still alive, it runs `recover_requests` and `budget.recover`. It then closes the transport and flushes tracing, and finally releases the gateway owner and the database lifecycle. A worker still inside a provider call keeps its attempt `dispatching`. It still settles if the call returns before the process exits; otherwise the next start marks it unknown.
