`/api/verify/maintenance/start` → `start_maintenance` → `maintenance.run` executes `STEPS` in order: backup, restore_check (into a scratch database), ingest, fidelity (changed only), keyword, embedding (stops at a paid estimate with `NeedsApproval`), regression (`compare.regression` on the served index versus the rebuilt one), and report. It stops on the first failure or when the service is closing. It records `provider_calls` since start and whether serving stayed unchanged. CLI `maintain --actor` runs the same sequence.
