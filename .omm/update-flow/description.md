This is the self-update from the page, the focus of this branch. Trigger: any signed-in member presses 업데이트 in `UpdateBanner`, which appears only when GitHub main is a strict fast-forward ahead of the running commit. `POST /api/update` → `service.request_update`, which raises the fence, refuses while paid work is open, writes the marker and audits. The root `bidmate-update.path` unit sees `/srv/bidmate/update-request/requested` and starts the oneshot `bidmate-update.service` (`TimeoutStartSec=30min`). That runs the root-owned copy `/usr/local/sbin/bidmate-update` of `tools/infra/update.sh`, which fast-forwards the checkout as the service user, reinstalls and rebuilds when needed, restarts `bidmate`, health-checks and rolls back on failure. The new process starts with fresh memory, so sessions and entered API keys are gone. The waiting banner reloads once the server answers again.
