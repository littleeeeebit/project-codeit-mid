# Complete Korean HWP and PDF preprocessing

Proposed route: treat the originals as the content source, the CSV as metadata plus a potentially incomplete preview, and preserve an immutable original alongside structured extracted elements. Decode correctly, check extraction coverage, and retain table relationships as three separate requirements. None substitutes for another.

## HWP and HWPX

[pyhwp](https://pyhwp.readthedocs.io/en/latest/intro.html) is a HWP v5 parser with experimental conversion tools. Its documented Python compatibility is old; the audit used an isolated temporary installation on the current Python 3.13 environment. Trial success does not establish general compatibility. Record the exact package versions and keep the converter environment separate from the app. Its published license is AGPLv3; assess that dependency before distribution.

Use [structured XML export](https://pyhwp.readthedocs.io/en/latest/hwp5proc.html), rather than `hwp5txt`, as the primary trial:

```text
hwp5proc xml --output parsed.xml source.hwp
```

Walk the document's paragraph and table hierarchy in source order. Keep text inside `TableCell`, row/column indices and spans, section identity, and element ordinals. Count content inside nested cells exactly once. A flat walk of every `Text` element is useful for the audit's volume checks, but does not constitute the final table-preserving ingestion algorithm.

The documented `PrvText` stream uses UTF-16LE and is a preview, not the full body. Inspect it to diagnose supplied text, never use it as the complete index. HWP binary records, compression, and controls belong to the parser; applying `decode('utf-8')` to the original HWP file is incorrect.

Quarantine password-protected, unsupported, malformed, or incomplete documents. A zero exit code is insufficient: require nonempty well-formed XML and expected content. The audit encountered malformed XML from this converter. Do not repair it with `errors='ignore'` or silently drop invalid characters; locate the failure or route the document through a verified alternative.

The all-file trial left two recovery cases: 한국농어촌공사 AFSIS Cambodia, whose exported XML was malformed, and 대전대학교 MILE, whose style record raised a UTF-16 decoding error. The other 94 HWP outputs parsed, but still require table/content review. Neither failure is evidence that the original Korean document cannot be read by its native application; both are parsed by the loader fallback below and checked by `fidelity run`.

Fallback: when pyhwp fails, `ingest` parses the original HWP with `HwpHwpxLoader` (`storage/hwp_loader.py`, from `langchain-hwp-hwpx-loader`). Its elements carry location format `hwp_loader` and a parser fingerprint of their own (adapter version plus loader and parser package versions), and the source keeps the warning `pyhwp_failed` with pyhwp's reason. The loader gives the whole body as one element with table text inline, then notes, memos and links. Its separate table elements are not requested: on AFSIS and MILE every table cell was already in the body, so they only doubled the text. Table cells, spans, pages and coordinates are not available. If the loader fails too, the source is quarantined with the loader's reason code (`hwp_loader_failed`, `hwp_loader_result_invalid` or `hwp_empty_output`). The Hancom print is never parsed as a source of text, whether or not one exists. It stays the fidelity witness, so `fidelity run` judges a loader parse against the print like any other HWP, comparing the body line by line so each line is aligned on its own pages (finding cell `l<line>`). A failure pyhwp raises after conversion (no `BodyText`, a malformed attribute, an unreadable equation record) is a reason code like the converter's, so it falls back too: `auto_verified` or `auto_flagged`, and an `auto_flagged` source stays active and is reviewed at the reported places. [Hancom's OWPML model](https://github.com/hancom-io/hwpx-owpml-model) is a reference for the XML structure; it is not a drop-in HWP converter. HWPX is a different container and needs its own ZIP/XML route if later supplied. The present corpus contains no HWPX files.

## PDF route

Use [PyMuPDF text blocks and table extraction](https://pymupdf.readthedocs.io/en/latest/recipes-text.html) on every page. Its documentation describes reading-order controls and `Page.find_tables()`. Reading-order sorting alone cannot prove correct table associations, especially across pages or merged cells. Keep page number, bounding boxes, and the original text; verify units and footnotes against the rendered page.

If a page renders text but extraction yields blank text, replacement glyphs, or implausible content, investigate missing character mappings and use the OCR route below. Changing a PDF string's encoding will not repair missing glyph-to-Unicode mappings. Do not replace a good text layer with OCR simply because the document is Korean.

## Text inside images

Decided 2026-09-30: a local OCR model reads every image region; only the regions it fails on go to a paid model. No general VLM runs locally. The corpus is digital, so images are embedded pictures, not scans. Changed 2026-10-09: HWP regions come from the HWP file itself instead of the Hancom print, and the paid model is `gpt-5-mini` instead of Gemini, so OCR is reproducible without a Gemini key.

1. Regions. HWP: the pictures embedded in the file (`BinData`), each image once. pyhwp's walk leaves a `picture` marker, with its `BinData` reference and its share of the page, where a picture control sits: after the paragraph holding it, and for a picture in a table cell after the table. A picture covering less than `IMAGE_MIN_AREA` of the page is not read. Pictures in headers and footers are page chrome and are not read. WMF and EMF are rendered to bitmaps (Pillow, Windows only; a WMF without the placeable header gets one spanning its window extent from 0, since the render follows the metafile's own window records). Transparency goes on white and the long side is at most 2,048 pixels. OLE objects, drawings (shape groups and shapes that are neither a line nor a text box), pictures linked to an outside file and images that cannot be decoded are not read. Each is counted per document as `ocr_unavailable`, by kind (`ole`, `drawing`, `missing`, `format`). A document pyhwp cannot walk is parsed by the loader, which gives no picture positions, so it gets no image text (`ocr coverage` lists it). PDF: raster images on the original's pages (`page.get_image_info()`, at least `IMAGE_MIN_AREA` of the page), each rendered clean at 150 dpi.
2. Local OCR: PaddleOCR-VL 1.6, prompt `OCR:`, greedy, stopped on a loop (12 identical lines, or 48 lines with at most 8 distinct).
3. Fallback test, per region, from signals available without the truth: the loop stop fired; the output ran out of tokens (2,048) before the model ended it; mean token probability below 0.90; or the output is longer than 20 times the ink estimate, or longer than 5 times and over 500 characters. The ink estimate is 0.39 characters per glyph-sized connected component (correlation 0.99 with the true length on text regions).
4. `gpt-5-mini` reads only flagged regions (Chat Completions, image at `detail: high`, reasoning effort `minimal`, at most 4,096 completion tokens), and its text replaces the OCR text for that region. It is paid with `OPENAI_API_KEY` from the local environment, the owner's personal key, through the budget gateway into the shared ledger, from the `ocr` envelope. That envelope starts empty; the owner funds it with `set-envelopes`. The OCR run owns the paid gateway for its whole duration. On taking it, the run first recovers what a dead owner left: a call left dispatching becomes unknown, which blocks dispatch until it is reconciled, and an undispatched reservation is released. Each call is reserved at worst case before dispatch: the prompt counted like any request plus 4,000 image tokens, more than any image can bill. It is settled on the usage the response reports. A call whose outcome or usage is unknown is marked unknown and stays charged at its reservation, and the run stops until it is reconciled. A budget refusal also stops the run. Only one OCR run at a time, local-only included, may write the cache, so one run's checkpoint cannot overwrite another's paid reads. A refusal or an unfinished answer is paid, but it is not a read: the region stays unresolved for the next run. The Gemini reads of 2026-09-30 and `.runtime/ocr/gemini-ledger.jsonl` are kept as history and as the reference of `ocr sample`; no Gemini call is made.
5. Output: element kind `image_text`, with its engine (`paddleocr-vl-1.6` or `gpt-5-mini`) and image digest in its location. Cached by source hash plus OCR configuration; a cached read is reused only for the same image digest, and a finished read of that digest anywhere is preferred over an unfinished one in place. A local read cached before truncation was recorded is read again. HWP: the text takes the place of the picture's marker (rendering `hwp_bindata`, with the `BinData` name, section and walk path, no page). It inherits the marker's section, and no marker is ever stored. A picture placed twice gets its text at both places. PDF: only reads of regions the original still has (same page, box and pixels) are merged; the rest are reported as `ocr_stale` until OCR runs again. The OCR text goes after the element holding the text above the image, or before the one holding the text below. That element must be the only one on the anchor's page holding the anchor (elements keep no box, so repeats there are ambiguous and the other anchor is tried), and a picture with no such element is reported as `ocr_unplaced`. A picture before the first element, or one left unplaced, belongs to no section. On a rotated page, boxes stay in unrotated coordinates and only the render is rotated. Unresolved reads are reported as `ocr_unresolved`. The extraction fingerprint covers the added text, where it was placed and the placement version, so moved OCR text is a new revision. OCR text has no independent witness and is labelled machine-read wherever it is cited.
6. Coverage: `ocr coverage` writes `.runtime/ocr/coverage.json`, per document the embedded images read against the distinct images of its Hancom print in the 2026-09-30 cache (463 across the corpus, PDF originals included), with the `ocr_unavailable` counts of the latest ingest.

Benchmark behind these choices: 80 print regions whose text layer is the truth.

| Model | Korean 3-gram recall | 3-gram precision | CER | s/region |
|---|---|---|---|---|
| PaddleOCR-VL 1.6 | 0.78 | 0.85 | 0.31 | 6.1 |
| GLM-OCR | 0.62 | 0.64 | 0.35 | 8.1 |

The thresholds were first fitted on those text regions (0.95 confidence, 0.8–1.5 times the ink). On the corpus's real images they flagged 365 of 438 distinct images: charts, diagrams, maps, logos and scanned forms behave differently. They were refitted on 50 random real regions, with Gemini's read as the reference and "failed" meaning an order-free character F1 below 0.8 against it. 16 of 50 local reads failed, as runaway repetition, loops, garbled map or diagram labels, or near-empty output. The rule above flags all 16, plus 4 good reads. A shortfall against the ink is not used, because contents pages with dotted leaders read perfectly at 0.2–0.6 of the estimate. Across the corpus it flags 193 of 463 distinct images. The fit rests on 50 samples; confident misreads of single characters are not caught.

`gpt-5-mini` was measured on 2026-10-09 with `ocr sample`. The 50 calibration regions were never recorded, so the sample is a seeded draw (seed 20261009) of 50 from the 200 cached Gemini reads. All 50 finished. Cost was $0.0325, or $0.00065 per image (highest $0.0018). Character F1 against Gemini's read: mean 0.816, median 0.945, 12 below 0.8. PaddleOCR-VL scored a mean of 0.533 on the same regions. The low F1 scores are mostly tiny regions (1 to 7 characters) and low-resolution screenshots. On those screenshots Gemini invented captions and table figures that cannot be read, while `gpt-5-mini` read only the legible text. The report keeps both texts for that reason.

The first run over the embedded pictures read 377 distinct images: 208 passed locally and 169 were flagged. The 169 cost $0.161 on `gpt-5-mini`, more per image than the sample, because embedded pictures are read at up to 2,048 pixels. After the re-ingest, 81 of the 88 gold rows cited superseded extractions. 80 of them can be found again at the same walk path with the quote intact. One (`needle-18`) quoted the old Gemini read of a print region and cannot. So the new index was built inactive and not activated: retrieval evaluation scored only the 7 rows still pinned. Activation waits for the gold rows to be moved onto the new extractions.

[Docling](https://github.com/docling-project/docling) is an alternative for PDF layout and tables. Its documented format support does not establish reliable binary HWP ingestion.

## Korean preservation and output contract

1. Read the supplied CSV using `utf-8-sig`; retain multiline quoted fields with a CSV parser.
2. Write all new text, JSON, and Markdown using UTF-8 without BOM; configure subprocess decoding and terminal output explicitly.
3. Preserve raw extracted text. Apply NFC to a separate searchable representation so decomposed Hangul is searchable without rewriting evidence.
4. Normalize line endings and obvious repeated whitespace inside a cell or paragraph. Keep boundaries, negation, punctuation-bearing IDs, units, and table structure.
5. Save extraction method/version, source hash, completeness state, and source locations. Never invent HWP page numbers from paragraph counts.

For HWP without trustworthy pagination, citations should name section, requirement ID, and table/cell ordinal and offer the original download. Show PDF physical page number separately from a printed page label when they differ.

## Acceptance before indexing

Every one of the 100 files must have an ingestion status. Check start, middle, and end content; detailed requirement IDs beyond the contents page; representative budget, submission, and requirement tables; and source-viewer navigation. Compare extracted amounts and identifiers to the originals, not to generated summaries. U+FFFD count, Hangul count, and character length are diagnostics rather than an automatic pass.

Keep failed documents visible with their reason and suppress unsupported full-document answers. The product must distinguish “not present in the original,” “original not fully ingested,” and “retrieval did not find it.” See [evaluation](evaluation.md) for how those states affect scoring.
