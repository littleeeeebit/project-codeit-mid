# Cleanup-mode refactor scope settled: all L0/L1 work, tests included, ratchet adopted at the end

In cleanup refactoring mode, the user asked for all L0 and L1 work. L0 is mechanical: dead code, unused imports, renames. L1 is restructuring inside one module with no public or behavior change. The user chose everything in scope including tests; long functions, duplicated blocks within a module, and dead code and unused imports as problem kinds; and adopting the ratchet at the end. The assistant then drafted a spec with extra judgment calls the user has not yet confirmed. The cleanup run had not started.

## Decisions

- Scope covers everything in the repository, tests included
- Problem kinds in scope: long functions, duplicated blocks within a module, dead code and unused imports
- Adopt the ratchet (.wiki/ratchet.json) at the end of the cleanup
- Work is limited to L0/L1 (within one module, no change to public names, signatures or behavior); L2 cross-module and L3 contract changes are out of this mode — Cleanup mode only allows L0 and L1; the user asked for all L0 and L1

## Facts

- PR #24 split `src/rfp_assistant` into subpackages, so most remaining debt is inside modules (unverified)
- The debt-scan ranking weighs size by git churn; PR #24 moved the biggest modules, resetting their churn to 1–2, so `service/service.py` (3,027 lines), `evaluation/evaluation.py` (2,496 lines) and `corpus/ingestion.py` (1,317 lines) rank below test files (unverified)
- Cleanup mode by default takes only the top-ranked hotspots from the debt scan, one L1 step and one PR each, in order (unverified)
- Longest single function per file: 235 lines in `cli.py`, 218 in `web/src/components/ask/ask-page.tsx`, 195 in `evaluation/evaluation.py`, 136 in `api.py`, 95 in `corpus/ingestion.py`, 86 in `tools/verify.py` (unverified)
- Lines repeating in blocks of 6+: 41 in `tests/test_gold.py`, 14 in `evaluation/evaluation.py`, 12 in `service/service.py`, 8 each in `api.py` and `tests/test_dense.py`, 6 in `web/src/components/verify/judges.tsx` (unverified)
- The repository has no `.wiki/ratchet.json`, so the growth-limit gate is inactive; `debt.py init` creates the ratchet (unverified)
- `tests/test_api.py` requires every route to go through `rfp_assistant.service.service`, so the service functions `api.py` calls cannot be renamed (unverified)
- `web/openapi.json` records every `/api/*` route and response shape; PR #24 used it as its no-behavior-change check (unverified)

## Preferences

- Wants all L0 and L1 cleanup done ("모든 l0, l1 을 절이하고 싶다"), not just the top-ranked hotspots
- Wants tests included in the cleanup scope

## Open

- Unconfirmed spec rule: every file with a long function or repeated block must be either cleaned up or listed with the reason it can't be done at L0/L1 (cross-module duplicates and signature-changing splits are L2)
