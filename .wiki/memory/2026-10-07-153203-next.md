# 검증 page redesign agreed: regroup menu by verifier question, rename comparisons, show release gates in 평가·릴리스; PR #27 merged

The verification and frontend owner said the 검증 page (http://35.255.64.243:8501/verify/) was hard to read: section roles were unclear and the evaluation criteria were not visible. The assistant traced this to an 11-section menu grouped by pipeline internals and to targets that exist only in docs/rag/evaluation.md. It proposed three fixes, and the user approved them and asked for a fix spec. The assistant gave a one-PR spec. The transcript ends with PR #27 merged (round 3, 0 remaining P2); it does not say what the PR contained.

## Decisions

- Regroup the 검증 left menu by the verifier's question: "내가 처리할 것" (할 일), "기준을 통과했나" (평가·릴리스, 판정 모델), "왜 틀렸나" (검색 추적, 실행 비교), a separate "운영 (소유자)" group for 실험 비교 and 유지보수, and reference records last — Group names don't match their contents. "사람이 볼 차례" holds owner operations such as 실험 비교 and 유지보수, and 실험 비교 changes production serving. (rejected: Redoing the layout as summary tiles with tabs; the grouped left menu had already been chosen)
- Rename the comparison sections by what they compare, e.g. 검색 구성 비교, 추적 비교, 판정 모델 비교, 답변 후보 평가 — "Comparison" meant four different things: pipeline variants, two traces, judges, and answer finalists.
- Rebuild 평가·릴리스 in the 판정 모델 비교 pattern: verdict on top, each metric as value / target / ✓ with its denominator, a one-line Korean definition per metric, run IDs folded away — The screen showed metric columns but never the gates, so nobody could tell whether the release passes. This was named the most important of the three fixes.

## Facts

- The 검증 page has 11 sections in one left menu, grouped as 사람이 볼 차례 (할 일, 실험 비교, 유지보수), 재현 (검색 추적, 실행 비교), 현황 (평가·릴리스, 판정 모델 비교) plus 데이터셋 / 수집 상태 / 수정 기록 / 요청 기록 (unverified)
- Choosing a row in 실험 비교 switches what the app serves. 유지보수 runs backup → ingest → fidelity check → index → embed → regression table from one button (unverified)
- In 검색 추적, re-running retrieval is free and shows five stages; generating an answer is a separate paid step. 평가·릴리스 has a paid "run evaluation" button (unverified)
- 판정 모델 비교 checks whether the Jev judge can replace the gpt-6-luna judge. It was rebuilt on 2026-10-04 to show the verdict first, then each condition as value vs threshold (unverified)
- 평가·릴리스 shows a raw table with columns 필수 주장 정확도, 치명 오류, 인용 정밀도(하한), 미판정 인용, 부정 질문 처리. It has no targets and no ✓/✗, and includes CLI hints (export-review → import-review) (unverified)
