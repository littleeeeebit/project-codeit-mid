# Add local Docker Langfuse tracing to the ask/answer and drafting pipelines (merged as PR #15)

The user wanted to add Langfuse, self-hosted locally in Docker, to check how well answers are grounded. They asked that the agent be given a fixed instruction about installing the Langfuse skill. The assistant laid out the integration points and four open choices, and the user picked the recommended option for each. A spec was written and the result was PR #15, merged (round 5, 0 remaining P2).

## Decisions

- Trace scope: the ask/answer pipeline plus drafting
- Payload: send full text, with secrets masked at the client in a single masking function on the Langfuse client — Masking at the last point before data leaves the process, instead of at each place that sends data (rejected: Masking at each individual send site)
- Grounding scores: push the existing deterministic citation checks (scope, evidence references, quote locations) to Langfuse as scores — Reuses validation the answer path already runs, with no extra paid calls
- Run the stack with compose.langfuse.yaml plus tools/start-langfuse.ps1
- The agent instruction goes into the spec word for word: "Install the Langfuse AI skill from github.com/langfuse/skills and use it to add tracing to this application with Langfuse following best practices." — The user asked for it to be passed as written
- Proof of done is one real /api/ask request visible in the local Langfuse UI. The agent runs it, then stops for the user to inspect the trace before writing its done report — The request is a paid call against the $5 cap

## Facts

- All OpenAI calls (chat and embeddings) go through `OpenAITransport` in src/rfp_assistant/generation.py, which is owned by `service.Resources` (unverified)
- The answer pipeline is service.retrieve → service.answer → service.ask, behind POST /api/ask (unverified)
- The OpenAI transport is created in two places: service.Resources and the drafting runner, which builds its own. The Langfuse client must be created, flushed and closed with those same owners (unverified)
- Langfuse is observability only. The SQLite/PostgreSQL ledger stays the only budget authority, and Langfuse cost figures are informational (unverified)
- Langfuse must fail open: missing keys or a down container must not change answering, the ledger or settlement (unverified)
- The existing verify retrieval traces (/api/verify/traces) stay as they are; Langfuse is added alongside them (unverified)
- Self-hosted Langfuse v3 runs its own Postgres, ClickHouse, Redis and MinIO. It is kept separate from the bidmate-postgresql pgvector container and follows its pattern: bind to 127.0.0.1 only, with secrets in an env file created by a start script (unverified)
- PR #15 merged: 라운드 5, 남은 P2 0
