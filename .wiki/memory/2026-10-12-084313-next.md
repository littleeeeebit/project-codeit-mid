# All-documents Ask mode routes metadata filter/sort questions (amount, institution type) to a validated query structure instead of top-k passage search; PR #45 merged

The user reported that in codeit (over SSH), asking for projects with a budget of 1억원 or more returned only one IP-NAVI project at 60,000,000원 and said no such projects existed. They asked for a full audit and a fix that lists every matching project with a short description. The assistant traced the cause to All-documents (corpus) mode being a top-k passage search, not a filter. The user then widened the scope to general metadata queries: any amount threshold, cheapest or most expensive, and institution type such as universities, with no hardcoding. The spec became one task and one pull request, and the result reports PR #45 merged in round 6 with 0 remaining P2.

## Decisions

- Questions in All-documents mode are translated by the model into a fixed, validated query structure (fields, operators, values, sort, limit). Code validates it and runs it against the metadata, so the model never chooses which projects are listed. — A rule-based phrase parser would need a new pattern for every wording (가장 싼, 제일 비싼, 대학에서 낸, ~가 발주한), which is hardcoding. The user explicitly asked for no hardcoding. (rejected: Rule-based Korean condition parser (chosen first, then replaced))
- The feature is a general metadata query: conditions on amount, institution and dates with any operator and value, combined with AND, plus sorting and limits. It is not a fixed '1억 이상' lookup. — The user expects other questions too: 5000만원 이상, the cheapest project, price lists of university proposals, and university proposals of 1억 or more. (rejected: Hardcoded 1억 threshold feature)
- Each institution is classified by type once (university, local government, public agency, …) and stored as reviewable metadata. — Institution type is a meaning, not a word. A substring match on 대학 gives false hits, such as a university sports association or a 대학생 project run by a non-university. (rejected: Substring match on 대학 in the institution and title fields)
- Each listed project gets a description: an overview passage from its original document plus one generated line per project.
- Unknown amounts go in a separate '확인 필요' section with the reason. This covers 0원, missing and conflicting amounts.
- Audit scope '1번에 langfuse span까지': every filter or aggregate question type gets a test set where each answer must list exactly the right projects, and each routing step is its own Langfuse span. — So a failing request can be checked in the Langfuse trace.
- Acceptance runs locally against codeit's data first, then on codeit after deploy.
- The institution-type classification and the query feature ship together as one task and one PR, under the same spec slug as the earlier spec. — A question like '대학에서 낸 제안서 중 1억 이상' can't be accepted without both.

## Facts

- All-documents mode (`mode: "corpus"`) is a passage search, not a list or filter. It combines BM25 with pgvector, and the answer model receives only the top 10 passages across all documents, so it can never list every match (unverified)
- The design docs already state that budget and institution filters should go to typed SQL filters, because top-k retrieval does not guarantee completeness (unverified)
- Each document has a typed `amount_krw`. The free project search already applies `amount_min`/`amount_max` filters and treats unknown or conflicting amounts as undecided rather than as matches. The Ask path was not connected to it before this fix (unverified)
- CSV metadata: 65 of 100 projects have `사업 금액` ≥ 100,000,000 KRW and 34 are below. Of those 34, 6 are 0 and 1 is 1원 (likely data-entry gaps), and 1 project has no amount. The server applies reviewer corrections and indexes 98 active sources, so its count may differ (unverified)
- A substring search for 대학 in the CSV institution and title fields finds 13 projects, some of them wrong (unverified)
- Spec detail: amounts below 1,000,000원 count as suspicious and go to 확인 필요 with 0원, missing and conflicting amounts. Extreme-value questions such as 가장 싼 must ignore these placeholders (unverified)
- Spec detail: extreme-value questions list every tied project, not just one (unverified)
- Spec detail: institution classification and query translation both use gpt-5-mini on the shared ledger, about 1–2k tokens per question (unverified)
- Spec detail: the write session stops before its done report and waits for the user to run the same question on codeit after deploy (unverified)
- PR #45 merged in round 6 with 0 remaining P2

## Preferences

- No hardcoding for this feature. It must handle arbitrary thresholds above or below, cheapest and most expensive, and institution-type conditions.
- List answers must output the complete list of matching projects, not just one, together with what each project is.
- Audit everything before fixing (전수조사후, 해결까지).
