# Remove Hancom-printout text from HWP parsing: HwpHwpxLoader recovery fallback, OCR from embedded HWP images, no Gemini OCR (PRs #34, #35 merged)

The user asked to remove the step that converts HWP to a Hancom PDF, arguing it adds noise when a library already parses HWP fully. The assistant disagreed in part. The printout has three roles: fidelity check, text recovery for two files that pyhwp fails on, and OCR image source. The user chose to drop only the recovery and OCR-source roles and keep `fidelity run`, and settled the follow-on choices, including replacing Gemini OCR with gpt-5-mini on the user's personal OpenAI key. The work was split into two PRs, recovery fallback then OCR rework with re-ingest and gated rollout. PR #34 and PR #35 were merged, with 1 P2 left on #35.

## Decisions

- Remove the Hancom printout's recovery role and its role as OCR image source; keep it only as the independent witness for `fidelity run` — Without the fidelity check nothing would show that the parser reads documents fully (rejected: Removing the HWP→Hancom PDF printout entirely)
- Use `HwpHwpxLoader` (from #30) as the production fallback parser when pyhwp fails (AFSIS Cambodia, MILE), with its output checked by `fidelity run` (rejected: Reading the printout's text layer as `hwp_print` in `_parse_source`)
- If recovery is flagged by the check, keep the document active as `auto_flagged`; if parsing fails outright, quarantine it
- Take OCR images from the HWP file itself; convert WMF/EMF to bitmaps; count the images that can't be read and report them as not OCR'd (rejected: Cutting image regions from printout pages)
- Do not use Gemini for OCR; flagged local OCR reads go to a second reader, gpt-5-mini (option 3), using the user's personal OpenAI key, with spending recorded in the shared ledger — To use only keys provided to the project, for reproducibility (사용자: 프로젝트에 제공된 key만으로 쓰기위함, 재현성); the personal key matches how drafting and the judges already work (rejected: Gemini as second reader; the team OpenAI key)
- Remove GeminiReader, its config and its docs; keep the existing ledger file as history. Gemini dense embeddings, which also read `GEMINI_API_KEY`, stay — Embeddings are a separate retrieval-side use
- Build the new index without activating it; activate only if retrieval evaluation doesn't get worse
- Split the work into two PRs: (1) the recovery fallback, (2) the OCR rework with full re-ingest and gated rollout, evaluated on a main that already contains the first — The first is small and stands alone; the second's evaluation needs the first on main

## Facts

- Corpus for 입찰메이트 (BidMate): 100 Korean RFPs, 96 HWP files and 4 PDFs (unverified)
- pyhwp fails on AFSIS Cambodia (malformed XML) and MILE (UTF-16 decoding error); their text came from the printout, marked unreviewed (unverified)
- `HwpHwpxLoader` (#30) returns body, tables and notes grouped separately rather than in document order, with no pages or coordinates; it extracted 176 elements from the AFSIS sample (unverified)
- The pyhwp walker sees the picture control (`GShapeObjectControl`) but keeps only caption and text-box text, not the picture's position; placing OCR text needs a picture marker in the document flow (unverified)
- OCR baseline: 463 distinct images; the local model is PaddleOCR-VL; the quality test flags 193 of them and caught all 16 wrong reads in a 50-image sample (unverified)
- The OCR cache is keyed by printout pixels, so reads of embedded images won't hit earlier cache entries (unverified)
- Gemini had spent $0.26 of its $0.50 cap (unverified)
- Answers use gpt-5-mini on the team OpenAI key through the shared budget gateway (unverified)
- With a personal key for OCR second reads, a teammate holding only the team key cannot re-read the flagged images; the cached reads and the ledger are the record (unverified)
- Checkout is blocked when `.wiki/graph.json` has a local change to its `"repo"` label: the wiki writes the folder or branch name there. `git restore .wiki/graph.json` before starting a task is safe; the durable fix belongs in the wiki-agent generator, outside this repository (unverified)

## Preferences

- Use only keys provided to the project, for reproducibility; no Gemini for OCR
- When a choice is dropped, the user wants new options offered again ("다시 선택지를 줘라")
